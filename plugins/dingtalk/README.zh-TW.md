# 釘釘機器人與工作臺

企業機器人通過釘釘 Stream 閘道器接收訊息，無需公開回調埠；使用 Node 內建 WebSocket、fetch、crypto，無兄弟外掛依賴。自定義群機器人 Webhook 單獨支援文字和 Markdown 通知。

## 配置

1. 在釘釘開放平臺建立企業內部應用，啟用機器人與 Stream 模式，取得 AppKey、AppSecret、robotCode。
2. 配置機器人相關訊息、下載、上傳及傳送許可權；在外掛面板填寫憑據和機器人編碼，啟用雙向會話。金鑰通過宿主 secrets 儲存。
3. 可配置 Staff ID 白名單、預設工作目錄、模型和思考強度。設定白名單後，缺少傳送者身份或不在名單的訊息均拒絕。
4. 自定義群通知填寫 Webhook URL 和可選簽名金鑰。自定義 Webhook 與企業機器人媒體介面的許可權不同。

## 命令

| 命令                                                          | 行為                                                  |
| ------------------------------------------------------------- | ----------------------------------------------------- |
| `/help`                                                       | 檢視命令和媒體限制                                    |
| `/new`、`/clear`、`/reset [prompt]`                           | 更換隔離賬號；可選 prompt 立即在新上下文執行          |
| `/status`                                                     | 當前真實會話、執行 ID、模型、思考強度、目錄和最近錯誤 |
| `/stop`、`/abort`                                             | 優先按穩定 runId 呼叫宿主 `abortRun`；失敗明確反饋    |
| `/model [provider/id\|default]`                               | 查詢或設定當前渠道會話的模型偏好                      |
| `/thinking [off\|minimal\|low\|medium\|high\|xhigh\|default]` | 查詢或設定思考強度                                    |
| `/cwd [絕對路徑\|default]`                                    | 查詢或設定工作目錄；目錄必須存在，切換後啟用新上下文  |

`/workspace` 是 `/cwd` 的相容別名。未知命令只回復幫助提示，不會投遞模型。命令名相容大小寫、全形字母與全形斜槓；`DEFAULT` 和思考強度相容大小寫。三個重置別名都接受可選 prompt，保留其字面內容，`/new /stop` 會把 `/stop` 作為模型輸入。模型、思考強度和目錄設定均輪換隔離賬號並開啟新上下文，舊在途操作失效；目錄驗證遲到不會覆蓋之後的重置。普通訊息在當前執行結束前會提示等待，不會覆蓋待回信的執行。`/stop` 不排在媒體下載或 chat 投遞之後：立即確認停止請求；媒體準備完成後不再投遞，若宿主回執尚未返回，則收到回執後按 runId 中止。下載本身仍可能繼續至完成或 30 秒超時。模型和目錄最終可用性由宿主在下一次投遞時驗證，外掛不會宣稱已經切換成功。

會話按機器人賬號、企業、群/單聊、渠道、執行緒和傳送者隔離，並持久化 scope 的隔離賬號與重置代次。新版宿主返回的穩定 `sessionId` 用於儲存回信路由；網頁主動續聊的無 runId `run_start` 可按該路由建立本輪迴信，最終回到原目的地。舊宿主僅支援精確 `clientId + conversationId` 的記憶體相容，不認領裸 `c1`。未知 runId 絕不借 sessionId 認領；回執前的事件只按回執精確 runId 重放。每輪結束僅回一次，採用最後一個助手正文候選，空正文或工具呼叫會清空前言候選，不拼接工具執行前言。無精確 runId 的網頁任務只能在網頁停止，外掛明確反饋，絕不猜測 conversationId 中止。

## 媒體接收

支援 `picture`/`image`、富文本圖片、`audio`/`voice`、`file`、`video` 回撥。通過訊息中的 `downloadCode`/`pictureDownloadCode` 呼叫企業機器人下載 API，下載實際內容：

- PNG/JPEG/GIF/WebP 圖片以 `host.chat({text, attachments:[{path:"", imageData, mimeType, name}]})` 輸入，絕不以下載 URL 代替圖片。
- 檔案、語音、影片以 `{path:"", fileData, mimeType, name}` 附件輸入，由宿主持久化。當前使用通用二進位制 MIME，保留回撥檔名。
- 入站每個媒體（圖片、檔案、語音、影片）最大 10MiB，每條最多 8 張圖片，媒體總計最大 20MiB，每條最多 16 個富文本片段。下載具備大小限制及超時。
- 語音、影片保留原檔案；本外掛不提供語音識別、影片抽幀或音影片解碼。接收時明確告知，實際理解依賴模型可用工具。圖片執行格式簽名檢查，不是完整畫素解碼；損壞但簽名正確的圖片仍可能由宿主/模型報錯。
- 不支援的位置、卡片等型別、缺少下載碼、認證失敗、無許可權、下載失敗和格式檢查失敗都會反饋。沒有 sessionWebhook 時拒絕投遞，並記錄狀態錯誤。

需要支援 `host.chat.attachments` 的新版宿主。圖片理解還依賴可用的視覺模型或宿主視覺橋。外掛不提供舊宿主的 URL 文本降級。

## 媒體傳送

AI 工具 `dingtalk` 支援 `action:"media"`；UI 訊息介面也接受 `type:"send_media", payload:{...}`。當前面板沒有獨立媒體上傳表單。指定本地 `path`、`mediaType` 和唯一接收目標 `openConversationId`（群）或 `userId`（員工單聊）：

| mediaType | 輸入與邊界                                           |
| --------- | ---------------------------------------------------- |
| `image`   | PNG/JPEG/GIF/WebP，本地檔案上傳後傳送原生圖片        |
| `audio`   | AMR 檔案及 `duration` 秒；其他格式需轉換或按檔案傳送 |
| `file`    | 本地檔案，保留檔名與副檔名                           |
| `video`   | MP4、`duration` 秒及 `coverPath` 圖片封面            |

每個上傳檔案不超過 20MiB；釘釘實際格式、大小、時長和許可權限制可能更嚴格，平臺錯誤會直接反饋。通過上傳 API 獲取 media_id，再呼叫企業機器人群訊息或單聊傳送 API；自定義/session Webhook 不支援任意二進位制媒體傳送。模型產生的附件不會自動轉發，需顯式呼叫媒體工具並指定收件目標。

所有 Webhook 與媒體請求校驗 HTTP 狀態及平臺錯誤碼；回信失敗記錄在 `/status` 的最近錯誤。Webhook 已失效或網路斷開時無法保證錯誤本身還能送達原會話。

`/new`、`/clear` 與 `/reset` 立即更換隔離賬號並保留模型、思考強度和目錄偏好；下載或宿主投遞尚未返回時也可重置。舊下載、延遲迴執和任務事件不會重新繫結新會話，已知舊任務會請求中止；中止失敗會明確提示。外掛不排隊入站訊息，新會話可以立即接收下一條訊息。

Stream 斷開後重連；stop/reload 保留持久 scope、偏好、代次和穩定 sessionId 路由，不重置上下文，也不恢復未完成任務。reset、模型/目錄設定與機器人賬號變更撤銷舊路由，過載不會復活舊代次。訊息去重和舊宿主 owner 路由僅儲存在記憶體。回信優先走原 sessionWebhook；失敗時僅當原回撥包含明確群/單聊型別和精確收件目標，才複用企業機器人傳送介面回原目的地；缺少目標、許可權或平臺拒絕均記錄真實錯誤，不改投配置群 Webhook。當前沒有真實釘釘憑據聯調證據，自動測試覆蓋閘道器訊息、HTTP 請求、附件、持久路由與宿主事件契約，仍需在企業環境驗證許可權、媒體模板和時長欄位。
