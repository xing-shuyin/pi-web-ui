# QQ 机器人与工作台 (QQBot Plugin)

> QQ 机器人插件，基于腾讯官方开放平台 QQBot WebSocket 出站长连接，支持双向会话对话（零公网 IP / 免反代）、结构感知 Markdown 智能分块、白名单安全准入与频道/群聊消息推送。基础文字与媒体收发使用 Node 内建能力；自动语音回复按需安装 SILK 编码组件。

## 功能特性

- 🤖 **QQBot 官方 WebSocket 出站长连接双工对话**：基于腾讯官方开放平台 QQBot Gateway 协议，客户端主动发起长连接，**零公网 IP、免域名备案、免反向代理、免开放入站端口**，在局域网或个人电脑即可即开即用！
- 📦 **结构感知 Markdown 分块**：针对 QQ 消息长度限制，采用类似 `dsh-im` 的智能分块算法，保证代码块（\`\`\`）自动闭合与语法高亮不破损。
- ⚡ **斜杠快捷指令**：支持 `/help`、`/clear` 或 `/new`（清空上下文开启全新对话）、`/status`（查看机器人在线指标）、`/abort`（同 `/stop`、`/8`，中止当前目的地的任务；失败会明确提示）。
- 🛡️ **安全白名单控制**：支持设置允许对话的 QQ OpenID / 用户 ID 白名单，未授权人员友好拦截，防止 Bot 被陌生人滥用。
- 💬 **被动消息引用与多端支持**：支持 QQ 频道子频道（@机器人）、QQ 群聊（@机器人）以及单聊好友消息，自动关联 `msg_id` 被动回复。
- 🛠️ **AI 工具**：向 AI 助手注册 `qq` 工具，AI 可自主向 QQ 频道推送消息与通知。
- 🖼️ **富媒体双向（图片/语音/视频/文件）**：
  - **收**：QQ 发来的附件（事件里的 `attachments`，腾讯 CDN、有实效）下载后落到工作区
    `.pi-qq-media/`。PNG/JPEG/GIF/WebP 图片以 `imageData` 附件进入模型（最多 8 张、单张 10MiB、合计 20MiB）；其他图片格式明确提示转换。文件、音频和视频作为路径引用附件传给宿主，不承诺模型能直接理解音视频。语音优先下载 `voice_wav_url`（按 WAV 命名），保留平台 ASR 文本，即使下载失败或关闭落地；没有平台 ASR 时明确说明插件不提供转写，请补充文字或使用转写工具。单件下载上限 25MiB，超限/下载失败降级为占位文字（绝不吞消息）；
    设置里可开关「接收图片/文件落地」。
  - **发**：`qq` 工具新增 `image` / `file`（本地路径或 http(s) URL）与 `user_openid` /
    `group_openid` 目标。链路 = `POST /v2/{users|groups}/{openid}/files`
    （本地文件 ≤ 5MB 走 base64 `file_data`，更大自动走 `upload_prepare` → 分片 PUT →
    `upload_part_finish` → 合并拿 `file_info`）→ `msg_type=7` + `media.file_info`。
    超过软限制（图片 20MB / 视频 30MB / 语音 20MB）由 QQ 侧降级为文件卡片。
  - **频道限制**：QQ 频道子频道只接受**公网 http(s) URL** 的 `image` 字段，本地文件没有
    上传通道 —— 要么先用单聊/群聊发，要么给公网链接（工作台会直接报错提示）。

群聊和频道按「用户 + 目的地 + thread（若事件提供）」隔离会话；单聊按用户隔离。`/new`、`/clear` 与 `/cwd` 切换递增该 peer 的会话 epoch，同时更换宿主 accountId，避免复用旧上下文。命令先于附件下载处理，`/stop` 不等待媒体下载。回执中的真实 conversationId 用于续聊，稳定 runId 用于接管后的事件归属；回执前事件只有匹配该 runId 才重放。同一会话执行中再次发消息会提示等待或中止。网页打开该 QQ 会话并主动续聊时，最终助手回复也会回传对应单聊、群或频道；回传绑定使用稳定 SDK `sessionId`，保留目的地与当前会话 epoch 校验。`/new` 等重置后旧会话不再回传，不按局部 `c1` 猜测联系人；多人绑定同一网页会话时存在歧义，不自动回传。`bindActive` 显式开启时会使用宿主当前会话，同一会话已有运行时拒绝覆盖。

网页发起且没有通道运行标记的任务，QQ `/stop` 会提示到网页端停止，不按局部会话编号中止。超出 QQ 被动回复窗口时尝试主动消息发送，实际受平台权限和额度限制；投递失败会显示在 QQ 面板状态中。

## 自动语音回复

QQ 工作台 →「机器人凭证与高级设置」→「自动回复语音」，选择「语音回复」或「语音和文字」，再选择引擎、音色和语速，保存即可。默认维持文字回复。

- `builtin` 使用服务器的系统语音，无需 TTS 插件。Windows 使用已安装的系统音色，macOS 使用 `say`，Linux 需有 `espeak-ng` / `espeak`。
- 安装并启用 TTS 插件后，可以选择 `doubao-tts`、`deepseek-tts` 及其音色；其他插件向统一 TTS 中心注册的引擎也会出现在列表中。凭据在提供该引擎的插件中配置。
- 单聊、群聊及已绑定网页会话的最终回答支持语音；频道、指令回执和进度提示使用文字。长回复朗读开头，同时保留完整文字；语音生成、转码或发送失败时自动回退到完整文字，原因可在高级设置查看。
- 首次合成 QQ 语音时按需安装 `silk-wasm`；AAC 等压缩音频按需安装 `ffmpeg-static`。系统 WAV 只需 SILK 编码组件。

引擎注册、系统音色、API 与取消规则见 [`docs/architecture-tts.md`](../../docs/architecture-tts.md)。

## 配置指南

1. 打开 [QQ 开放平台](https://q.qq.com/) 并注册/登录开发者账号；
2. 进入「机器人」管理后台，创建机器人应用；
3. 获取机器人的 **AppID** 与 **ClientSecret**；
4. 在机器人设置中配置好机器人名称、头像以及权限列表；
5. 在 pi-web-ui 的 QQ 面板点击「⚙️ 配置凭证」，填入 AppID 与 ClientSecret，勾选「启用 QQ 机器人双向会话对话服务」即可！
