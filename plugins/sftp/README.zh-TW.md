# sftp — 專案級 SFTP 同步

把本地工作區與遠端伺服器互傳：**配置存專案自己的 `.pi/`**，先算差異再傳，刪除先進垃圾桶，
憑據只寫引用不寫明文。面板裡可以手動上傳/下載單個檔案或整棵目錄；AI 側是**一個** action 式
`sftp` 工具，模型能自主配連線、看差異、上傳下載、改遠端檔案。

不出現在 UI 也不影響使用的方式：不裝外掛 = 不存在。裝上後介面上**只多一個入口** ——
頂欄的「SFTP 同步」檢視 tab（不佔底欄），檔案右鍵選單多兩條「上傳到遠端 / 上傳此目錄」
（點了會把面板切出來，就地顯示進度）。同步狀態：進行中拼在按鈕文案裡（掃描階段是
`SFTP 掃描 1234`，傳輸階段是 `SFTP 3/10`），懸停看詳細提示，完成/失敗/被停止另發通知。

## SSH 主機信任

首次連線時，面板會顯示主機、埠、金鑰型別、SHA256 指紋和 `known_hosts` 儲存位置。
請通過伺服器控制台或管理員獨立核對指紋，勾選確認後點擊「信任並重新連線」。外掛將記錄儲存到
**執行 pi-web-ui 服務的電腦**（預設 `~/.ssh/known_hosts`，可用 `PI_WEB_SSH_KNOWN_HOSTS` 指定），
然後重新讀取遠端目錄；上傳、刪除等先前失敗的操作需要重新發起。

金鑰變更時，面板會明確警告，並要求再次確認已核實伺服器重灌或金鑰輪換後才替換舊記錄。
已撤銷的金鑰不能通過面板重新信任；萬用字元或證書機構規則也不能在面板內替換，需要管理員維護。
確認請求有效期為五分鐘，繫結發起連線的工作區；過期後重新連線即可。
儲存失敗會顯示錯誤，不會關閉主機校驗或自動接受新金鑰。AI 工具不能確認主機信任，請在外掛面板完成。

認證方式以當前選擇為準：密碼/機密登入不會讀取殘留的私鑰路徑，金鑰或 agent 登入不會被全域性密碼覆蓋。
更換憑據或切換連線時會重新建立連線；同一主機指紋等待確認期間，日誌在一分鐘內只提示一次。

## 配置：`.pi/sftp.json` + `.pi/sftp.local.json`

```
<專案>/.pi/
├── sftp.json         連線與同步策略 —— 可提交、可分享（憑據只放引用）
├── sftp.local.json   本機覆蓋（埠 / 私鑰路徑 / 明文口令…）—— 外掛會自動加進 .gitignore
└── sftp-trash/       本地垃圾桶（刪除保護，按批次分目錄）
```

兩層**深合併**（local 覆蓋 base，陣列整體替換）：團隊共用一份 base，每臺機器只寫自己的差異。
讀取永遠合併，**寫入分檔案** —— 工具改哪個欄位就落哪個檔案，不會把本機覆蓋內容反向灌進 base。

```jsonc
// .pi/sftp.json
{
	"version": 1,
	"active": "prod",
	"defaults": {
		"ignore": ["dist", "*.map"], // 追加在外掛預設排除之後
		"delete": "none", // none | remote-only | both
		"concurrency": 4, // 1..16，傳輸併發
	},
	"connections": {
		"dev": {
			"host": "10.0.0.5",
			"port": 22,
			"username": "deploy",
			"remotePath": "/srv/app", // 必須絕對路徑
			"auth": {
				"method": "key", // password | key | agent（預設按內容自動判定）
				"privateKeyPath": "~/.ssh/id_ed25519",
				"passphrase": "${secret:dev-key-pass}",
			},
		},
		"prod": {
			"host": "203.0.113.10",
			"username": "root",
			"remotePath": "/project/app",
			"auth": { "method": "password", "password": "${secret:prod-password}" },
			// 只同步對映的子樹（各自獨立的樹，互不重疊）；不配 mappings 就是「工作區根 ↔ remotePath」
			"mappings": [{ "local": "web/dist", "remote": "/var/www/app" }],
			"sync": { "direction": "up", "delete": "remote-only", "compare": "mtime+size", "conflict": "newer" },
		},
	},
}
```

**內建預設排除**（不可被負向規則放回）：`.git`、`node_modules`、`.pi`、`.sftp-trash`、`*.log`、`*.tmp`，
外加內部護欄 `.sftp-trash/`（垃圾桶）與 `.sftp-tmp-*`（傳輸半成品）——它們永遠不會被同步回雙方，
否則「刪掉 → 進垃圾桶 → 下次又傳回去」會自我迴圈。

### 憑據引用（明文永不進配置）

| 寫法             | 取值來源                                                                                   |
| ---------------- | ------------------------------------------------------------------------------------------ |
| `${secret:名}`   | 宿主加密機密（AES-256-GCM 存 `<dataDir>`，跨機器拷走解不開）。`sftp_secret` 工具寫的就是它 |
| `${env:VAR}`     | 程序環境變數（CI 裡注入）                                                                  |
| `${file:~/path}` | 從檔案讀（首尾空行會去掉，方便 `echo xxx > pass`）                                         |
| 其它字串         | **明文**。可用，但 `plaintextWarn` 開啟時會在介面與工具回執裡告警                          |

寫成 `${env}` 這種殘缺引用會**直接報錯**，不靜默回落成空密碼 —— 否則拼錯一個變數名會退化成
「認證失敗」這種難以排查的現象。

### 遷移

首次啟用時若發現 `.vscode/sftp.json` 且專案還沒配過，面板會出現「匯入 .vscode/sftp.json」按鈕
（等價於 AI 調 `sftp_save` 前先 `sftp_secret`）。匯入時明文口令會被搬進加密機密，
配置檔案裡只留 `${secret:…}` 引用。

## 同步語義

**兩段式：計劃 → 執行。** `sftp_plan`（面板「預覽差異」）只掃描、只回報，
清單分六類：`add` / `update` / `same` / `local-only` / `remote-only` / `conflict`。
`sftp_sync` 預設 `dryRun`，**一個位元組都不動**；確認後才 `dryRun: false`。

| 方向   | 含義                                                                                                                                                                                    |
| ------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `up`   | 本地 → 遠端（部署程式碼）。遠端多出來的檔案是否清理由刪除策略決定                                                                                                                       |
| `down` | 遠端 → 本地（拉回伺服器上的東西）。本地多出來的檔案是否清理由刪除策略決定                                                                                                               |
| `both` | 雙向。只有一邊有的檔案視為「新增」補到另一邊（**不刪**，避免把「剛刪掉」誤判成「對側新增」）；兩側都有但不同 → 按 `sync.conflict`（`newer` 預設比 mtime / `local` / `remote` / `skip`） |

| 刪除策略       | 允許的動作                                           |
| -------------- | ---------------------------------------------------- |
| `none`（預設） | 從不刪除，多出來的檔案只在計劃裡標註「不清理」及原因 |
| `remote-only`  | 允許清理遠端多餘檔案（`up` 場景）                    |
| `both`         | 雙向都可清理                                         |

**刪除永不真刪**：遠端挪進 `<remotePath>/.sftp-trash/<批次>/`，本地挪進 `.pi/sftp-trash/<批次>/`，
按 `trashDays` 自動清理過期批次。`sftp_rm` 工具同樣走垃圾桶。

其他保障：

- **可取消**：面板上的「停止」（工具側是 `action=cancel`）在**掃描階段與傳輸階段都能停** ——
  服務端一個 `AbortController` 管全程，停止請求進來後不再領新檔案、在傳的流被掐斷、半成品被清掉；
  已傳完的檔案保留，垃圾桶批次可回滾。取消**不算失敗**（不寫進 `failed`），停完 `job` 立刻釋放，
  可以馬上重來（老版本只有 `running` 標誌、沒有取消通道，按下去沒反應，只能重啟服務）；
- **掃描按層並行**：本地同層目錄一起 `readdir`、同層檔案一起 `stat`；遠端同層目錄一起 `readdir`
  （一次 readdir 一個往返，序列的 500 個目錄在高延遲鏈路上要幾百秒）。併發數由設定頁的
  `scanConcurrency`（預設 8，1..32）控制；掃描期間介面顯示「已掃 N 個檔案 / M 個目錄」，不再只有一個「掃描中…」；
- **遠端快掃（需要「允許在遠端執行命令」）**：開啟 exec 後，遠端掃描先用**一次 `find`**
  （`-printf '%y\t%s\t%T@\t%P\0'`，純目錄名的 ignore 規則翻譯成 `-prune`，順便剪掉整棵 `node_modules`）
  把整棵樹取回來 —— 399 個目錄的樹在 10ms RTT 上：逐目錄 readdir 1.6 秒 → 一次 find 12 毫秒。
  服務端沒有 `find`、不認 `-printf`、輸出被截斷或欄位對不上時**整批放棄**、回落逐目錄掃描（慢但一定對），
  原因會寫進外掛日誌；
- **小檔案批次打包傳輸（需要「允許在遠端執行命令」）**：一批 ≥5 個小檔案打成一個 tar 傳完，
  每個檔案 5~8 個往返還成每批幾個。**兩頭都是流**：上行邊讀邊發（AsyncGenerator → SSH 通道，
  帶背壓），下行 `tar -czf -` 邊到邊解邊落盤 —— 中間不會出現「整包 Buffer」。
  實測 20MB 小檔案集：流式 RSS +4MB，老做法（先攢整包）RSS +40MB。
  - **上行**：本地 `tarStream()` 邊讀邊產 ustar（自己寫頭，不依賴本機 tar）→ 背壓喂進 exec 的 stdin
    → 遠端解到同步根內的 `.sftp-tmp-stage-*` 暫存目錄 → 再一次 `find` 校驗整批大小 → 逐個 `mv` 落位；
  - **下行**：遠端一次 `tar -czf - <這幾列檔案>` → `createGunzip()` + 流式 ustar 解析器
    → 本地只解出**這批要的那幾個 rel**（其餘成員讀掉就丟，絕不落盤）→ 逐個 `rename` 落位；
    本地暫存區也在 `.pi/` 下（同盤才原子）；
  - 兩個方向都：大小逐個校過、暫存區用完即刪（內部護欄保證不會被下次同步傳回去）、
    任何一步出問題（沒有 tar、gzip/tar 解不開、checksum 對不上、大小不符、mv/rename 失敗）就
    **整批放棄、回落逐檔案**，原因進外掛日誌（`batchTransfer` 可單獨關掉）；
- **計劃複用**：`/plan` 回一個 `planToken`，引數沒變時執行可以直接帶回來沿用那份計劃，
  省掉第二次全量掃描（大樹上這是「預覽→執行」裡最久的一段）；5 分鐘過期、引數/連線一變即失效、
  執行完立刻作廢 —— 寧可重掃，不可傳錯；
- **併發流式**：預設 4 路併發，`createReadStream`/`createWriteStream` 分塊傳輸，不吃記憶體（舊做法整檔案讀進記憶體，大檔案直接 OOM）；
- **原子落盤**：先寫 `.sftp-tmp-*` 再 `rename` 落位（遠端目標已存在時先刪再 rename，相容 Windows OpenSSH 不覆蓋的 `mv`）；中斷只留可識別、可清理的半成品；
- **大小校驗**：傳完比對位元組數，靜默截斷變成顯式失敗；
- **mtime 容差 2 秒**：FAT/NTFS/sshd 的秒級精度抖動不會導致全量重傳；遠端不返回 mtime 時退化為「大小相同即視為一致」並在計劃裡告警；
- **越界防護**：本地寫入路徑必過 `safeRel` 且必須落在同步根內；遠端 `readdir` 返回的含分隔符 / `..` 的名字一律拒收（否則一個惡意服務端就能寫穿工作區）；符號連結一律跳過；`remotePath` 為 `/` 且開了刪除時強制降級為 `delete: none`（要真刪得顯式 `allowRootRemote: true`）。

## AI 工具：一個 action 式 `sftp`

**只有一個工具**（不是十幾個）：這些動作共用同一份配置、同一條連線、同一套守衛，拆開只會把上下文塞滿，
模型還容易漏看某幾個。代價是描述要寫全 —— 用一張動作表把「哪個 action 要哪些引數」說清。

| action                                                     | 作用                                                          | 關鍵引數                                                                                                    |
| ---------------------------------------------------------- | ------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------- |
| `status`                                                   | 讀配置狀態（profile 清單、憑據有無、依賴狀態）—— **不回明文** | —                                                                                                           |
| `save`                                                     | 新建/更新連線（缺席欄位沿用舊值，`null` 清除憑據）            | `name` `host` `port` `username` `remotePath` `ignore` `direction` `deletePolicy` `target` `activate` + 憑據 |
| `secret`                                                   | 把密碼/口令寫進加密儲存，返回 `${secret:名}` 引用             | `name` `value`                                                                                              |
| `test`                                                     | 連線 + 遠端根可達 + 寫許可權探測                              | `profile`                                                                                                   |
| `plan`                                                     | 差異計劃（不傳檔案）                                          | `profile` `direction` `scope` `path` `deletePolicy`                                                         |
| `sync`                                                     | 執行同步（`dryRun` 預設 true，必須顯式 `false` 才動檔案）     | 同上 + `dryRun`                                                                                             |
| `cancel`                                                   | 停掉正在跑的同步（含掃描階段）；沒任務時冪等返回              | —                                                                                                           |
| `ls` / `read` / `write` / `mkdir` / `mv` / `rm` / `search` | 遠端檔案 CRUD 與搜尋（刪除走垃圾桶）                          | `path`（遠端絕對路徑）/ `from` `to` / `text` / `query` `maxResults` `maxDepth`                              |
| `exec`                                                     | 遠端跑 shell 命令                                             | `cmd` `timeoutMs`                                                                                           |

`path` 的含義隨動作變：`plan`/`sync` 下是**本地相對路徑**，檔案動作下是**遠端絕對路徑**。

**`exec` 預設不在 enum 裡** —— 在「設定 → 外掛 → SFTP 同步 → 允許在遠端執行命令」開啟後，外掛會登出並
重新註冊工具，`exec` 才出現在動作表裡（模型看不見的能力才是真關掉）。同一個開關還開啟上面那兩條
快通道（一次 `find` 掃描 + tar 批次打包），另有「小檔案批次打包傳輸」開關可以單獨關掉批次傳輸。
設定頁還能調：預設刪除策略、傳輸併發數、掃描併發數、是否自動維護 `.gitignore`、是否告警明文憑據、
垃圾桶保留天數。專案檔案的 `defaults` 優先於設定頁（專案約定不該被機器級開關改掉），檔案裡沒寫才回落設定頁。

## 手動上傳 / 下載（面板）

不想先看計劃、就想把手上這一個東西傳過去時，面板裡有直通路徑：

- **遠端檔案樹**每行尾巴的 `⬇`：下載這一項（目錄則整棵子樹）；
- **遠端檔案樹工具欄**的「上傳本地對應目錄」：把當前遠端目錄對應的本地目錄推上去（服務端反查
  mappings / 遠端根，所以路徑給的是遠端絕對路徑）；
- **本地檔案樹右鍵選單**：「上傳到遠端」/「上傳此目錄」（由 manifest 的 `contextmenu.file` 提供）。

它們走 `POST /transfer`，與 `POST /sync` 的區別只有兩條：**不等計劃、直接執行**；以及
**固定 `deletePolicy: none`** —— 手動推一個目錄不該把遠端多出來的檔案清掉。手動傳輸同樣進 `job`
進度與通知，傳完會重新整理差異面板。

路徑越界與非法配置拒絕、`.vscode/sftp.json` 遷移（明文不入庫）、單個 action 式工具的註冊與
`exec` 動作的開關、手動 `POST /transfer`（單檔案上下傳 / 遠端目錄反查本地目錄 / 永不動刪除策略）、
`scope=tree` 的遠端路徑、down 覆蓋與 both 互補、mappings 子樹對映、
計劃 token 複用（`reuse` 命中就不重掃，token 不對就重掃）、**掃描中途 `POST /cancel`**
（這條會臨時給 mock 的 READDIR 加 40ms 延遲造出真即時間窗：斷言掃描期間 `/state` 有進度、
停止後返回 `cancelled`、執行位釋放且外掛還能接著出計劃），以及**兩條 exec 快通道**
（13 個小檔案上行一次 tar 批次、下行 `tar -czf -` 一次拉回，內容與巢狀相對路徑都對、暫存目錄清乾淨；
再把遠端 tar 開關關掉跑一遍：`batched` 誠實歸零、回落逐檔案依舊一個不少；
同一條命令鏈的 `find` 快掃與逐目錄 readdir 得出的計劃必須一模一樣）。

引擎層另有純單測：
`tests/unit/sftp-engine-cancel.test.ts`（`runPool` 中止後不再領任務、`scanLocal` 層序掃描與中止即拋、
`applyPlan` 取消不算失敗）與 `tests/unit/sftp-fastscan-batch.test.ts`（自寫 ustar 頭 + 獨立讀取器驗 checksum 和解包；
上行用 `tarStream` 邊產邊收（斷言最大 chunk 遠小於整包）、下行把 tar 按 **100 位元組碎塊**餵給
`readTarStream`（逼它跨塊拼頭與正文）；`parseTarBuffer` 時代的老用例全部改為流式口徑：
checksum 改一個位元組、正文截斷、不要的成員丟而後續仍然對齊、超過 `maxBytes` 直接報錯；
外加 `parseFindOutput` 的 NUL/換行兩種口徑、`scanRemoteViaFind` 的 `-prune` 命令形狀與回落條件、
`pruneDirNames` 只收純目錄名）。
遠端由 `tests/lib/mock-ssh.mjs` 的記憶體 SFTP 服務提供（使用者 `tester` / 密碼 `secret123`，根 `/home/test`，
可選 `latencyMs` 給每個 readdir 加延遲；exec 側認得外掛會發的 `find -printf`、`tar -x -f -`、
`mkdir -p`、`mv -f`、`rm -rf`）。
