# AI 響應速度監控外掛 (Response Speed)

即時監控並在底部狀態列展示 AI 的最新響應速度與平均響應速度，支援 AI 自迴圈的每一次迴圈獨立測速。

## 什麼是響應速度？

**響應速度**（首字響應時間 / Time to First Token，簡稱 **TTFT**）：
指的是**把訊息請求發給 AI，到收到 AI 返回的首個回覆響應資料包的時間**。

它反映了模型網路延遲、推理冷啟動排隊、服務端處理與首 Token 生成的綜合時延。

## 主要特性

- 📊 **底部狀態列雙指標展示（最新 / 平均）**：
  - 在底欄（`bottombar`）以現代化極簡徽章直觀呈現當前對話最新一次請求與歷史平均響應速度（精簡純數值如 `12.7/14.3`，滑鼠懸浮展示詳細說明與毫秒耗時）；
  - 純淨穩定：不顯示“響應中…”，始終直接顯示該對話上一次的耗時，不破壞閱讀沉浸感；
  - 純淨設計：不注入右上角懸浮窗，不 hack 底層 WebSocket，完全由服務端權威執行軌跡驅動。
- 💬 **每個對話獨立記錄與隔離**：
  - 各會話獨立記錄與統計 TTFT 響應資料，互不干擾；
  - 切換對話時底欄即時無縫聯動更新為對應對話的最新與均速，新建對話即從空態開始獨立測速。
- 🔄 **支援 AI 自迴圈每次獨立測速**：
  - 當 AI 呼叫工具並在工具執行完後進入自迴圈（多回合 turn）時，每一輪向大模型發起的新請求都會**獨立計算耗時**；
  - 準確捕捉每一個回合的首包響應時延。
- 📈 **多維統計與看板**：
  - 點選底欄徽標，彈出當前對話的響應速度統計看板（Dashboard）；
  - 檢視平均響應速度 (Average Latency)
  - 檢視當前/最新回答速度 (Latest Latency)
  - 檢視最快與最慢響應時間 (Min / Max Latency)
  - 歷史測速樣本明細表格與一鍵清空當前對話記錄。

## 安裝與配置

外掛位於官方外掛體系 `plugins/response-speed`，開箱即用。
在設定 -> 介面外掛 中啟用即可生效。
