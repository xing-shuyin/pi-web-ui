# page-picker · 網頁元素拾取（瀏覽器擴充套件）

在**開發中的網頁**上點選元素，把它整理成 AI 能直接動手的上下文，一鍵注入 pi-web-ui 的對話輸入框。

另有**頁面橋**（兩個**配對過**的頁面互相讀寫）與 **AI 操作頁面**（讓對話裡的模型讀寫你授權的頁面）—— 見下文。

```
在開發網頁上按 Alt+Shift+P（或點擴充套件圖示）
   → hover 高亮、點選拾取（Shift+點選多選）
   → 底部浮條寫備註
   → 「新增到對話」
   → pi-web-ui 輸入框出現已排版好的上下文，你補一句「這三處間距不一致」再發送
```

採集的不是一張截圖，而是**能讓 AI 一次改對的東西**：

| 採什麼                                               | 為什麼關鍵                                                                                                       |
| ---------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------- |
| **React 元件原始碼位置**（`Card.tsx:18:5` + 呼叫鏈） | 從 fiber 的 `_debugSource` 挖出來。這是「AI 一次改對」與「AI 滿倉庫 grep」的分界線                               |
| **Vue SFC 檔案**                                     | 從元件例項的 `__file` 拿（只有檔案，沒有行號 —— 不硬編假行號）                                                   |
| **命中的 CSS：檔案 + 原始檔行號**                    | Vite dev 的 `<style data-vite-dev-id>` 的 textContent 與原始檔逐字對應，行號可精確反推                           |
| **計算樣式子集**                                     | **只報與預設值/繼承值不同的項**（現場造同 tag 空元素當探針比對）。一個真實卡片通常只剩 3~5 行，而不是 300 個屬性 |
| 選擇器 / XPath / DOM 路徑                            | 首選短且唯一的（`#card` > `section#card` > 兜底全 `:nth-of-type`）                                               |
| HTML 骨架 + 摺疊文本                                 | 結構而不是整棵 `outerHTML`（超深子節點折成 `…`）                                                                 |
| 元素截圖（可選）                                     | 走對話附件，不是塞 base64 進正文                                                                                 |

**發什麼由你勾**：頁面上下文 / 定位資訊 / XPath 與 DOM 路徑 / 原始碼位置 / 文本 /
命中的 CSS / 計算樣式 / HTML 骨架，逐項開關 —— 沒勾的**根本不採集**（不只是不渲染），
所以「這次只要原始碼」「這次只要樣式」都是最省的那一種。嫌麻煩就用預設：
精簡 / **標準（預設）** / 完整 / 只要能改對地方（選擇器+原始碼）/ 只排查樣式 / 只看文案結構。

**預設與逐項勾選在拾取浮條上就能改**（點完元素後那條裡的一排 chip，`Alt+1~6` 是同一個入口），
不用再去擴充套件選項頁 —— 「這次只要原始碼位置」這種判斷本來就是站在頁面上看著元素時才有的。
改完會**立即按新檔位重新採集已選元素**，所以浮條上寫的就是這次會發出去的；選擇會寫回擴充套件設定
（選項頁同步、下次拾取沿用）。預設同時決定採集深淺（文本長度、骨架深度），逐項勾選不改深淺。

## 裝

擴充套件**不在 Chrome 應用商店**（上架要走開發者賬號 + 稽核，且這個擴充套件的服務地址得你自己填，
商店版沒什麼額外好處）。三條路，按你是誰選：

### ① 直接下載裝（推薦，不需要 Node）

**下載**：[`page-picker-extension.zip`](https://github.com/xing-shuyin/pi-web-ui/releases/latest/download/page-picker-extension.zip)
（永遠指向最新版；想釘版本就去 [Releases](https://github.com/xing-shuyin/pi-web-ui/releases) 頁
下帶版本號的那個）

1. 解壓 zip（得到含 `manifest.json` 的目錄）
2. Chrome / Edge 開啟 `chrome://extensions`（Edge 是 `edge://extensions`）
3. 右上角開啟「**開發者模式**」
4. 點「**載入已解壓的擴充套件程式**」，選第 1 步解壓出來的目錄
5. 定服務地址（二選一）：
   - **最省事**：先開啟你的 pi-web-ui 頁面，在**那個頁面上**點擴充套件圖示 —— 擴充套件會認出它是
     pi-web-ui，在頁面底部彈出「這個頁面是 pi-web-ui，要把它設為拾取服務地址嗎？」；
     點「設為服務地址」就完事（地址/埠/子路徑都按當前頁面算，不用手打）
   - 手動：點擴充套件的「**擴充套件程式選項**」：填 pi-web-ui 地址（預設 `http://127.0.0.1:8787`）；
     遠端/區域網地址要先點「**授權該地址**」，再點「**測試連線**」

> 裝完在 `chrome://extensions` 裡它會有個「開發者模式擴充套件」的提示，這是所有未上架擴充套件的
> 常態（Chrome 更新後偶爾會彈一次「停用開發者模式擴充套件」，點保留即可）。

### ② 從原始碼裝（改程式碼的人）

```bash
npm run build:extension        # esbuild 打包到 plugins/page-picker/extension/dist/
```

然後按上面 ① 的第 3~4 步裝，只是目錄選倉庫裡的 `plugins/page-picker/extension/`。
改完原始碼重新 `npm run build:extension`，在 `chrome://extensions` 裡點這個擴充套件的「重新整理」圖示即可。

### ③ 打包成 zip 分發（自己出包）

```bash
npm run pack:extension         # → release/page-picker-extension-<版本>.zip（含 CRC 自校驗）
```

CI 在打 tag 時自動跑同一條命令並把 zip 掛到 GitHub Release（見 `.github/workflows/extension-release.yml`），
所以 ① 的連結永遠是最新的。

### 許可權觀感

只預置了 `localhost` / `127.0.0.1` 的 host 許可權 + `activeTab`（**點圖示那一次**才臨時授權
當前標籤頁），不做常駐全站注入。換成區域網 IP / 域名 / https 地址時，需要那一個 origin 的
授權 —— 在**那個地址的 pi-web-ui 頁面上點一下圖示**就會引導你完成（見「服務地址怎麼定」）。

### 前置：pi-web-ui 版本要夠新

擴充套件靠 pi-web-ui 頁面上的宿主動作橋 `window.__piWebUiHost.compose()` 注入內容
（宿主 API **v2**）。舊版 pi-web-ui 沒有這個方法時，擴充套件會明確提示「版本過舊」並改成
複製 Markdown 兜底，不會靜默失敗。（**繫結浮條不受版本限制**：沒有橋時會退一步探同源的
`/api/health`，一樣能認出頁面。）

## 遠端 / 區域網部署（pi-web-ui 不在本機）

**能用，而且不需要在伺服器上裝任何東西** —— 擴充套件是純瀏覽器側的東西，投遞走的是
「瀏覽器裡開啟的那個 pi-web-ui 頁面」，不是服務端 API。所以典型的遠端場景是這樣：

```
[你的瀏覽器]
  ├─ 標籤頁 A：https://pi.example.com/         ← pi-web-ui（遠在伺服器上）
  └─ 標籤頁 B：http://localhost:5173/settings  ← 你正在開發/除錯的站點
        ↑ 在這裡按 Alt+Shift+P 拾取 → 內容注入到標籤頁 A 的輸入框
```

遠端/區域網下唯一要做的事就是**把服務地址定對（並授權那一個 origin）** ——
見下一節，其中 ① 就是為這種場景做的。

## 服務地址怎麼定（本地 / 區域網 / 遠端不限）

地址和埠都不固定（本機可能是 `localhost:8787`，也可能是 `127.0.0.1:9000`；遠端是
`http://203.0.113.10:8787` 或反代域名），所以擴充套件不猜地址 —— **兩條路都行**：

### ① 在 pi-web-ui 頁面上點一下圖示（推薦）

擴充套件先探測當前頁：

- **是 pi-web-ui**（看頁面上有沒有宿主動作橋，老版本則探一次同源的 `/api/health`）→ 底部彈出
  浮條問「要不要把它設為拾取服務地址」→ 點「**設為服務地址**」。地址、埠、子路徑全部
  按當前頁面算，不用手打；已經是這個地址時只告訴你「已繫結」，不再多問；
  浮條上還有「**在本頁拾取元素**」（開發 pi-web-ui 自己時會用到）。
- **不是 pi-web-ui** → 照舊進入拾取模式（底部同時出現一條**常駐細條**：狀態 +
  「**讓 AI 操作本頁…**」+「與另一頁配對…」+「退出」，見下文「AI 操作頁面」）。

如果那個遠端地址**還沒授權**，浮條會提示並給一個「開啟設定頁授權」按鈕 —— 因為
`chrome.permissions.request` 必須在擴充套件自己的頁面裡發出（瀏覽器要求使用者手勢，網頁上的
按鈕不算），這不是多餘一步，是許可權模型的要求。

### ② 選項頁手填（等價，出問題時按這個排查）

1. 擴充套件選項頁把地址改成 `https://pi.example.com`（或區域網 `http://192.168.1.10:8787`、
   反代子路徑 `https://host/pi`）
2. 點「授權該地址」（這一步是必須的：manifest 只預置了 `localhost` / `127.0.0.1`，
   其餘地址要顯式授權；沒授權時連「找到那個標籤頁」都做不到）
3. 點「測試連線」——它會同時告訴你**服務端在不在**和**瀏覽器裡有沒有開啟這個頁面**

> 本機部署不管換成 `localhost` 還是別的埠都**不用授權**（預置的 `http://localhost/*`、
> `http://127.0.0.1/*` 埠是通配的），只是要保證選項頁裡的地址和你位址列裡那個一字不差
> —— 匹配是嚴格的（寧可報「沒找到頁面」，也不往字首相似的除錯站點亂注入）。

遠端場景下的注意點：

| 情況                                           | 行為                                                                                        |
| ---------------------------------------------- | ------------------------------------------------------------------------------------------- |
| pi-web-ui 頁面**關著**（伺服器在跑但沒開頁面） | 投遞失敗 → 複製 Markdown 兜底。**這是設計使然**：注入目標就是那個頁面                       |
| 沒授權該地址                                   | 明確提示「還沒授權 `https://pi.example.com/*`，去選項頁點授權」，並複製兜底                 |
| 開著多個標籤頁（含你正在除錯的站點）           | 按 URL 複核，只投給 pi-web-ui 那個頁面；**絕不往除錯站點/字首相似的站注入**                 |
| 子路徑反代（`https://host/pi/`）               | 支援（授權按 origin，頁面匹配按你填的路徑字首）                                             |
| 開了 `PI_WEB_TOKEN`                            | 與擴充套件無關：鑑權由頁面自己帶（cookie/URL），擴充套件只是往已登入的頁面裡寫草稿          |
| HTTPS + 自簽證書                               | 需要瀏覽器先信任該證書，否則頁面打不開就無從注入                                            |
| 服務端與瀏覽器不在同一臺機器                   | 完全沒問題，擴充套件不直接訪問服務端（只有選項頁的「測試連線」會 fetch 一下 `/api/health`） |

## 互動

| 操作                                             | 效果                                                                                                                                     |
| ------------------------------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------- |
| 點擴充套件圖示 / `Alt+Shift+P`                   | **當前頁是 pi-web-ui** → 問要不要把它綁成服務地址；否則進入拾取模式（底部同時出現一條常駐細條：“讓 AI 操作本頁…”就在上面，不用先點元素） |
| （底部細條）讓 AI 操作本頁 / 與另一頁配對 / 退出 | 開啟擴充套件設定頁的授權面板（已預填本頁）/ 開啟配對面板（已預填本端）/ 關掉拾取                                                         |
| （繫結浮條）設為服務地址 / 在本頁拾取 / 關閉     | 寫入設定 / 像普通頁面一樣拾取 / 關掉浮條（`Esc` 同）                                                                                     |
| hover                                            | 高亮 + 尺寸/標籤浮簽                                                                                                                     |
| 點選                                             | 拾取該元素並進入確認條（普通流程）                                                                                                       |
| `Shift`+點選                                     | 追加多選，停留在拾取模式                                                                                                                 |
| `Enter`                                          | 從拾取模式進入確認條                                                                                                                     |
| `Backspace`                                      | 撤銷最後一個                                                                                                                             |
| `Alt+1~6`                                        | 一鍵切預設（精簡/標準/完整/改對地方/樣式/文案）—— 拾取與確認條都能用                                                                     |
| `Ctrl/⌘+Enter`                                   | 直接傳送（鍵盤能把整套流程走完）                                                                                                         |
| `Esc`                                            | 確認條 → 回拾取模式；拾取模式 → 退出（丟棄）                                                                                             |

確認條裡每個元素一行：選擇器 + 「這個元素的問題」備註框 + ✕ 移除。元素列表上面是一排**預設 chip**
（精簡 / 標準 / 完整 / 改對地方 / 樣式 / 文案）+ 右邊「調整項 ▾」（展開 8 項逐項勾選，與選項頁等價，
預設收起）；預設行下面有一條摘要寫著「當前傳送什麼 + 採集深淺」；再往下還有一條整體說明。

## 失敗時的兜底

**絕不會出現「點了新增、什麼都沒發生」**：

| 情況                                             | 行為                                                                                                                                                           |
| ------------------------------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 沒開啟 pi-web-ui 頁面                            | 提示 + **Markdown 複製到剪貼簿**，手動粘進輸入框                                                                                                               |
| 在 pi-web-ui 頁面上點了圖示（不小心）            | 不是報錯：改成問「要不要把它綁成服務地址」，也提供「在本頁拾取元素」                                                                                           |
| background 認頁面失敗（CSP / 許可權 / 奇怪環境） | 浮條會**自己再認一次**（同源 `/api/health` + DOM 兵形）：是 pi-web-ui 就正常問繫結，不是就自己退場並讓 worker 補註入拾取器 —— 不會出現「點了圖示什麼都沒發生」 |
| 點了「設為服務地址」但缺授權                     | 浮條提示差哪次授權，並給「開啟設定頁授權」（那種頁面上的點選給不了瀏覽器要的手勢）                                                                             |
| pi-web-ui 版本過舊（無 compose）                 | 明確提示升級後重新整理頁面，同樣複製兜底                                                                                                                       |
| 輸入框還沒就緒                                   | 提示重新整理頁面後再試，同樣複製兜底                                                                                                                           |
| 截圖失敗（無 activeTab 等）                      | 只是沒有截圖，Markdown 照常投遞                                                                                                                                |
| 頁面注入不了（`chrome://`、商店頁）              | 擴充套件角標 `!` + 懸浮提示寫明原因                                                                                                                            |

## AI 操作頁面（給模型一個能讀寫網頁的工具）

這是這個擴充套件的第二件正事：**讓對話裡的模型直接操作你在瀏覽器裡開啟的頁面** ——
讀它的內容、點按鈕、填表單、滾動、跳轉，必要時在它裡跑一段指令碼。

```
你說：“把後臺訂單頁前 10 條的金額讀出來，按金額排序”
   → 模型調 browser_page（op: read / click / …）
   → 服務端把它推給瀏覽器裡那個 pi-web-ui 頁面
   → 擴充套件在**你授權過的目標頁面**上執行，結果原路回到模型
```

**另一端固定是 pi-web-ui 頁面**（模型的動作要從它那裡送進擴充套件），所以不像頁面橋那樣要配兩端 ——
只需授權**被操作的那個頁面**。代價：**那個 pi-web-ui 標籤頁得開著**（與拾取投遞同一個取捨）。

### 怎麼開通

**入口在 pi-web-ui 頂欄的「瀏覽器操作」按鈕上**（它同時是狀態面板）：

- 開啟它就能看到「擴充套件在不在 / 授權了幾個頁面 / 兩個總開關的狀態」；
- 裡面有一個 **「開啟擴充套件設定頁」** 按鈕 —— 網頁不能自己跳 `chrome-extension://`，所以這一步由擴充套件代勞；
- 面板裡還寫著兩句可直接照拄的例子。

授權三步：

1. **在目標頁面上點一次擴充套件圖示** —— 它就進了候選；拾取模式下的**底部細條**上直接會顯示
   本頁的授權狀態（未授權 / 已授權 / 總開關關著）；
2. 在細條上點 **「讓 AI 操作本頁…」**（確認條裡的同名按鈕、或直接在擴充套件選項頁填地址都行）；
3. 在擴充套件選項頁點 **「授權該頁面」**（這一步順帶申請那個地址的 host 許可權）。

授權完成後回到那個頁面，細條會**自己變成「已授權 · 模型可操作本頁」**（擴充套件監聽授權表變化，
不用重新點圖示、也不用重新整理頁面）。

也可以隨時在選項頁**收回授權**（收回後模型立即再也碰不到那一頁）。

### 引用一個頁面到對話（不用手打網址）

授權之後，讓模型操作某個頁面不需要在話裡寫網址 —— 頂欄那個按鈕就是入口：

- **只授權了一個頁面**：頂欄按鈕**直接變成那個頁面的標題**，點一下就把「網頁引用」放進輸入框；
  右側的 **▾** 才是原來的狀態面板（授權管理 / 開關 / 重新整理都在裡面）。
- **授權了多個頁面**：按鈕仍是「瀏覽器操作 · N」，打開面板，每個頁面後面都有 **「引用到對話」**，
  可以連著引用多個。
- 引用進輸入框的是一個 `🌐 頁面標題` 的附件 chip —— 與「引用檔案」同一種東西（可刪、可多條、
  可與檔案附件混搭），**不會自動傳送**：你補一句「把前十條讀出來」再發。
- 傳送時服務端會給模型附一句說明（`<browser-page url title>`）：**這個頁面已授權、用 `browser_page`、
  `target=` 這個 origin** —— 模型不必從你的話裡猜網址，也不會跑去抓網頁。

**模型在頁面裡動手時，那個頁面右下角會閃一條提示**（「AI 正在操作本頁 · click #submit」）——
只報信、不攔截、2 秒後淡出，省得你以為頁面自己在動。

### 模型能做什麼

| 動作     | 引數                                                  | 說明                                                                                          |
| -------- | ----------------------------------------------------- | --------------------------------------------------------------------------------------------- |
| `pages`  | —                                                     | 列出已授權頁面（標題、開著沒、以及使用者正在看的那一個 `active:true`）—— 模型先看這一步再幹活 |
| `read`   | `what`: text / html / title / url / query；`selector` | 讀頁面或某個元素；`query` 返回元素摘要（文本/尺寸/輸入框的值）                                |
| `click`  | `selector`、`index?`                                  | 先滾進視口再派發真點選（頁面的監聽器會收到）                                                  |
| `type`   | `selector`、`text`、`clear?`、`submit?`               | 輸入（走原生 setter + 補發 input/change，React 受控元件也認）；`submit` 會發回車              |
| `scroll` | `selector?`、`to?{x,y}`、`by?{x,y}`                   | 滾動或把某個元素滾進視野                                                                      |
| `goto`   | `url`                                                 | 跳轉（先回結果再跳，不讓這次呼叫變成“沒響應”）                                                |
| `wait`   | `selector?`、`text?`、`timeoutMs?`                    | 等元素/文案出現（SPA 非同步渲染就靠它）                                                       |
| `eval`   | `code`                                                | 在頁面裡執行一段 JS（**預設關**，見下）                                                       |
| `shot`   | `selector?`、`maxEdge?`                               | **截圖**（AI 的眼睛）：給整屏或某個元素，長邊預設 1280、上限 1568。需要額外授權，見下         |

`pages` / `status` 除了列頁面，還會回答「**使用者正在看哪個頁面**」：最後一個聚焦窗口裡 `active` 的那個標籤，
對應頁面標 `active: true`，並在列表旁給出 `activeOrigin`。這裡不額外要 `tabs` 許可權 —— 只對**已授 host 許可權的
origin** 查 `{ active: true, lastFocusedWindow: true }`，未授權頁面即便在前臺也不會被報給模型。
多個授權頁面並存時仍**必須顯式 `target`**（不能默默挑一個動手），報錯文案會直接點名使用者正在看的那個 origin。

### 三層開關

| 開關                        | 位置                         | 預設                           |
| --------------------------- | ---------------------------- | ------------------------------ |
| 工具 `browser_page`         | pi-web-ui 設定 → 工具        | 開                             |
| 「允許 AI 操作頁面」總開關  | 擴充套件選項頁 → AI 操作頁面 | 開                             |
| 「允許執行任意 JS（eval）」 | 擴充套件選項頁 → AI 操作頁面 | **關**                         |
| 「允許截圖（shot）」        | 擴充套件選項頁 → AI 操作頁面 | 開（但要先授一次許可權，見下） |

`read` / `click` / `type` / `scroll` / `goto` / `wait` 都是「用頁面自己會響應的事件做事」；
`eval` 是「把頁面交給一段模型寫的指令碼」——能改資料、能提交表單，所以它預設關，要用得手動開啟。

### 截圖（AI 的眼睛）與視覺橋

模型預設只能靠 `read` 讀 DOM 文本 —— 「這頁看起來對不對」這類問題它答不了。`shot` 補上這一環：
整屏或某個元素截一張圖，**主模型能識圖就直接看圖；純文本模型自動走視覺橋轉寫**
（與使用者貼上圖片同一套邏輯：設定裡開著就生效，不需要額外配置）。

兩個必須知道的代價：

| 代價           | 說明                                                                                                                                                                                           |
| -------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **要額外授權** | 瀏覽器的截圖 API 只認 `<all_urls>` 或「你點圖示那一刻的臨時授權」（普通 host 授權不夠）。所以開啟「允許截圖」時會彈一次**「讀取您在所有網站上的資料」** —— 不給就保持關閉，模型仍能用 `read`。 |
| **會切標籤頁** | 截圖只能截**當前活動標籤頁**：擴充套件會先把目標頁切到前臺、截完**立刻切回**（失敗也切回）。你的焦點會跳一下。                                                                                 |

截圖長邊預設 1280、上限 1568（JPEG，體積可控）；`selector` 給了就按元素裁剪（元素幾乎不在視口裡時**不截**，而不是給一張誤導人的碎圖）。

### 安全模型

- **授權列表是唯一憑據**：沒被授權的頁面一個位元組都不注入，模型也點不到；
- **只在 pi-web-ui 頁面上發起**：擴充套件只認「瀏覽器裡那個已綁服務地址的 pi-web-ui 頁面」作為呼叫方
  （用 `sender.tab.url` 判定），其它頁面和外部程式一律拒絕；
- **動作白名單**：白名單共 12 個（上表 9 個 + 宿主側自用的 `status` / `openOptions` / `metrics`），之外的動作名直接拒（否則頁面裡一段指令碼就能指使擴充套件幹別的）；
- 授權必須在選項頁點一次（host 許可權要使用者手勢），所以“把某個頁面交給 AI”總是人工決定。

### 失敗時會說什麼

| 情況                        | 模型看到的                                            |
| --------------------------- | ----------------------------------------------------- |
| 沒授權任何頁面              | 「還沒有授權任何頁面給 AI —— 去選項頁授權」           |
| 目標頁面沒開啟              | 「頁面（http://…）沒開啟 —— 先把它開在標籤頁裡」      |
| 頁面多個且沒指定 target     | 「有多個已授權頁面 —— 用 target 指定一個」            |
| 選擇器沒匹上                | 「選擇器沒匹上：#xxx」（帶下一步建議）                |
| `wait` 超時                 | 返回 `found: null` + 花了多久（不報錯，模型自己決策） |
| 開啟過 eval 但頁面 CSP 禁止 | 一句帶「換用 read/click/type」建議的錯誤              |
| 瀏覽器裡沒有 pi-web-ui 頁面 | 「請先開啟 pi-web-ui 頁面」（工具超時前就會說）       |

### 已知限制

- **pi-web-ui 頁面得開著**（並在那個瀏覽器裡）：模型的動作只能從它送進擴充套件。
- **桌面版（Electron 外殼）用不了**：桌面窗口裡沒有 Chrome 擴充套件執行時，擴充套件裝不上
  （issue #153）—— 請用系統瀏覽器開啟同一個 pi-web-ui 地址（網頁版），面板裡有直達按鈕。
- **`eval` 受目標頁面的 CSP 約束**：頁面寫了不許 `unsafe-eval`（不少生產站）時，eval 用不了 ——
  這是瀏覽器的規矩，不是 bug（改資料請用 click/type）。
- 橋裝在**頂層幀**；跨源 iframe 裡的元素拿不到。
- `chrome://`、擴充套件頁、商店頁、`file://`（需手動允許）不能授權。
- 頁面裡的**第三方指令碼**也能看到擴充套件注入的 `window.__piBridge`（與頁面橋同一個邊界）——
  所以只對你信任的頁面授權。

## 頁面橋：讓兩個頁面互相讀寫

拾取是單向的（網頁 → pi-web-ui 輸入框）。**頁面橋**把擴充套件的另一半能力也開啟：兩個
**配對過**的頁面可以互相呼叫 —— 跨源、跨標籤頁、跨視窗都行。

瀏覽器裡只有擴充套件能做到這件事：跨源 `postMessage` 需要 `window.open` 的返回控制代碼且對方配合，
`BroadcastChannel` / `localStorage` 只限同源。

```js
// B 頁（被呼叫方）：註冊能力
window.__piBridge.on("orders", () => [...document.querySelectorAll(".order")].map((el) => el.textContent));
window.__piBridge.on("highlight", ({ id }) => document.querySelector(`#${id}`)?.scrollIntoView());

// A 頁（呼叫方）：調它
const orders = await window.__piBridge.call({ op: "orders" }); // 唯一對端時不用寫 to
await window.__piBridge.call({ to: "https://other.example", op: "highlight", args: { id: "row-3" } });
window.__piBridge.peers; // 我能跟誰說話（陣列，僅參考）
```

| 方法                                   | 說明                                                                     |
| -------------------------------------- | ------------------------------------------------------------------------ |
| `on(op, handler)`                      | 註冊操作（`op` 是非空短字串）；返回登出函式。對端呼叫時執行 `handler`    |
| `off(op)`                              | 登出                                                                     |
| `call({ op, args?, to?, timeoutMs? })` | 調對端，resolve 它的返回值；失敗 reject 一個帶原因的 `Error`             |
| `peers`                                | 當前對端 origin 列表（**僅供參考**，放行與否由擴充套件後臺按配對錶判定） |
| `version` / `self`                     | 協議版本 / 本頁 origin                                                   |

**怎麼開通**（**地址不用手打**）：

1. 在要配對的兩個頁面裡**各點一次擴充套件圖示**（拾取那一下就行）—— 它們就進了候選；
2. 開發頁上的拾取浮條還有個「與另一頁配對…」按鈕：點一下會把**本頁**預填好並直接開啟設定頁；
3. 在選項頁「頁面橋」裡點一下另一個端點的輸入框、在下拉里選它，再點「授權並新增配對」。

預設**關閉**：只有列出來的配對能通，頁面不會因為裝了擴充套件就憑空多出一條通道。

> 候選為什麼只看「點過圖示的頁面」：直接列所有標籤頁要麼得加 host 許可權（未授權站點讀不到 url），
> 要麼得加 `tabs` 許可權（安裝時會提示「讀取您的瀏覽記錄」）—— 為一個下拉框多要一份看著很嚇人的許可權
> 不划算。點圖示那一刻本來就有 `activeTab`，url 與標題都可讀。

### 契約與限制

| 項         | 規則                                                                                         |
| ---------- | -------------------------------------------------------------------------------------------- |
| 資料       | 必須能 JSON 序列化（跨源兩個 JS 堆隔離，只能傳普通資料）。DOM 節點 / 函式 / 迴圈引用都過不去 |
| 引數體積   | ≤ 256KB；結果 ≤ 512KB（超了報錯，不會把 service worker 拖死）                                |
| `op`       | 非空、≤ 64 字元、不含控制字元                                                                |
| 超時       | 預設 5s，最大 30s；超時由**頁面側**自己兜底（Promise 不會懸著）                              |
| 對端沒開啟 | 報「對端頁面沒開啟 —— 先把它開在一個標籤頁裡」                                               |
| 對端沒註冊 | 報錯裡列出**它註冊了什麼**（省得對著兩個頁面對照程式碼）                                     |
| 注入不了   | `chrome://`、擴充套件頁、商店頁、`file://`（需手動允許）都不能配對                           |
| iframe     | 橋裝在**頂層幀**；跨源 iframe 裡的頁面各自算一個頁面（另有其 origin）                        |

### 安全模型（重要）

- **預設拒絕**：沒配對的 origin 一律拒絕，配對錶裡被停用的也拒絕。
- **只認 sender**：擴充套件後臺判斷「你是誰」只用 `sender.tab.url`，**訊息體裡的任何欄位都不作數**
  —— 否則 A 頁面可以自稱是 B，把 B 的全部資料拿走。
- **授權要使用者手勢**：加一對配對要在選項頁點一下（`chrome.permissions.request` 不認網頁上的
  按鈕），所以「開一條橋」天然帶一次人工確認。
- **`window.__piBridge` 在頁面主世界**：被配對頁面裡的**任何指令碼**（含第三方廣告/統計）都摸得到它。
  這是 MAIN world 的物理邊界，不是實現缺陷 —— 所以**只對你信任的頁面開橋**。

失敗時一律是一句能看懂的話（「對端沒註冊…」「還沒配對…」「沒授權…」），不會出現「點了沒反應」。

## 為什麼必須裝擴充套件

「在任意網頁上點選元素」這件事只能由瀏覽器內的程式碼做（要讀你開啟的那個頁面的 DOM、
要能跨站點執行）。可選的替代方案都更差：

- **書籤小工具（bookmarklet）**：不用裝東西，但會被頁面 CSP 擋（`script-src` 不含
  `unsafe-inline` 的站點直接失效），且無法可靠地把結果送進另一個源的 pi-web-ui 頁面。
- **純 DevTools Snippets**：手貼一段程式碼，每次都要自己找、自己跑，沒有 hover 高亮與多選。

所以擴充套件是唯一干淨的做法；代價就是要在**使用它的那臺瀏覽器**裡裝一次（開發者模式載入即
可，不必上架商店）。

## 已知限制

- **自動化裝擴充套件：Chrome 不行、Edge 行**。Chrome 137 起移除了 `--load-extension`（本機
  Chrome 153 實測 `chrome://extensions` 裝不上），所以主力 E2E 走「注入真實 `dist/picker.js`
  - 真 background 模組 + 真 pi-web-ui 頁面」的等價路線（`tests/page-picker-test.mjs`）；
    但**實測 Edge（152，headless）仍然接受 `--load-extension`**，於是另有一條**裝真擴充套件**的
    E2E（`tests/page-picker-edge-ext-test.mjs`，沒裝 Edge 就 SKIP）—— 它跑的是真 `chrome.*`，
    能發現「假 chrome 不校驗 match pattern」那類問題（0.2.0 的投遞失敗就是這麼漏掉的）。
    手動「載入已解壓的擴充套件程式」不受影響。
- 截圖只截**當前可見區域**（`captureVisibleTab`）；元素幾乎全在視口外時不截，而不是截一張誤導人的碎圖。
- Vue 只有檔案沒有行號（SFC 行資訊要 sourcemap 才能還原）；生產構建沒有 `_debugSource`，
  React/Vue 定位會自然降級到「命中的 CSS 位置」。
- 跨域樣式表讀不到 `cssRules` → 只跳過那張表，不影響其它來源的規則與拾取本身。
- 投遞**依賴 pi-web-ui 頁面開著**（這是當前架構的取捨：走頁面上的 `compose()` 而不是服務端
  API，好處是零服務端改動、天然複用登入態與草稿合併邏輯；代價是頁面關著時只能複製兜底）。
  要做成「頁面沒開也能收到」，得在服務端外掛里加一條 HTTP 收件路由 —— 那是另一條路。
