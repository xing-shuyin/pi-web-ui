# 執行軌跡（run-trace）

類 harness 的 agent 執行軌跡檢視：直接顯示**當前開啟對話**的時間線並做分析——頂部橫向泳道時間軸看全貌，點選分段看**分析**（來源/狀態/耗時/佔比），而不只是把對話內容再看一遍。

## 效果

```
🧭 執行軌跡 ● 即時    [寫小說 ●當前] [修 bug]        搜尋 [____]  ▶ 回放  EN  🗑
─────────────────────────────────────────────────────────────
09:01                                    用時 12分        09:13
輸入  ▓▓────▓▓────────────────────────────────────────────
模型  ──▓▓▓▓▓▓▓▓▓▓▓▓▓────────────────────────────────────
工具  ──────▓▓▓▓▓▓─────────────────────────────────────────
──────────────────────────────┬────────────────────────────
分段列表                       │ 詳情（概述/預覽/原始內容/來源）
🧭 使用者 · 第 1 輪 · 寫個小說    │ 來源  工具 · edit
💭 思考                        │ 狀態  已完成
✅ edit · novel.md · 1.2s      │ 時長  1.2s
📝 改動 1 個檔案                │ 輪次  第 1 輪
🏁 …                           │ 📈 edit：累計 3 次 · 平均 1.1s ·
                               │   失敗率 0% · 佔工具耗時 62%
```

- **頂部泳道**：專業時間軸引擎 vis-timeline（自帶 vendor，離線優先）——自適應毫秒刻度、滾輪縮放、拖拽平移、一鍵適應；工具段按工具名著色（讀=青、寫=琥珀、bash=紫，其餘雜湊分配，圖例與色塊同色），失敗標紅、執行中閃爍，點選色塊即選中分段；vendor 缺失時回退 CDN，再失敗回退手寫時間軸。
- **即時流動（跟隨）**：對話正在跑時，時間軸錨定「現在」——**色塊逐幀平滑左移，時間刻度線釘在螢幕固定位置一動不動**（刻度數值隨時間滾動），繪圖區右側 40px 處一條固定的「現在」豎線，新事件貼著它出現再往左流走；執行中的色塊右端始終釘在「現在」線上、隨真即時間生長。滾輪縮放不會退出跟隨（按新縮放級別重新錨定），拖拽平移會暫停跟隨（點「跟隨」恢復），執行結束時平滑退出、內容不跳。
- **左列**：分段列表（使用者/思考/回答/工具/檔案/系統 chips + 時間 + 耗時）。
- **右列**：選中分段的四 tab 詳情——
  - **概述**：來源/狀態/時長/輪次/長度/位置 + 分析（工具段：該工具累計呼叫/平均耗時/失敗率/耗時佔比）。
  - **預覽/原始內容/來源**：內容與出處（訊息 key、呼叫 id、輪次、對話）。
- **無選中時**：對話級分析（總時長/輪數/工具呼叫與失敗/工具耗時/最慢工具 Top/檔案改動/階段分佈）。
- **回放**：按**真即時間**播放——每個塊按其真實耗時停留（秒級工具一閃而過、長思考就停留這麼久），播放頭沿時間軸推進並自動跟隨視窗；可變速（0.5/1/2/4×），可勾選「跳過空閒」壓縮輪次間的長間隙；進度條拖動跳轉 + 播放/暫停。
- **中英雙語**，篩選（泳道開關 + 搜尋）。

## 原理

- 歷史全量：`host.getActiveConversation()`（當前開啟對話的全部訊息 + 統計）→ 開啟對話即有完整時間線，歷史對話切回來也有。
- 即時增量：`host.onRunEvent` 的 tool_start/tool_end 直接追加/原地更新工具段（含精確耗時/引數/結果）；message/run_* 事件觸發歷史重拉（去抖 300ms）+ 流式 5s / 空閒 30s 輪詢。
- 耗時：assistant 時間戳是訊息建立時刻（生成起點，transcript 裡總緊貼上一條 toolResult）：思考/回答自該時刻向前排布，按字元量估計時長（約 50 字/秒），上限至下一條訊息時刻（生成必在其前完成），超窗等比壓縮，結束處銜接工具呼叫起點；工具段耗時 = 結果時刻 − 呼叫起點（純執行，不再含生成）；瞬時/極短事件只在顯示層保底 ≈2px（按當前縮放視窗換算的窄條，保證可見可點），塊寬度與時間軸刻度嚴格對齊，放大後自動收斂回真即時長——不再用固定假寬把序列工具呼叫疊成一堆行。
- 初始總覽自動聚焦“活躍段”：把輪次間的長空閒裁掉，真正幹活的時間填滿視口（多輪相當分散時回退全量，不硬裁）；「⤢ 適應」按鈕仍是看全部。
- 跟隨的平滑靠「CSS transform 逐幀位移 + 視窗提交」兩段實現：累計位移 ≥90px 才 `setWindow` 一次（提交後同步觸發 vis 整表重繪，讓條目重排與 transform 歸零落在同一幀，肉眼無跳變）；跟隨期間隱藏 vis 自帶軸/網格，刻度尺由外掛自繪（位置固定、數值每秒滾動，步長從 1s 到 1 天按縮放自動選）。
- 檔案段：寫類工具（edit/write/patch…）成功後從**呼叫引數**摳路徑；歷史訊息的 toolCall 引數同樣覆蓋。
- 訊息原文預設不下發（單條可達 200K）：列表只帶摘要，詳情按段按需拉。
- 時間軸 vendor：`npm run build:runtrace-vendor`（升級 vis-timeline 後重打；產物提交進 git）。

## 限制

- 目前只覆蓋 **pi 引擎**（dsh 引擎無快照/事件，檢視為空態）。
- 跨重啟只保留最近開啟的對話（ transcript 本身是真相源，切回即重建；外掛不另存）。
