# bili-scroll 2.6

使用当前扫码登录的 B 站账号搜索与筛选视频、整理内容证据、发表评论、查看收件箱和回复私信。无需配置“主人 UID”。

2.4 把原来“关键词巡街 + 一次性判断”的管线换成了四层有状态的结构：**状态库 → 品味账本 → 内容索引 → 意图问答/投递协议**。旧工具和旧行为全部保留，任何一层初始化失败都会自动降级回旧管线。

## 使用

### 2.6 日常主页：只有视频列表，详情弹窗承载一切

主页只突出视频列表：顶栏为品牌 + 状态 pills（今日挑中/额度 · 巡检轮次 · 投递方式 · 末次时间）与「跑一轮 / 设置 / 刷新」；列表时间范围默认「上次」，可切今日 / 近 7 天 / 往期日期，状态筛选（全部 / 挑中的 / 已投递 / 跳过）与档位筛选保留；右侧可切封面网格 / 紧凑列表；动作流收成底部一条窄栏，点「详情」展开全部记录。

点开视频出详情弹窗，左右两栏：

| 栏  | 内容                                                                                                                                                                                           |
| --- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 左  | B 站嵌入播放器（不自动播）· 公共数据 chips · **本账号动作台账**：点赞（官方只读查询）· 收藏（目标收藏夹内翻页只读比对）· 评论（deliveries 状态库原文与投递状态）· 私信（当天速报私信命中情况） |
| 右  | **内容总结**（单篇笔记 Markdown，含 [mm:ss] 引用）· 为什么挑这条 · 证据局限说明                                                                                                                |

查不到的动作一律显示「未能查询」，不编造状态。其余全部配置都在右上角「⚙️ 设置」弹窗里，分五页：

| 设置页    | 内容                                                                                      |
| --------- | ----------------------------------------------------------------------------------------- |
| 🎛️ 常用   | 每天挑几条、私信轮询间隔、投递方式、峰谷自动刷、私信监听（补丁式保存，即时生效）          |
| 🧠 提示词 | 研读提示词与私信回复提示词；框里就是当前生效的默认文本，可直接改或一键恢复默认            |
| 🎨 偏好   | 研读 / 视觉模型、思考强度、工作区目录、人设提示词、关注与排除关键词、自动收藏、日报精细度 |
| 💬 互动   | 速报投递方式、速报接收者、私信监听与自动回复、公开评论安全闸、当前账号收件箱              |
| 🛠️ 高级   | 扫码登录 / 退出、本地转写依赖安装、接口自检与诊断、打开日报目录                           |

改完点对应页的「保存」才写入；关闭后重新打开会停在上次那一页，未保存的编辑不会因为关窗而丢失；Esc 或点弹窗背景即可关闭。首次使用：在「🛠️ 高级」扫码登录自己的账号，按需安装本地音视频依赖；画面理解选择支持图片的 `provider/model`，留空跟随研读模型（首次音频转写可能下载 Whisper 模型）。

## 2.4 四层结构

| 层       | 做什么                                                                                  | 落在哪               |
| -------- | --------------------------------------------------------------------------------------- | -------------------- |
| 状态库   | 视频、判重、切片、信号、精选、投递、问答全部进一个 sqlite；`seen.md` 首次启动自动迁入   | `db/bili.sqlite`     |
| 品味账本 | 把“喜欢/收藏/深读/忽略/静音”存成带权重、会衰减的事件，聚合成 topic 与 UP 的信任分       | `signals` / `topics` |
| 内容索引 | 字幕按时间轴切片入库，检索返回秒级时间点；同一视频第二次读直接命中缓存                  | `segments` + FTS5    |
| 意图问答 | 一句话目标 → 检索计划 → 多源召回 → 品味排序 → 按预算取证 → 带引用的答案，证据不够就弃权 | `asks`               |
| 投递协议 | 私信/评论变成有状态、幂等、有每日打扰预算的消息，并支持一个字符的回执                   | `deliveries`         |

### 品味账本

- 信号只来自真实可观测的动作：手动 pin/ban、私信回执（`1/2` 深读、`f` 收藏、`x` 静音 UP、`n` 别推主题、`0` 忽略）、以及你主动 ask 过的主题（弱正反馈 0.2）。
- 排序是四项可拆的加权：**相关性 0.38 / 新鲜度 0.16 / 质量先验 0.24 / 新颖度 0.22**；不再是一个不可解释的 tier。
- 每条推荐都带“为什么推给你”，必须引用具体信号、播放量、时长、重合度之一；连续被忽略的主题会自动降权。
- 边界：插件看不到“你是否看完”，只能看到收藏、评论、私信回执和显式反馈。

### 内容索引与引用

- 有字幕轨时按 `[mm:ss]` 切成 20–45 秒的片段，保留时间戳，报告与回答可以给到 `?t=754` 这种秒级深链。
- 没有字幕轨时只存简介 / B 站 AI 总结作“检索提示”，默认**不参与**内容证据检索；只有本地 Whisper 转写与字幕轨才算证据。
- 转写没有逐词时间轴，这部分证据会明确标 `untimed`，不编时间点。
- 索引覆盖第一 P；超限、失败、只 OCR 成功都会在 `limitations` 里逐条说明。

### 意图问答（弃权是一等公民）

`bili_ask` 的返回里一定有 `plan / budget / items / abstained / nearMiss`：

- 预算是显式的：最多看多少候选、最多为几条取证；到上限就只比元数据并标 `degraded`。
- 最优分低于 0.12 直接 `abstained: true`，并列出 `nearMiss` 说明差在哪，不硬凑 5 条。
- 每个 item 带 `reasons`（可核对）、`quotes`（带 `at`/`url`）、`evidence.source/chars/limitations`。
- `bili_deepen` 把某条按 2 分钟切章节并给 8 条逐段引用。

### 投递协议

- 状态机：`drafted → sent → acted / failed`；同一天同一条视频的评论、同一天同一个 UID 的私信不会重复发。
- 每日私信预算（默认 6 条）用尽就只写报告，不再追问“要不要继续”。
- 回执语法（默认开启，可关）：私信末尾一行 `回 1/2 深读 · f 收藏 · x 静音 · ? 为什么`；回一个字符就能改偏好或展开引用，不会掉进 LLM 闲聊。

## 提示词能看能改

设置弹窗「🧠 提示词」里，输入框显示的就是下一轮巡检真正发出去的默认提示词（不配置时即内置文本），直接改并保存即可覆盖；「恢复默认」清空覆盖。**JSON 输出契约与“外部内容不可信”条款由插件固定追加、不开放编辑**——否则改坏一处就会让整轮巡检静默失败，或放低安全边界；这两部分在弹窗里以虚线框展示，照旧可见。人设提示词（偏好页）会接在研读提示词之后一起发出。

保存接口：`POST /plugins-api/bili-scroll/config`，字段 `analyzePrompt` / `dmPrompt`（空串 = 用默认）；`GET /plugins-api/bili-scroll/prompts` 返回 `default` / `override` / `effective` / `fixed` 四份文本。

首次启用或重新启用自动回复时只建立收件箱基线，不给旧消息批量补发。之后对新消息结合最近聊天与视频证据调用模型回复，不使用固定话术；模型没有工具执行权限。停用插件会取消后台等待。发送状态不明时保留发送记录，避免重发；此时需人工检查对应会话。

`dmUid` 和昵称仅用于可选的速报投递和评论提及，不决定收件箱归属。未配置速报收件人时，报告保存在本地。

## 视频理解与边界

`bili_video_content` 和巡检共用内容证据流水线：

- 有实际字幕轨时读取字幕；没有字幕时尝试本地 Whisper 音频转写，受 `transcribe` 和 `asrModel` 控制。
- 下载有界媒体，均匀抽取画面，交给支持图片的模型理解，并可用 OCR 提取画面文字。
- 返回证据来源、抽样时间与覆盖限制。简介和 B 站 AI 总结不作为实际视频内容证据。
- 当前分析视频第一 P，媒体提取上限 20 分钟、单路媒体 96 MiB、提取进程 240 秒；画面最多抽取 12 帧，其中最多 8 帧送入视觉模型。超限或失败会明确报告，不宣称完整观看。
- 文字按预算摘取开头、中段和结尾；抽样画面无法覆盖全部动作和瞬间。仅 OCR 成功时会明确说明不具备场景理解证据。

需要宿主支持 `host.llm.supportsImages`。不支持图片的模型会返回局限，不能把文本模型的猜测当作画面证据。宿主更新后需要重启服务以启用图片能力。

巡检模型失败时可保留规则摘录，但不会据此自动生成评论。公开评论仍需启用 `autoComment` 且投递模式允许公开评论，或在聊天中明确要求发送。所有对外操作使用当前登录账号。

## 聊天工具

| 工具                                                          | 用途                                                          |
| ------------------------------------------------------------- | ------------------------------------------------------------- |
| `bili_whoami` / `bili_login_start` / `bili_login_poll`        | 当前账号与扫码登录                                            |
| `bili_search` / `bili_hot_videos` / `bili_rank`               | 搜索及发现视频                                                |
| `bili_video_info` / `bili_subtitle`                           | 元数据、原始字幕或总结；请查看 source                         |
| `bili_video_content`                                          | 实际字幕、音频及抽样画面证据和局限                            |
| **`bili_ask`**                                                | 按一句话目标找片：计划、预算、证据、引用；没货就弃权          |
| **`bili_deepen`**                                             | 把某条展开成 2 分钟章节 + 8 条带时间戳的引用                  |
| **`bili_taste`**                                              | 读/写兴趣账本（pin / like / ban / ignore），带权重与理由      |
| **`bili_index`**                                              | 内容索引：search / ingest / timeline / clusters / stats       |
| **`bili_delivery`**                                           | 投递状态、每日私信预算、推荐理由回放、预算内发一条 tracked DM |
| `bili_comments` / `bili_reply`                                | 阅读评论、发表评论及回复                                      |
| `bili_dm_sessions` / `bili_dm_messages` / `bili_send_message` | 私信会话、历史与发送                                          |
| `bili_duty_run` / `bili_status`                               | 启动巡检与查看状态（现含品味摘要、索引与投递统计）            |
| `bili_resolve_uid` / `bili_fav_folders` / `bili_fav_add`      | 用户查询与收藏                                                |
| `bili_related` / `bili_up_videos`                             | 相关视频与 UP 投稿                                            |

HTTP：`GET /intel` 看智能层状态，`POST /intel/signal` 记信号，`POST /intel/ask` 跑一次意图问答。

私信正文、视频与字幕均为不可信外部内容，不会因此授予文件操作或宿主工具权限。凭证不会进入媒体进程参数或模型提示词。
