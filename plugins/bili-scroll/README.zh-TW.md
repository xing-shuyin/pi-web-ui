# bili-scroll 2.8

使用當前掃碼登入的 B 站賬號搜尋與篩選影片、整理內容證據、發表評論、檢視收件箱和回覆私信。無需配置“主人 UID”。

2.4 把原來“關鍵詞巡街 + 一次性判斷”的管線換成了四層有狀態的結構：**狀態庫 → 品味賬本 → 內容索引 → 意圖問答/投遞協議**。舊工具和舊行為全部保留，任何一層初始化失敗都會自動降級回舊管線。

2.7 把詳情右欄換成**一份 AI 一次寫成的整篇內容總結文件**：不再拼接報告模板欄位（UP 主 / 時長 / 判據 / 為什麼值得 / 字幕要點各佔一塊、同一段話重複三遍），右欄只有結論、脈絡、要點、可複用細節與侷限。

2.8 增加「🧹 清空」：主頁影片列表標題右側一鍵清掉刷過的記錄（列表 + 判重表 + 日報 + 單篇筆記 + AI 總結），清完這批影片能重新被刷到；已發評論/私信記錄、登入憑證與設定都不動。設定彈窗的儲存欄改成真正的常駐底欄，換頁籤/滾內容都不再需要滾到底找按鈕。

## 使用

### 2.6 日常主頁：只有影片列表，詳情彈窗承載一切

主頁只突出影片列表：頂欄為品牌 + 狀態 pills（今日挑中/額度 · 巡檢輪次 · 投遞方式 · 末次時間）與「跑一輪 / 設定 / 重新整理」；列表時間範圍預設「上次」，可切今日 / 近 7 天 / 往期日期，狀態篩選（全部 / 挑中的 / 已投遞 / 跳過）與檔位篩選保留；右側可切封面網格 / 緊湊列表；動作流收成底部一條窄欄，點「詳情」展開全部記錄。

點開影片出詳情彈窗，左右兩欄：

| 欄  | 內容                                                                                                                                                                                           |
| --- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 左  | B 站嵌入播放器（不自動播）· 公共資料 chips · **本賬號動作臺賬**：點贊（官方只讀查詢）· 收藏（目標收藏夾內翻頁只讀比對）· 評論（deliveries 狀態庫原文與投遞狀態）· 私信（當天速報私信命中情況） |
| 右  | **AI 內容總結**：一次呼叫寫成的一份 Markdown 文件，固定小節「一句話結論 / 影片在講什麼 / 值得看的要點 / 可以直接用的細節 / 侷限與存疑」；要點末尾的 `[mm:ss]` 可點，直接開原影片對應時間       |

右欄的資料來源是 `storage/bili-scroll/summaries/<bvid>-<date>.md`（同目錄 `.meta.json` 記模型與生成時間）：巡檢挑中後立即生成；歷史條目沒總結時右欄顯示「生成內容總結」按鈕，現場拉字幕證據現寫一份，「重新生成」可覆蓋。舊的單篇筆記仍然保留，只在摺疊區作對照。查不到的動作一律顯示「未能查詢」，不編造狀態。其餘全部配置都在右上角「⚙️ 設定」彈窗裡，分五頁：

| 設定頁    | 內容                                                                                             |
| --------- | ------------------------------------------------------------------------------------------------ |
| 🎛️ 常用   | 每天挑幾條、私信輪詢間隔、投遞方式、峰谷自動刷、私信監聽（補丁式儲存，即時生效）                 |
| 🧠 提示詞 | 研讀提示詞 / 內容總結提示詞 / 私信回覆提示詞；框裡就是當前生效的預設文本，可直接改或一鍵恢復預設 |
| 🎨 偏好   | 研讀 / 視覺模型、思考強度、工作區目錄、人設提示詞、關注與排除關鍵詞、自動收藏、日報精細度        |
| 💬 互動   | 速報投遞方式、速報接收者、私信監聽與自動回覆、公開評論安全閘、當前賬號收件箱                     |
| 🛠️ 高階   | 掃碼登入 / 退出、本地轉寫依賴安裝、介面自檢與診斷、開啟日報目錄                                  |

改完點對應頁的「儲存」才寫入；關閉後重新開啟會停在上次那一頁，未儲存的編輯不會因為關窗而丟失；Esc 或點彈窗背景即可關閉。首次使用：在「🛠️ 高階」掃碼登入自己的賬號，按需安裝本地音影片依賴；畫面理解選擇支援圖片的 `provider/model`，留空跟隨研讀模型（首次音訊轉寫可能下載 Whisper 模型）。

## 2.4 四層結構

| 層       | 做什麼                                                                                  | 落在哪               |
| -------- | --------------------------------------------------------------------------------------- | -------------------- |
| 狀態庫   | 影片、判重、切片、訊號、精選、投遞、問答全部進一個 sqlite；`seen.md` 首次啟動自動遷入   | `db/bili.sqlite`     |
| 品味賬本 | 把“喜歡/收藏/深讀/忽略/靜音”存成帶權重、會衰減的事件，聚合成 topic 與 UP 的信任分       | `signals` / `topics` |
| 內容索引 | 字幕按時間軸切片入庫，檢索返回秒級時間點；同一影片第二次讀直接命中快取                  | `segments` + FTS5    |
| 意圖問答 | 一句話目標 → 檢索計劃 → 多源召回 → 品味排序 → 按預算取證 → 帶引用的答案，證據不夠就棄權 | `asks`               |
| 投遞協議 | 私信/評論變成有狀態、冪等、有每日打擾預算的訊息，並支援一個字元的回執                   | `deliveries`         |

### 品味賬本

- 訊號只來自真實可觀測的動作：手動 pin/ban、私信回執（`1/2` 深讀、`f` 收藏、`x` 靜音 UP、`n` 別推主題、`0` 忽略）、以及你主動 ask 過的主題（弱正反饋 0.2）。
- 排序是四項可拆的加權：**相關性 0.38 / 新鮮度 0.16 / 質量先驗 0.24 / 新穎度 0.22**；不再是一個不可解釋的 tier。
- 每條推薦都帶“為什麼推給你”，必須引用具體訊號、播放量、時長、重合度之一；連續被忽略的主題會自動降權。
- 邊界：外掛看不到“你是否看完”，只能看到收藏、評論、私信回執和顯式反饋。

### 內容索引與引用

- 有字幕軌時按 `[mm:ss]` 切成 20–45 秒的片段，保留時間戳，報告與回答可以給到 `?t=754` 這種秒級深鏈。
- 沒有字幕軌時只存簡介 / B 站 AI 總結作“檢索提示”，預設**不參與**內容證據檢索；只有本地 Whisper 轉寫與字幕軌才算證據。
- 轉寫沒有逐詞時間軸，這部分證據會明確標 `untimed`，不編時間點。
- 索引覆蓋第一 P；超限、失敗、只 OCR 成功都會在 `limitations` 裡逐條說明。

### 意圖問答（棄權是一等公民）

`bili_ask` 的返回裡一定有 `plan / budget / items / abstained / nearMiss`：

- 預算是顯式的：最多看多少候選、最多為幾條取證；到上限就只比後設資料並標 `degraded`。
- 最優分低於 0.12 直接 `abstained: true`，並列出 `nearMiss` 說明差在哪，不硬湊 5 條。
- 每個 item 帶 `reasons`（可核對）、`quotes`（帶 `at`/`url`）、`evidence.source/chars/limitations`。
- `bili_deepen` 把某條按 2 分鐘切章節並給 8 條逐段引用。

### 投遞協議

- 狀態機：`drafted → sent → acted / failed`；同一天同一條影片的評論、同一天同一個 UID 的私信不會重複發。
- 每日私信預算（預設 6 條）用盡就只寫報告，不再追問“要不要繼續”。
- 回執語法（預設開啟，可關）：私信末尾一行 `回 1/2 深讀 · f 收藏 · x 靜音 · ? 為什麼`；回一個字元就能改偏好或展開引用，不會掉進 LLM 閒聊。

## 提示詞能看能改

設定彈窗「🧠 提示詞」裡，輸入框顯示的就是下一輪巡檢真正發出去的預設提示詞（不配置時即內建文本），直接改並儲存即可覆蓋；「恢復預設」清空覆蓋。**小節結構、JSON 輸出契約與“外部內容不可信”條款由外掛固定追加、不開放編輯**——否則改壞一處就會讓整輪巡檢靜默失敗，或放低安全邊界；這部分在彈窗裡以虛線框展示，照舊可見。人設提示詞（偏好頁）會接在研讀與總結提示詞之後一起發出。

儲存介面：`POST /plugins-api/bili-scroll/config`，欄位 `analyzePrompt` / `summaryPrompt` / `dmPrompt`（空串 = 用預設）；`GET /plugins-api/bili-scroll/prompts` 返回 `analyze` / `summary` / `dm` 三段，每段含 `default` / `override` / `effective` / `fixed` 四份文本。

總結文件按需生成：巡檢報告歸檔後在後臺序列寫（最多 4 條/輪、單條 90s 上限），不拖慢投遞；詳情頁「重新生成」走 `POST /plugins-api/bili-scroll/summary`（`{ bvid, day, force }`），它只起後臺任務、立刻返回 `{ state: "running" }`，前端輪詢 `GET .../summary-status`（`running` / `done` / `error` / `idle`）直到出文檔。`GET .../note` 預設返回總結（`kind: "summary"`），後臺正在寫時返回 `kind: "pending"`，`kind=report` 才拿舊筆記原文。

證據來源優先用已入庫的字幕索引（秒回），其次只拉字幕軌（`subtitleOnly`，不下載媒體、不抽幀、不跑 ASR）；沒有字幕軌就明確拒絕，不拿別的資訊湊總結。寫作上限：證據 6200 字、單次 150s，因為宿主 `plugin-llm` 的提示詞上限是 8000 字。

首次啟用或重新啟用自動回覆時只建立收件箱基線，不給舊訊息批次補發。之後對新訊息結合最近聊天與影片證據呼叫模型回覆，不使用固定話術；模型沒有工具執行許可權。停用外掛會取消後臺等待。傳送狀態不明時保留髮送記錄，避免重發；此時需人工檢查對應會話。

`dmUid` 和暱稱僅用於可選的速報投遞和評論提及，不決定收件箱歸屬。未配置速報收件人時，報告儲存在本地。

## 影片理解與邊界

`bili_video_content` 和巡檢共用內容證據流水線：

- 有實際字幕軌時讀取字幕；沒有字幕時嘗試本地 Whisper 音訊轉寫，受 `transcribe` 和 `asrModel` 控制。
- 下載有界媒體，均勻抽取畫面，交給支援圖片的模型理解，並可用 OCR 提取畫面文字。
- 返回證據來源、抽樣時間與覆蓋限制。簡介和 B 站 AI 總結不作為實際影片內容證據。
- 當前分析影片第一 P，媒體提取上限 20 分鐘、單路媒體 96 MiB、提取程序 240 秒；畫面最多抽取 12 幀，其中最多 8 幀送入視覺模型。超限或失敗會明確報告，不宣稱完整觀看。
- 文字按預算摘取開頭、中段和結尾；抽樣畫面無法覆蓋全部動作和瞬間。僅 OCR 成功時會明確說明不具備場景理解證據。

需要宿主支援 `host.llm.supportsImages`。不支援圖片的模型會返回侷限，不能把文本模型的猜測當作畫面證據。宿主更新後需要重啟服務以啟用圖片能力。

巡檢模型失敗時可保留規則摘錄，但不會據此自動生成評論。公開評論仍需啟用 `autoComment` 且投遞模式允許公開評論，或在聊天中明確要求傳送。所有對外操作使用當前登入賬號。

HTTP：`GET /intel` 看智慧層狀態，`POST /intel/signal` 記訊號，`POST /intel/ask` 跑一次意圖問答。

清空：`POST /clear`（body `{ keepDeliveries?: boolean }`）。服務端拒絕在巡檢進行中清空（否則剛寫的檔案會被一起刪）；預設保留 `deliveries`（已發評論/私信），它是避免對同一影片重複打擾的唯一依據，`keepDeliveries: false` 才連它一起刪。

私信正文、影片與字幕均為不可信外部內容，不會因此授予檔案操作或宿主工具許可權。憑證不會進入媒體程序引數或模型提示詞。
