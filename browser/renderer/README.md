# Browser renderer

Vite root: `browser/renderer`, base: `./`. Entries: `shell.html`, `newtab.html`, `office.html`, `workspace.html`.

- The shell owns exactly two 44px rows. Its remaining surface stays transparent; browser/Agent content belongs to native WebContentsViews positioned by the desktop host below y=88.
- `common.ts` imports the shared `web/src/styles.css` baseline. `browser.css` defines prefixed browser structures using existing theme tokens.
- Preload may attach asynchronously. Calls and state subscriptions wait up to three seconds for `window.piBrowserShell`. Dropped files expose no path in the renderer, so `piBrowserShell.filePath(file)` (preload + `webUtils.getPathForFile`) is the only way to hand a `.crx` to the host; `enableCrxDropTarget()` in `common.ts` adds the drag hint and drop handler for the shell and new tab.
- `call(action,args)` returns data directly and rejects on failure. State is initialized with `state` and updated with `onState`.
- Shell dialogs acquire `overlay {open:true}` before display and release with `{open:false}` (the native content view sits above the DOM, so a floating panel needs it). They are **non-modal** (`dialog.show()`, not `showModal()`): no backdrop, no dimmed window, the toolbar stays clickable, and a click outside or `Escape` closes the panel. The extensions panel is the compact variant (`.pb-dialog-compact`, width 360px, height follows the list). Internal-page dialogs use the same `overlay` signal, but the host keeps their sender visible.
- Window controls use `window.piDesktop.window`. Optional `onOpenOptions` and `onFocusAddress` bridge events support native menus/shortcuts while page views own focus.
- Additional host actions: `downloads.list`, `extensions.list` (loaded + remembered-but-disabled, each with `path`/`enabled`, loaded ones also carry `popup`), `extensions.load` (unpacked folder), `extensions.installCrx` (`.crx` file, unpacked host-side; `{ path }` installs a dropped file, no `path` opens the picker), `extensions.toggle {path,enabled}`, `extensions.reload {path}`, `extensions.remove {path}` and `extensions.openPopup {path,anchor}` (frameless window on the extension's own `default_popup`, anchored at the row's bottom-right corner and sized to the page's own content — the host measures it and clamps to 800×600). The toolbar puzzle button opens the extensions panel; its badge counts enabled extensions and refreshes on `pb-extensions-changed`. One row per extension: clicking the row body opens that extension's page exactly like its toolbar icon (popup first, options page as fallback, panel closes first); the trailing ⋯ button and right-click share the same native `extensions.menu`. Download entries accept `filename` and legacy `name`; opening a download sends `download.open {id}`.
- Bookmarks use folder/link arrays. All page titles, bookmark names, imported content and credentials are rendered through DOM properties; user HTML is never inserted.
- Settings expose search engine, link target, Agent URL, `aiControl`, `allowShot`, `allowEval`, `allowScripts`, secure credential management and legacy data import. Extensions are managed in their own panel (toolbar icon, or the "Manage extensions" button in settings): one tap on a row opens the extension's own page, the row switch and the ⋯ menu handle enable/disable, reload, options and remove, and the two install buttons sit at the bottom of the panel; the set is restored on next start.
- File pages accept `?path=...` (and the legacy `?file=...`). Reads use `files.read {path}`; existing text files save with `files.save {path,content}`; new files use `{path:name,saveAs:true,content}`. The host grants paths through its native chooser.
- DOCX/XLSX/PPTX previews read real OOXML from bounded ZIP archives. They show document paragraphs, cached sheet values and ordered slide text. They do not preserve layout/images, evaluate formulas or execute macros, and cannot overwrite binary originals. Text/Markdown/CSV/TSV support editing. Large tables fall back to the text editor to preserve all data.
- Workspace previews raster images, audio, video and PDF from granted bytes in Blob URLs. HTML/SVG and other active content are shown only as text or rejected as unsupported.
- The old search popup is represented by the shell address bar; map the `search` internal alias to `newtab.html`.

Local checks (no global build):

```sh
npx tsc -p desktop/tsconfig.json --noEmit
node browser/renderer/verify-ui.mjs
```

`verify-ui.mjs` starts a temporary Vite server on 8994 and uses `playwright-core` with local Chrome/Edge. Set `BROWSER_EXECUTABLE` to use another Chromium executable. It checks delayed preload, fixed transparent chrome, navigation/modes, overlay lifecycle, bookmark escaping/mutation, settings, permissions, credential add/delete, the extensions panel (non-modal, no backdrop, icon badge, toggle, row click opens the popup, ⋯/right-click menu, remove, both install entries, toolbar toggle + click-outside), download opening, responsive newtab, CSV save and compressed OOXML fixtures. The host bridge is mocked; native Electron behavior is verified by `node tests/browser-desktop-smoke.mjs` (seeded unpacked extension → restore → popup window → disable/enable/reload/remove).
