# 裝置中心與跨平臺協作（內測）

手機原生客戶端可使用 Hub 賬號列出、連線和切換多臺裝置，集中接收裝置通知；native 登入、capability、中繼邊界和構建驗收見 [`mobile.md`](mobile.md)。

裝置中心是獨立的賬號、裝置連線和群聊服務。每臺 pi-web-ui 主動連線中心，無需每臺電腦具有公網地址。裝置中心可自行部署；倉庫沒有配置一個已上線的官方公共入口。Windows、macOS、Linux 使用相同連線協議，真實平臺測試仍須在對應機器上執行。

主程式的 **裝置連線與跨平臺協作** 是統一入口，按 **裝置與連線 / 群組與工單 / 外部渠道** 分割槽。裝置分割槽保留配對、Bot、遠端桌面與執行許可；群組分割槽可建立或管理群組，並直接配置獨立 AI Router、檢視工單和重試失敗執行；外部渠道內嵌隨包 Superagent，配置 GitHub / 飛書憑據與群組對映，無需單獨安裝或獨立頂欄入口。實際聊天仍沿用左側群組主對話流。

獨立部署步驟見 [裝置中心部署指南](device-center-deployment.md)：從伺服器連線、預設 IP + HTTP，到埠放行、可選域名與 HTTPS、驗證及故障恢復，無需專案上下文。

繫結裝置中心後，左上角品牌圖示可點選開啟裝置快捷列表，直接訪問同賬號裝置或開啟遠端桌面。快捷列表複用裝置中心的裝置目錄與繫結授權入口，支援線上狀態、手動重新整理和窄屏展示；點選外部或按 Escape 關閉。尚未繫結時保留普通品牌展示，臨時連線失敗不撤銷已知繫結入口。

## 首次使用與安裝引導

未繫結中心時，本機即可建立 Bot 和群組，無需連線其他裝置、註冊賬號或安裝獨立 Hub。群組入口按需啟動程序內的私有 loopback Hub，複用現有 Bot、群聊、任務及檔案協議；資料儲存在 `<pi-web-ui data-dir>/local-device-hub/`，憑據只在服務端使用並在重啟時輪換。本機任務允許執行，仍受 Bot 能力白名單和本機審批限制；外部 Hub 的執行許可仍預設關閉。本機 Bot 使用原有 unpaired 作用域，群組和訊息重啟保留；繫結外部 Hub 後切換到其獨立作用域，斷開後恢復本機資料，切換前必須停止舊執行時。外部 Hub 離線時保留其繫結和已知群組，不自動切換本機資料。

裝置中心概覽始終提供 Bot 和群組管理入口。需要跨裝置時，可選擇「連線已有中心」或「建立我的中心」；建立時可以使用承載 pi-web-ui 服務的當前機器，也可以在已有伺服器部署。尚無伺服器可先使用當前機器體驗，無需購買伺服器才能開始。這裡的「當前機器」指 pi-web-ui 服務所在機器，不是開啟瀏覽器的裝置。

本機一鍵安裝預設僅允許通過 localhost/127.0.0.1 訪問；反向代理部署可用 `PI_WEB_ALLOW_HOSTS` 宣告該域名，聲明後同樣可以訪問（未宣告時行為不變）。寫請求必須同源。頁面先展示平臺、Node 版本、獨立資料目錄和安裝方案；點選安裝後以獨立子程序呼叫當前包的 Hub CLI，以固定引數執行，不經過 shell。預設監聽 `127.0.0.1:8790`，資料儲存在 `<pi-web-ui data-dir>/device-hub/`，與客戶端配置分離。頁面可修改監聽 IP、埠及公開訪問 origin；其他裝置要連線時，必須使用其他裝置可達的地址，並配置相應網路訪問。

安裝成功表示服務已安裝並通過啟動驗證，不代表已登入或完成配對。通過 `pi-web-ui hub status --json` 可檢查已安裝服務，通過 `pi-web-ui hub restart --allow-registration=false` 關閉註冊。接著開啟中心建立賬號，再回到配對流程，繫結後建立 Bot 和群組。安裝會顯式開放賬號註冊，建立賬號後應使用服務管理命令關閉開放註冊。已經繫結的中心暫時離線或列表請求失敗，不應被當作未配置，群組入口和已載入列表仍保留。

「讓 AI 幫我部署」會新建獨立對話，攜帶選定部署目標、監聽地址、公開地址及可用的本機環境資訊。AI 先檢測環境，再通過同一套 CLI 執行部署並驗證；遠端部署需要使用者提供明確目標和已有的可信連線方式，不能預設對當前機器執行遠端方案。密碼、私鑰與配對憑據不應進入部署提示詞。提示詞攜帶獨立部署指南的 GitHub 公網原文及網頁備用連結，要求先讀取文件；預設 IP + HTTP，域名及 HTTPS 可選。AI 須區分系統防火牆與雲安全組，明確使用者需放行的實際 TCP 埠、來源範圍及操作位置；不能操作雲控制台時標記等待使用者處理，之後重新驗證外部可達性。此入口不會自動購買伺服器或完成賬號登入。

`GET /api/device-center/setup` 返回本機部署方案及 CLI `hub status --json` 查詢到的已有安裝、歸屬和健康狀態；讀取失敗不得當作尚未安裝。重新整理或離開頁面後，可恢復實際安裝地址並繼續配對，頁面離開不會撤銷已經提交的系統服務安裝。`POST /api/device-center/setup` 接受 `host`、`port`、`publicUrl` 和顯式 `allowRegistration: true`。安裝請求互斥，重複請求返回 409；校驗失敗返回 400，安裝失敗返回 500。關閉裝置中心執行時會取消並等待安裝子程序退出，避免舊操作繼續釋出成功狀態。

## 使用流程

1. 從裝置中心首次引導連線已有中心，或使用本機一鍵安裝、AI 輔助或下方 CLI 部署自己的中心。可以直接使用 HTTP 與公網 IP；裝置網頁與遠端桌面預設共用 Hub 埠，入口為 `/device/<裝置ID>/`，無需額外開放裝置埠。
2. 啟動各電腦上的 pi-web-ui，在頂欄切換到「裝置中心」應用內標籤頁；介面隨當前主題和語言顯示，不另開瀏覽器頁面。裝置繫結管理預設仍須通過 localhost/127.0.0.1 訪問（`PI_WEB_ALLOW_HOSTS` 裡宣告的域名同樣可用，便於反向代理部署）。舊 `/devices` 地址會轉到主應用的裝置標籤頁。
3. 輸入中心地址與本機名稱，獲取十分鐘有效的配對碼。
4. 在中心登入自己的賬號，輸入配對碼確認。本機頁面輪詢領取裝置憑據，憑據僅儲存在本機資料目錄，不顯示給瀏覽器。
5. 在承載裝置的「裝置中心」建立 Bot，填寫名稱和身份提示詞，通過全域性路徑元件瀏覽固定工作目錄、通過通用模型選擇器選擇模型或繼承本機預設模型。工具、Skill 和 MCP 使用可搜尋的勾選列表；新建 Bot 首次載入目錄時按當前已儲存的工具開關預設勾選，後續重新整理目錄或切換專案不覆蓋手動選擇，編輯已有 Bot 保留其授權；內建工具完整展示，高許可權和平臺不支援的工具僅提示，不按 Bot 專用黑名單隱藏或拒絕，執行授權以 Bot 顯式工具白名單為準（平臺本身的可用性及工具自身校驗仍有效）；切換專案目錄會重新整理該專案的能力目錄，已有但當前不可用的授權保留顯示並可移除。一個裝置可建立多個 Bot。左側「群組」點選 ＋，選擇本賬號的 Bot 建立群組。點選群名複用主對話流聊天；輸入 `@`，搜尋並選擇 Bot 後傳送任務。候選插入含穩定 Bot ID 的明確目標標記，單獨輸入 `@名字` 不會派單。Hub 網站也可建群和聊天。
6. 需要執行任務和接收檔案的電腦，在本機繫結頁顯式啟用執行許可權。預設關閉。該許可權允許智慧體修改檔案、執行命令和應用明確提交的檔案同步請求，仍受本機審批限制。

群成員只有 Bot，裝置僅負責承載、線上連線和執行許可。同一 Bot 可以加入多個群；不同賬號的裝置、Bot 與群隔離。每臺裝置的 pi-web-ui 都可從左側「群組」摺疊區建群、開啟群聊，並通過右鍵重新命名、管理成員或刪除群組；裝置中心標籤頁保留群組管理，實際聊天統一進入現有主對話流。Hub 統一負責賬號、裝置連線、群組與訊息儲存轉發、任務路由和檔案中繼，不要求各裝置使用者另開 Hub 網站操作。Hub 網站保留獨立訪問入口。當前不支援跨賬號邀請或團隊成員管理。

本機使用者操作與 AI 接力使用不同許可權：新配對時分別生成裝置執行憑據和本機互動憑據，後者僅由本機受限 HTTP 介面持有，不下發瀏覽器或模型。本機人類可發起新的任務鏈，AI 憑據仍需可信父任務；舊繫結缺少互動憑據時需重新配對。刪除群組或移除成員遇到相關未結束任務時拒絕，避免丟失執行歸屬。

## 左上角裝置浮層（桌面浮層 / 手機抽屜）

頂欄左上角品牌按鈕（`BrandDeviceMenu`）在有外部繫結時變成裝置入口：桌面是貼著按鈕的浮層，窄屏或粗指標（`(max-width: 640px), (pointer: coarse)`）換成從底部升起的抽屜。兩處共用同一份內容體 `DevicePanel`，只換容器與尺寸令牌。

- **一行一臺裝置 = 一個可點區域**：整行點選直接開啟該裝置（最高頻動作，0 層選單）；行尾常顯 `遠端桌面` 與 `⋯` 兩個動作，`⋯` 只放低頻（設定備註 / 複製裝置 ID）。遠端桌面是第二高頻動作，不進選單——否則就多一次點選。開啟任一裝置後浮層/抽屜立即收起。
- **本機行只做標識**：不渲染整行連結、不渲染 `遠端桌面`（開啟自己是重複視窗，遠端控制自己沒有意義），只留「本機」標籤和 `⋯`（備註 / 複製 ID）。
- **尺寸**：桌面浮層 264px 寬、行 30px、圖示 24px；觸控佈局行 56px、觸控塊 44×44（兩塊之間 1px 分隔線，讀作「分體按鈕」）、行內顯示裝置 ID 次行、隱去 chevron。
- **備註**：桌面在行內就地編輯（`Enter` 儲存、`Esc` 取消、行高不變）；手機是「長按整行」或 `⋯ → 設定備註` 開啟抽屜底部編輯條（`儲存` 一次點完）。
- **手勢**：抽屜在列表滾到頂部時下拉重新整理（0 次點選）、從頂部抓手條下滑關閉、點遮罩關閉；鍵盤 `Esc` 關閉。觸控反饋走 `:active`，不依賴 `:hover`。
- **浮層契約**：`⋯` 選單 portal 到 `body` + `fixed`（否則被 `.dp-scroll` / 浮層的 `overflow` 截斷），層級走 `useOverlayZIndex()`；抽屜容器用疊棧層號，`max-height: 62dvh` + `overscroll-behavior: contain` + `env(safe-area-inset-bottom)`。
- **斷點單源**：`web/src/use-coarse-pointer.ts` 的 `COARSE_POINTER_QUERY` 與 `styles.css` 裡 `.dp-*` 的媒體查詢必須同時改，否則元件與樣式會各走一套佈局。
- **事實源**：`web/src/components/DeviceDirectory.tsx`（取數 / 備註寫回 / 頁面版卡片） · `web/src/components/DevicePanel.tsx`★（浮層與抽屜的內容體） · `web/src/components/BrandDeviceMenu.tsx`（浮層 / 抽屜容器） · `web/src/use-coarse-pointer.ts` · `web/src/styles.css`（`.dp-*`）。單測：`tests/unit/device-panel.test.ts`、`tests/unit/brand-device-menu.test.ts`。

## 部署中心

已安裝 npm 包可直接管理服務；原始碼目錄需要先構建服務端：

```sh
npm run build:server
```

推薦用獨立服務管理命令安裝並配置登入自啟：

```sh
pi-web-ui hub install --host 127.0.0.1 --port 8790 --public-url http://127.0.0.1:8790 --allow-registration
pi-web-ui hub status --json
pi-web-ui hub restart --allow-registration=false
pi-web-ui hub stop
pi-web-ui hub start
pi-web-ui hub uninstall
```

`install` 儲存配置並啟動，`start/stop/restart/status/uninstall` 使用已儲存的配置；`restart --allow-registration=false` 僅變更註冊設定並保留其他配置。`uninstall` 移除自啟動配置，保留賬號、裝置和群組資料。安裝拒絕覆蓋已有或無法確認歸屬的服務；端口占用、許可權不足、健康檢查失敗會明確報錯。安裝中斷後先執行 `status --json` 檢查，再用 `start` 或 `restart` 恢復；不要刪除資料目錄來重試。

Linux 使用 `systemd --user`，macOS 使用 launchd 使用者服務，Windows 使用登入計劃任務。原生服務管理器不可用或許可權不足時，安裝會報告失敗；Linux 在無人登入時開機啟動需管理員為該使用者啟用 linger。CLI 配置中的鎖只有在確認持有程序已退出時才回收，未知或仍存活的持有者不會被覆蓋。

### 公網 HTTPS 自動部署

Linux 公網安裝預設配置可信 HTTPS。將下面的地址換成自己的公網 IPv4 或已解析到伺服器的域名即可；不依賴某臺電腦、固定 IP 或其他應用的配置：

```sh
pi-web-ui hub install --public-url https://YOUR_PUBLIC_IP_OR_DOMAIN --allow-registration
```

Debian/Ubuntu 自動準備 Certbot（至少 5.4），為公網 IPv4 申請 Let's Encrypt 短期證書，為域名申請域名證書，安裝 Node HTTPS/WebSocket 閘道器和每六小時檢查一次的續期計時器。已有匹配的 Certbot 證書會複用，其原有續期鉤子保持不變；閘道器自動載入更新後的證書。管理員許可權僅用於證書、80/443 埠和 systemd 系統服務；Hub 仍使用原來的使用者服務和資料目錄。其他 Linux 發行版需事先安裝 Certbot 5.4+；自動 IPv6 證書部署暫不支援。

公網 TCP 80（證書驗證）和 443（HTTPS）須在雲安全組及防火牆放行。自動安裝器不會搶佔其他應用的埠：若 80/443 已被佔用且沒有可複用證書，應使用現有反向代理並傳 `--https=external`；區域網 HTTP 或除錯部署可傳 `--https=off`。HTTP 的 `--public-url` 在自動部署成功後會轉為同一主機的預設 HTTPS 地址，內部 Hub 埠仍是 8790。HTTPS 校驗失敗會恢復原 Hub 配置，命令不會報告安裝成功。

已有 Hub 更新到支援 HTTPS 的版本後，執行一次 `pi-web-ui hub https`。可用 `--public-url https://YOUR_DOMAIN` 指定新地址。原有 HTTP 地址僅保留已認證裝置連線，瀏覽器入口跳轉 HTTPS；已有賬號、群組和裝置繫結保留。裝置稍後可改用 HTTPS Hub 地址，全部遷移後可關閉舊 HTTP 埠。`PI_DEVICE_HUB_LEGACY_ORIGINS` 是這一相容白名單（最多八個 HTTP origin），不會放寬瀏覽器管理介面的 Origin 校驗。`PI_DEVICE_HUB_HTTPS=off|external` 與對應安裝引數同義。

HTTPS 提供瀏覽器 WebCodecs、剪貼簿等安全上下文；P2P 能否建立仍取決於雙方版本及 NAT/防火牆。HTTPS 本身不會讓中繼自動變成直連。僅解除安裝 Hub 使用者服務不會刪除共享證書或 HTTPS 系統服務；停用整個部署時應同時停用對應的 `pi-device-hub[-名稱]-https.service` 和續期計時器。

不帶子命令的 `pi-web-ui hub` 保留前臺執行方式，可配置以下環境變數；原始碼目錄也可以執行 `node bin/pi-device-hub.mjs`。

| 環境變數                           | 說明                                                                    |
| ---------------------------------- | ----------------------------------------------------------------------- |
| `PI_DEVICE_HUB_PUBLIC_URL`         | 中心的 HTTP 或 HTTPS origin，如 `http://203.0.113.10:50001`，不可含路徑 |
| `PI_DEVICE_HUB_PATH_ACCESS`        | 預設開啟；`0` 恢復舊版獨立域名/埠模式                                   |
| `PI_DEVICE_HUB_DEVICE_DOMAIN`      | 相容舊版獨立裝置域配置；預設通過 Hub 單埠路徑訪問裝置                   |
| `PI_DEVICE_HUB_HOST`               | 預設 `127.0.0.1`                                                        |
| `PI_DEVICE_HUB_PORT`               | 預設 `8790`                                                             |
| `PI_DEVICE_HUB_DATA_DIR`           | 預設 `~/.pi-device-hub`，必須獨立於客戶端資料目錄                       |
| `PI_DEVICE_HUB_ALLOW_REGISTRATION` | `1` 開放註冊，預設關閉；首次建立賬號時開啟，完成後重啟關閉              |

### Hub 線上升級

獨立 Hub 的「一鍵升級」和 `pi-web-ui hub update` 會將 npm 當前 `latest` 包安裝到服務配置目錄下的 `releases/<隨機 ID>/`，再切換服務入口並重啟。安裝、構建檢查失敗時舊服務繼續執行；新版本啟動失敗時恢復 `service.previous` 儲存的舊服務定義並重新啟動。資料目錄、例項 ID、賬號、裝置憑據和群組保持原位。回滾恢復執行程式，不回滾業務資料；釋出的新版本必須保持資料向後相容。確認已有上個受管版本後，成功升級保留當前與上個執行版本，清理更早的受管目錄；無法證明目錄歸屬時保留供人工診斷。

Hub 的首個賬號是部署所有者，只有該賬號可升級或查詢升級任務。網頁 Cookie 操作繼續檢查同源；裝置端人工入口使用獨立 `uiCredential`，通過 `/api/device-user/system/upgrade` 請求，執行憑據不能呼叫系統維護。舊裝置缺少人工憑據時需要重新配對。前臺或內嵌 Hub 不支援自動服務升級，會明確報錯。

升級請求返回 HTTP 202 和持久任務 ID，受理不表示成功。`<Hub 資料目錄>/hub-upgrade.json` 記錄 `queued/running/succeeded/failed`、階段、版本、啟動標識和失敗原因；`hub-upgrade.log` 儲存本次 npm/預檢日誌。頁面按任務 ID 查詢結果，只有目標版本與健康檢查版本一致、例項和註冊配置匹配、啟動標識改變時顯示成功。舊程序仍健康、升級 API 報錯或查詢超時均不算成功。任務和生命週期分別使用跨程序鎖，阻止網頁、命令列同時提交或執行升級。

執行器由獨立服務管理任務啟動：Linux 使用 `systemd-run --user`，macOS 使用 GUI 域中的一次性 launchd 作業，Windows 使用單獨的臨時計劃任務，避免 Hub 停止時結束自己的升級程序。升級任務沿用安裝服務時已驗證的配置位置，並再次核對例項和資料目錄，不依賴後臺程序重新推斷 HOME 或 APPDATA；配置路徑不通過升級 API 公開。Windows 會等待計劃任務及其例項停止，並核對配置監聽地址的 TCP 資源已釋放，再啟動新服務；資源釋放檢查最多等待四分鐘。若截止後端口仍未釋放，或無法核實資源狀態，升級明確失敗，不會終止端口占用者。macOS 會確認舊 launchd 作業已移除，再啟動新服務。Node 旁必須帶有 npm。升級依賴安裝關閉生命週期指令碼及可選依賴，獨立 Hub 不載入 Agent SDK 或本機終端模組。服務安裝時可通過可信環境變數 `PI_DEVICE_HUB_UPDATE_SOURCE` 儲存內網 registry 包標識或本地候選 `.tgz`；HTTP 請求不能指定包來源。`PI_DEVICE_HUB_SERVICE_NAME=pi-device-hub-<名稱>` 可安裝隔離命名例項，預設名稱相容既有部署。

舊公開版本沒有版本化健康資訊時，可以安裝新的全域性 CLI 後執行 `pi-web-ui hub update` 完成首次引導；後續可直接在 Hub 網頁操作。釋出前的真實服務驗證、候選包校驗和與跨平臺矩陣見 [Hub 釋出包升級驗收](hub-upgrade-release-testing.md)。

### 直接使用 HTTP 與公網 IP

```sh
PI_DEVICE_HUB_PUBLIC_URL=http://203.0.113.10:50001 \
PI_DEVICE_HUB_HOST=0.0.0.0 \
PI_DEVICE_HUB_PORT=50001 \
PI_DEVICE_HUB_ALLOW_REGISTRATION=1 \
pi-web-ui hub
```

在安全組開放對應 TCP 埠，然後瀏覽器開啟中心地址，在各裝置中填寫同一地址即可繫結。此模式不需要域名、證書或反向代理，使用 HTTP 和 WebSocket；賬號、裝置憑據、訊息和檔案均為明文傳輸。註冊完成後建議關閉開放註冊。裝置網頁使用同一埠的 `/device/<裝置ID>/` 路徑，不要求額外埠、域名或證書。入口先驗證賬號歸屬或兌換本機互動憑據簽發的一次性票據，再在隔離框架中載入裝置頁面。裝置頁面沒有 Hub 的同源許可權；資源、API 和 WebSocket 都通過繫結裝置的隨機能力路徑訪問。群組欄和裝置選單使用只讀 `/api/device-center/chat-status` 查詢 `hubUrl` 與 `deviceId`；Hub 的能力入口直接提供該最小繫結資訊，並對舊裝置 UI 的 `/status` 查詢返回相同的兩個欄位；本機管理用的 `/status` 及設定介面仍禁止轉發到裝置。通過能力校驗後的策略拒絕、離線等錯誤響應也攜帶沙箱 CORS 頭，便於頁面讀取實際錯誤狀態。

### 單埠路徑與舊版獨立來源相容

預設裝置入口與 Hub 共用埠，例如 `http://203.0.113.10:50001/device/<裝置ID>/`；自定義別名仍指向同一入口。不再按裝置消耗額外埠。裝置頁面由 Hub 強制施加 CSP sandbox，並且不啟用 `allow-same-origin`。隨機能力路徑只允許訪問對應裝置，不能作為 Hub 賬號憑據使用；撤銷裝置會廢止其訪問許可權。隔離頁面的瀏覽器儲存不可用時使用頁面記憶體回退；同一原因導致 `navigator.serviceWorker` 在沙箱內不可讀時降級為 `undefined`，通知改走頁面內 `Notification`，不阻塞首屏。主題選擇（`pi-theme`）通過受限訊息橋儲存在 Hub 入口頁的瀏覽器儲存中，按賬號與裝置隔離，並在首屏渲染前恢復；重新整理、重新開啟或能力憑據輪換不重置主題。訊息橋只接受當前隔離 iframe 的主題讀寫，不能指定其他儲存鍵，也不會持久化裝置頁面的令牌。主題仍屬於當前瀏覽器，不跨瀏覽器或裝置同步；其他本地偏好仍隨頁面重新整理重置。舊版 Hub 未提供該橋時，頁面等待至多 500ms 後繼續啟動。

中心域與裝置域不得互為父子域，例如使用 `console.example.com` 與 `devices.example.net`。配置裝置域的通配 DNS、通配證書，將兩個域名的 HTTP 與 WebSocket 流量均轉發至同一中心埠，並保留原始 Host、Origin。代理不應緩衝 SSE。可使用 HTTP 或 HTTPS；HTTPS 提供傳輸加密，HTTP 頁面會顯示明文傳輸提示。

群組選單提供「清空訊息」：確認後刪除該群全部訊息、歷史任務和訊息回執，保留群組名稱與 Bot 成員，且無法撤銷。存在排隊、執行或停止中的任務時會拒絕清空，需等待任務結束。操作按賬號校驗，在 Hub 中原子持久化；本機群組與已繫結裝置使用同一介面規則。

## Bot 身份與執行邊界

Bot 的穩定 ID 與承載裝置分離。群使用 `botIds`，可選 `primaryBotId` 必須指向群成員；建立群組及管理成員時可選擇或清除主 Bot。未指定目標的人類訊息交給主 Bot，並續接它最近未關閉且配置有效的群會話；顯式目標及繼續會話優先。Bot 公開訊息不會觸發預設派發；移除主 Bot 或撤銷其裝置時清除設定，不自動選替代者。未設定主 Bot 時保持原有 @ 派發行為。派發上下文凍結當時的主 Bot ID，執行器只對同群且自身身份匹配的主 Bot 注入協調職責：普通問答直接回應，使用者要求執行的工作可查詢成員能力並委派，後續補充先查詢持久會話再繼續明確匹配的任務，多義時詢問使用者。協調身份不擴張工具或審批許可權，不根據歷史訊息自行派單；委派結果複用現有相關請求回覆和自動繼續機制，狀態完成仍須核對交付證據。訊息使用 `targetBotIds`，任務記錄目標 `botId`、內部路由 `deviceId` 與配置版本。裝置認證同步只能更新自身 Bot，群訊息與任務回報校驗 Bot 歸屬。Hub 儲存使用新版結構，不遷移舊裝置成員群資料。

每個群任務在派發前捕獲同一份共享上下文：群名、Bot 成員和按時間排序的近期公開訊息，JSON 總預算 24 KiB。當前任務正文單獨傳入，其他成員的歷史回覆是參考資料而非指令或派發授權；同批目標的上下文在任何成員執行前凍結。普通聊天上下文只隨任務傳輸；顯式契約任務將實際輸入封存為不可變 ContextManifest 並持久化到任務記錄。成員的內部思考和本機工具輸出不會進入群歷史。繼續會話保留原執行上下文，當前仍附帶一份最新的有界群訊息快照，尚未對群訊息做跨輪增量去重。

獲得 `device_collab` 授權的成員可用 `read_history`（`roomId`、自身 `sourceBotId`、可選 `before` 游標）讀取更早的原文，不會喚醒其他成員。每頁 JSON 上限 24 KiB，超長訊息按 `textStart` / `textEnd` 分段，沿 `nextBefore` 可繼續向前獲取完整文本；游標使用穩定訊息 ID，追加不打亂翻頁，清空或訊息淘汰後舊遊標明確失效。Hub 再次驗證賬號、裝置、啟用狀態和群成員身份。每群最多保留 500 條公開訊息，超出保留範圍的內容不可回查；不承諾無限歷史，也不額外呼叫模型生成可能丟失事實的摘要。工具未授權時仍會帶入近期上下文，但無法回查更早內容。

群輸入框通過 `@` 選單統一選擇目標：每個 Bot 提供「新對話」和帶名稱的「繼續對話」入口，輸入框保留選擇的含義，不再單獨展示任務目標下拉框。提及引用繫結穩定 Bot/會話 ID，傳送前轉換為 Bot 標記並路由至所選會話；修改或刪除提及會清除其引用。單條訊息繼續一個已有會話，混入其他新建或繼續目標會拒絕傳送；新對話仍支援同時 @ 多個 Bot。列表更新失敗僅在 @ 選單中提示，並阻止繼續舊會話。所選會話被刪除、關閉或配置失效時會明確報錯，不會悄悄改成新任務。\n\n普通聊天任務支援新建與繼續：新任務建立共享的標準持久會話（`independent: false`）；繼續會話通過 Hub 穩定會話 ID 恢復該 Bot 的原轉錄，工作目錄和身份取自 Bot 的啟動配置；未指定模型時捕獲本機 pi 預設模型，不繼承介面當前會話模型；工具、Skill 與 MCP 採用顯式白名單並在執行入口應用。MCP 使用任務專屬 Bridge，只啟動白名單服務，其工具還須匹配工具白名單。Skill 不授予額外工具許可權。工作目錄是預設操作位置，嚴格限制目錄外訪問仍需沙盒隔離。裝置執行許可及審批保持上層約束。同裝置最多併發執行 4 個任務，最多 32 個等待任務；同 Bot 或真實路徑重疊的工作區保持序列，排程按排隊順序選擇當前可執行項，獨立工作區可越過沖突等待項。目錄別名通過 realpath 統一，停止未確認的 Bot/目錄仍保持隔離；等待取消立即釋放佇列位置，超出容量明確拒絕。繼續訊息不會中斷正在執行的工具，而是在前一輪結束後恢復同一轉錄執行。Bot 對話可在本機直接檢視和處理互動，無需過戶；檢視不遷移執行歸屬，不影響群任務執行。Bot 轉錄仍禁止由普通曆史恢復入口建立另一執行例項；恢復只允許裝置本機持久登記的精確路徑，且校驗 Hub、裝置、群、Bot 配置版本與工作目錄。憑據輪換不改變會話身份，目錄或 Bot 版本變化則拒絕繼續，不靜默新建。轉錄在執行失敗後仍可保留供恢復和本機檢查。

會話容量按「未停止會話」計數：已停止會話進入有界歸檔（每群普通歸檔保留 200 條，無契約/交付/審查/整合記錄的可淘汰），歸檔不佔用新建會話名額；`POST /api/rooms/:id/conversations/:conversationId/delete` 僅允許無在途任務、無契約/交付/審查/整合記錄的會話，用於釋放容量，禁止用清空群組代替。撤銷承載 Bot 的裝置會關閉其會話並標記 `closedReason=device_revoked`；Bot 版本、裝置或成員變化後會話以 `stale` 返回，介面禁止繼續並提示新建。群訊息支援 `replyToMessageId`（必須指向同群訊息）作為回覆錨點，並隨群上下文與 `read_history` 投影給 Bot。人類訊息未顯式給出 `targetBotIds` 時由 Hub 解析正文 `@Name` / `@Name(<id>)`：同名多成員不猜、非成員不派發，正文提及不再因客戶端未解析而靜默回落到主 Bot。冪等收據與訊息保留解耦（每群 2000 條、7 天），訊息淘汰不再削弱重放保護。

顯式程式碼交付通過現有任務建立 API 或 `device_collab` 提交 `executionMode: "code"` 與版本化契約；介面普通訊息仍為聊天模式。程式碼每輪新建隔離執行會話，以固定倉庫基線及封存 Manifest 執行，確認停止後捕獲攜帶補丁與 Git Tree 的不可變產物；執行結束與產物生成分開記錄，不自動構成驗證或接受。契約任務及其會話額外保留到顯式清空或刪除群，防止歷史裁剪重寫版本權威。產物可通過 `task_evidence evidenceKind=artifact` 按摘要和位元組範圍讀取。請求預算、許可權和當前限制見 [版本化契約與程式碼任務](device-collaboration.md#21-版本化契約與程式碼任務)。

Hub 狀態分兩層持久化：`device-hub.json` 仍是唯一的**索引**（`version: 2`，同一 schema，賬號/裝置/Bot/群/會話/交付/收據都在其中，`messages`、`tasks`、`conversationMessages` 固定為空陣列），大集合落入 `hub-log/` 下的追加日誌：`hub-log/messages/<roomId>.jsonl`、`hub-log/tasks/<roomId>.jsonl`、`hub-log/conversation-messages/<conversationId>.jsonl`。每行是 `{"v":1,"op":"upsert","value":…}` 或 `{"v":1,"op":"del","ids":[…]}`；協同事務以 `hub-wal.jsonl` 為單一提交點：將索引與三個集合的增刪差量、遞增序號和校驗和寫入並 fsync 後才確認提交；日誌與索引隨後作為可恢復投影更新，索引最後儲存 `checkpointSeq`。投影失敗仍保留已經提交的記憶體狀態與 WAL，下一筆寫入或重啟重放後再補 checkpoint，不能用相同序號覆蓋舊事務或返回普通提交失敗。只有投影完成才清理 WAL。刪除以墓碑追加，墓碑數達到 200 或行數超過保留上限兩倍時按存活行重寫檔案（臨時檔案 + fsync + rename）；載入時按群保留 500 條普通曆史，額外保留未結任務與契約證據，並修復崩潰留下的半行（截斷到最後一個換行）。舊版本內聯的 `messages`/`tasks`/`conversationMessages` 在 `open()` 時先寫入日誌再清空索引（可重跑、不丟行）；`readPersistedHub(dataDir)` 供工具與測試在不觸發中斷標記、不建立目錄或修寫檔案的前提下，在記憶體重放 WAL 並重建完整狀態。**相容邊界**：索引 schema 與舊資料檔案均可載入，但舊版 Hub 直接讀 `device-hub.json` 只能看到空集合，回退舊版本前必須先匯出完整狀態。

裝置排程器的房間公平歷史（最近派發時間與次數）持久化在資料目錄 `task-scheduler-state.json`，250ms 防抖 + 原子寫入，重啟後恢復；狀態損壞或缺失時按中性公平性啟動，不阻塞派發。

「停止所選會話」先持久關閉新訊息准入，再請求裝置取消該會話的執行和排隊輪次；僅收到停止確認才算成功。確認缺失時顯示待確認，並繼續阻止群清空/刪除，失敗或斷線事件不能替代停止確認。停止僅作用於所選會話，不自動停止它已派發的其他成員任務；已關閉的發起會話不會被子任務結果再次喚醒。使用者可停止同賬號群會話，Bot 只可停止自身會話。\n\n## 群任務進度與人機互動

群聊通過賬號與群繫結的 SSE 接收任務進度，執行器只上報受限的助手正文片段、階段和工具名稱；內部思考、工具引數與原始工具結果不會進入公開進度。Hub 校驗 Bot、任務、attempt 與遞增序號，進度僅儲存在記憶體，持久任務狀態在事務成功後通知重新整理。正常連線時停用固定輪詢，連線失敗回退，重連重新獲取權威狀態。隱藏頁面和切換群組關閉舊連線，慢消費者斷開後重新同步。

原生 `ask_user_question` 與工具審批通過獨立互動橋展示在群內；回覆綁定當前任務與 attempt，審批僅支援本次批准或拒絕，不允許遠端修改持久授權規則。群專屬 `conversation_attention` 可在當前任務仍執行時接收人類回答；回答先持久儲存，後續輪次等待原執行結束再進入同一會話，避免併發寫入轉錄。

執行超時使用 20 分鐘無實際活動視窗，人工等待期間暫停。真實模型輸出和工具活動續約；狀態查詢與網路心跳不代表執行進展。網路斷開保留已獲租約的本機執行，重連後用 task/attempt/lease 認領，舊代次或已撤銷許可權不能恢復。Hub 重啟提供有界認領視窗；裝置程序重啟不能證明舊執行仍在時，記錄中斷並要求顯式繼續，不自動重放副作用。活躍租約與終態結果統一寫本機 `task-recovery-state.json`，在同一次原子替換中儲存結果並移除租約；舊的兩個恢復檔案在遷移成功後清理。Hub 按 attempt 與租約代次接納不可變結果，ACK 必須攜帶已提交的匹配摘要後才清除裝置 outbox；永久終態衝突或已失效 attempt 使用繫結原結果的拒收回執，將完整結果原子移入持久隔離區而不重連迴圈。恢復狀態寫入 version 2（相容讀取 version 1），隔離區最多 128 條 / 2 MiB，總檔案上限 8 MiB，遷移與回退見 [`device-collaboration.md`](device-collaboration.md#21-版本化契約與程式碼任務)；完整報告另有獨立 outbox，終態確認不會誤刪尚未上傳的報告。舊版不能讀取新的統一恢復檔案，回退前須備份並轉換恢復狀態，不能直接刪除新檔案。

訊息內報告仍保持 16 KiB 摘錄預算，完整原文在執行裝置持久儲存並分塊上傳 Hub，每報告上限 4 MiB，超限明確標記 rejected；裝置報告 outbox 總預算 64 MiB、最多 128 條，並清理已確認的有限歷史。任務詳情與 `task_evidence` 按分片、完整雜湊和版本讀取，上傳未完成、缺失或拒絕不冒充完整報告。上下文摘要保留約束來源、決策和證據引用，截斷處明確提示查詢完整記錄。

## Bot 執行上下文與提示詞分層

群任務的固定執行規則由本機執行能力繫結，作為 SDK 會話系統指令提供；主 Bot 協調職責取自當前派發時凍結的成員身份，不從歷史訊息恢復許可權。Bot 自定義身份指令和執行規則在預設提示詞、組合模板與恢復會話路徑保持有效。每輪使用者訊息只攜帶任務資料與本機測量資訊，不再追加完整的固定規則。系統層仍會隨底層模型請求提供必要上下文；這項調整消除的是轉錄中的重複規則，不承諾供應商的 token 計費或快取命中率。

`device_collab` 從當前 SDK 會話自動繫結來源 Bot、群和父任務；顯式引數與繫結衝突時拒絕。`current_task` 可查詢當前關聯資訊；`conversation_attention` 與 `conversation_deliver` 可省略自身會話 ID。接收 `kind=request` 的執行輪次使用 `reply_to_request` 回覆，服務端從當前請求繫結回覆目標與請求 ID，不能借此選擇其他目的地。普通本機對話沒有這些預設繫結，仍需提供原介面所需欄位並通過原有授權校驗。繼續其他工作會話仍須明確目標，避免將任務關聯誤認為派發授權。

群歷史通過獨立的 `device-group-context` 自定義訊息提供，首次為有界快照，繼續會話時為增量。投遞發生在 SDK 自動壓縮之後，以活動分支的實際上下文為依據：只省略仍可見且內容、傳送者、文本範圍完全相同的片段；編輯或範圍變化的片段會重新提供。歷史銜接點不可見時回退到當前有界快照並標記 `gap=true`。自定義訊息隨 SDK 轉錄持久化，恢復會話後重新計算覆蓋範圍，不依賴“已經發送”的程序內游標；被壓縮或上下文編輯移除的原文可再次提供。普通訊息、工具輸出及壓縮摘要中的相似標記不能作為去重證據。每次模型請求還會根據最終請求上下文複核覆蓋範圍；如果執行過程中再次壓縮，臨時補回缺失片段，避免增量引用已被移除的原文。臨時補全不冒充已持久化的投遞記錄。當前任務正文始終完整保留。

Hub 在每次原子事務提交前，統一從現有任務、訊息、等待決策和交付記錄投影結構化任務狀態與事件。狀態保留本會話初始目標、當前執行階段、待回答問題、最近結果、人工決策證據與交付引用；追問和工作 Bot 結果不會覆蓋初始目標。事件記錄有序遞增的 sequence，最多保留 100 條且總計不超過 64 KiB；這是當前快照加有限事件視窗，不承諾從序號零完整回放。舊資料建立無虛構歷史事件的初始快照，重啟後的中斷按真實轉換記錄。

`device_collab task_state` 讀取當前狀態和保留事件；`task_update` 只能由本會話當前執行中的 Bot 上報進度、約束、阻塞和下一步，需提供 `expectedRevision`，版本衝突後重新讀取。上報帶有 `bot_reported` 來源，不能改變服務端目標、執行階段或人工決策。派發攜帶任務狀態快照，`current_task` 返回的也是派發時觀察值；查詢即時狀態使用 `task_state`。這些讀取不會自動派發或重試任務。

派發給模型的任務狀態參考快照預設使用 12 KiB UTF-8 JSON 預算，包含選擇後設資料本身；初始目標、當前任務、階段和待回答問題保留，人工決策優先於 Bot 上報和歷史結果。可選記錄按完整條目選擇，不截斷當前使用者任務或 handoff。省略數量與已存在的證據截斷標記顯式提供；依賴被省略的約束或決策前需讀取 `task_state`。極小預算裝不下必要狀態時保留必要欄位並標記 overflow，不聲稱預算滿足。群歷史繼續使用獨立的 24 KiB 有界快照及增量機制，此預算不是完整供應商請求的 token 上限。

固定執行規則僅保留許可權、工作區、歷史信任和結果投遞等長期原則。`device_collab execution_guide` 按 `coordination`、`delivery`、`review` 讀取本機固定流程；首次委派或請求交付、評審前按需載入。工具許可權仍由原有白名單和服務端校驗，尚未按階段動態隱藏或啟用工具。

`device_collab context_metrics` 讀取當前繫結 SDK 會話的上下文計數。指標區分來源歷史文本、新增文本、去重文本、注入 JSON 與臨時修復位元組數；位元組均為 UTF-8，不等同 token、快取命中或計費。自定義訊息 details 儲存對應計數，模型正文不包含診斷後設資料。程序內取樣最多 50 個會話、每會話最近 100 條，工具返回最近 10 條及保留視窗計數；重啟和淘汰會丟失取樣，不影響任務或投遞依據。

本階段尚未實現模型生成的任務摘要、按階段切換工具或供應商成本與快取統計。去重、身份校驗與請求關聯由服務端負責，群訊息正文及其他 Bot 產出繼續作為不可信參考資料處理。

## Windows → Mac → Linux 接力

群訊息支援明確目標、任務狀態和結果報告。任務卡的接力入口可以把倉庫、提交、分支、待驗證項帶給下一臺裝置。建議先生成 Git 提交，再讓對應平臺核對提交併執行真實構建與測試。

執行器為新任務建立共享、持久的標準本機對話，繼續任務恢復原 Bot 會話，不切換使用者正在使用的對話。普通新建對話預設獨立（`independent: true`），跨頁面開啟保留原有過戶流程；群組和微信、QQ 等渠道建立的會話預設共享，直接檢視且保持原執行歸屬。它通過本機現有 WebSocket 協議呼叫智慧體，不會自動批准許可權，也不會替使用者回答問題；問卷和審批進入現有全域性彈窗，任務保持等待，人工等待期間暫停執行超時計時，回答後繼續。結果包含本機系統、會話標識與實際助手報告。測試通過與否仍以命令證據為準。

AI 可呼叫 `device_collab` 列 Bot、列群。獲得工具授權的 Bot 執行會話還可發訊息、向指定 Bot 派單和傳檔案。持久協作通過 `conversation_create` / `conversation_list` / `conversation_read` / `conversation_send` 操作；會話建立時儲存不可變的 `sourceBotId`、`sourceConversationId` 和 `parentTaskId` 委派來源，列表和工具投影保留這些欄位，後續繼續不改寫原始歸屬。新建與繼續均支援 `kind: request` / `requestId`，新建不允許 `reply`；`kind: request` 產生相關請求，接收者用 `kind: reply`、原 `requestId` 和請求中的 `sourceConversationId` 回覆原會話，不能僅憑 Bot 名字猜測目標。Hub 持久化訊息和執行輪次後再派發；子任務的終態報告可建立一輪原發起會話的繼續任務，重複報告不會重複喚醒，回覆或結果不會自動形成互相喚醒迴圈。所有寫操作明確指定本機 `sourceBotId`，任務和檔案另指定 `targetBotId`；普通會話不能按相同工作目錄冒用 Bot，執行會話不能冒用其他 Bot。裝置派單需要可信的當前父任務，上下文由執行器注入；同一根任務最多累計派發 16 個任務，接力深度最多 8。當前允許執行中的父任務主動派出下一任務，因此接力可能並行；結果回傳喚醒也計入同一自動接力預算。新的人工輸入可為原會話開啟新的有限任務鏈，Bot 自己的繼續訊息不能重新整理預算。沒有正在接收的群任務時，本地 AI 不能憑空偽造父任務發起機器人任務鏈；可由使用者先在群裡 @ 發起。

### 開發交付與驗收

群組對話的執行狀態與開發交付分開記錄：執行 `completed` 只表示本輪結束，不代表程式碼已交付或驗收通過。Bot 使用 `device_collab conversation_deliver` 向自己的穩定對話追加交付記錄：舊提交方式提供倉庫、基線與完整提交 SHA；程式碼產物方式由當前執行任務用 `artifactTaskId` 引用同一作者先前完成的產物，Hub 派生契約、Manifest、樹身份和驗收條件，不能把樹 SHA 當提交。檢查來源固定為 `bot_reported`，不會據此執行命令或生成驗證憑證。普通討論仍可直接回復，無需交付記錄。

人類可在摺疊交付面板按確切版本驗收，其他 Bot 使用 `conversation_review` 提交 `accepted` 或 `changes_requested`，不能自審。提交方式繫結同一提交 SHA；產物驗收必須先有真實成功的 Integration 驗證，並繫結 artifactDigest、integrationId、verificationDigest，按封存 acceptanceCriteria 逐項記錄結果與證據。舊版本、另一產物或兩個缺失的 commit 不能匹配當前交付。返工沿原群組會話繼續，保留歷史；驗收本身不自動派發返工或執行 Git 合併。

協議定義位於 `server/protocol.ts`；Hub 在事務內驗證賬號、群成員、Bot 和執行任務歸屬，並先持久化再返回。事務回撥保持同步，外部 RPC 在事務外執行；返回資料在 WAL 提交前驗證可克隆性並生成獨立副本，函式等不可分離結果不會造成“已經提交卻返回失敗”，非同步期間的外部別名也不能改寫返回事實。交付與審查按冪等鍵去重，相同鍵不同內容拒絕；歷史有容量預算，滿後明確拒絕追加。HTTP 入口為 `POST /rooms/:id/conversations/:conversationId/deliveries` 與 `/reviews`，沿用本機代理、Agent 及跨裝置賬號邊界。

完整開發迴歸：`node tests/device-project-collaboration-test.mjs`（或通過冒煙跑器）。測試啟動獨立 Hub 與兩個獨立裝置服務，使用真實 Git 倉庫和本地確定性模型，覆蓋交付、跨裝置拉取、失敗返工、再次驗收與整合檢查。同機雙服務驗證裝置間協議和流程，不替代 Windows/macOS 實機適配驗收。

繼續 Bot 轉錄前，服務端會等待已確認停止且已釋放註冊的舊執行例項完成清理，即使舊 WebSocket 的關閉事件還未到達。仍註冊或仍執行的持有者不會被搶佔，恢復將明確失敗；恢復階段的警告同樣結束本次任務，避免群組永久顯示執行中。真實鏈路迴歸執行 `node --import tsx tests/device-bot-live-integration-test.mjs`（先構建服務端）：獨立埠和臨時資料目錄啟動 Hub、裝置服務及本地 HTTP 模型，驗證三輪不同訊息進入同一個轉錄，並檢查後續 SDK 請求攜帶前文。

新會話的 SDK 轉錄路徑可能先於檔案分配：執行態在歸屬校驗後先原子登記路徑，允許第一條訊息隨後建立檔案，並在任務成功結束前驗證檔案存在。首輪失敗後保留登記以便恢復；繼續會話仍須驗證已登記檔案存在，不會通過建立空檔案偽造可恢復轉錄。

網路閃斷與程序崩潰分開處理：聯結器退避重連時保留原本機執行與衝突鎖，獲得當前任務租約認領確認後恢復進度和結果回報；Hub 不因網路關閉直接終結持有租約的任務。Hub 重啟允許原持有者在恢復視窗內認領；超時後統一結算中斷、父結果通知與會話排隊。裝置程序重啟發現孤兒租約只補報中斷，不盲目重跑；使用者可顯式繼續已登記的轉錄。撤銷裝置或明確停止會取消任務，停止未確認仍保持隔離。該協議避免測試覆蓋的重連重複執行，不承諾所有崩潰時刻的全域性恰好一次副作用。

## 群內原生問卷與一次性工具審批

`human-interaction.ts` 將當前 executor 連線的原生問卷與工具審批對映為短期隨機互動 ID；原生請求 ID 留在執行裝置。投影繫結任務、attempt、群、Bot 和裝置，Hub 再以持久任務校驗賬號與群成員。每任務最多 8 項、24 KiB，回答最多 16 KiB，Hub 最多保留 128 個任務的記憶體投影，不持久化。每執行最多消費 256 項，達到上限後繼續在執行裝置本地處理。

群端 `GET/POST /api/rooms/:id/interactions` 僅接受人類使用者會話（含經過既有 device-user 認證的本機 UI）；Bot 憑據不可回答。問卷支援選項、自由文本、依賴題和取消；審批僅支援批准本次或拒絕，引數和原因原文保留在執行裝置，群內提示先檢查原生請求。任何答案都不能攜帶任意 WS 幀、編輯工具引數、修改信任或記憶允許規則。executor 根據當前本地會話與待答項重新驗證後，只能傳送 `question_answer` 或 `tool_approval_response`（`scope: once`）。本機橋消費待答請求後，按當前 Bot 執行能力登記完整答覆幀；WebSocket 控制閘門只放行這一幀並立即消費授權，拒絕跨任務、不同請求 ID、篡改答案及擴大審批範圍，能力撤銷時清除未消費授權。

Hub 等待綁定當前裝置 WS 的 executor ACK 才移除互動；拒絕或 5 秒未確認返回 409，並保留待答項。撤回、超時、任務結束或連線失效後不能重放回答。介面隨群 SSE invalidate 重新整理，連線失敗時退回可見頁面的 2 秒輪詢；切群與停用取消未完成的回答請求。原生 WS 寫入後的最終工具執行結果仍由任務狀態報告，不以 HTTP 轉發成功替代。

迴歸：`tests/unit/device-center-human-interaction.test.ts`、`device-center-human-interaction-e2e.test.ts` 覆蓋橋邊界及真實 Hub 使用者代理、relay、connector 問卷與審批迴路。

## 排程、任務詳情與群工作區

裝置中心提供執行排程設定：併發預設 4（1–16），等待預設 32（0–128，0 表示不排隊）。設定先原子儲存再應用；非法或損壞的設定不會靜默擴大資源上限。排程在同 Bot 與真實重疊工作區序列約束下按群公平選擇，等待過久的可執行任務優先。佇列顯示位置和受控阻塞原因，取消繫結 task 與 attempt，停止未確認繼續佔用隔離槽。

群任務條可開啟詳情，檢視持久事件、工具開始/結束狀態、報告、互動和交付引用。事件採用有界非同步分段日誌，最多 20 段，每段約 50 條/64 KiB；淘汰、損壞、寫入失敗和過期游標明確反饋。工具引數僅公開結構化操作摘要，內部思考與敏感引數不進入公開事件。日誌和報告讀取嚴格校驗賬號、群、任務與執行代次。

群輸入框支援只規劃。計劃任務只允許已授權工具的只讀動作，未知工具與寫入/派發動作硬拒絕；真實計劃步驟持久就緒後，由人類點選「開始實施」建立後續執行輪次，Bot 不能自批。群工作區可綁定當前裝置的已有畫布，引用本身不啟動；顯式啟動複用原畫布服務並校驗 graphId 與 cwd。Bot 預設讀取真實本機配置，按白名單欄位和 revision 部分儲存；未攜帶的許可權不清空，在途 Bot 使用權阻止熱修改。群擴充套件插槽走宿主註冊與渲染；搜尋明確覆蓋群名、Bot 和任務標題/ID，不宣稱全文日誌索引。

## 交付驗證與整合流水線

提交交付沿用「先審查再準備」：產物可先準備並真實驗證，之後再獨立驗收；`completed` 不代表驗收通過。人類選擇目標 Bot 與分支、檢視隔離工作樹差異，驗證命令由賬號所有者首次明確提交併凍結，最終確認必須已有真實成功憑證，且目標分支在所有工作樹中均未檢出。釋出前 Hub 先持久儲存 `publishIntent`，裝置釋出日誌在 CAS 前落盤、成功回執在清理會話前儲存；啟動與重連只回查，不自動重發 CAS。

**完整硬約束以 [`device-collaboration.md`](device-collaboration.md) 的 §2.1～§2.3 與 §8 為唯一事實源**（WAL 事務、契約 / Manifest、憑證白名單、CAS 回查、隔離工作樹邊界、交付 ≠ 驗收），特別是 [`§2.3 釋出意圖與崩潰後回查`](device-collaboration.md#23-釋出意圖與崩潰後回查)。本文只保留本機落盤佈局、容量 / 預算上限與相容邊界這類操作細節。歷史遺留的機制描述（任務執行與恢復、交付與審查等節）尚未完全遷出，屬已知文案債：**機制變更只改 `device-collaboration.md`，不要在這裡補定義**（債項登記見 [`agent-bot-design.md`](agent-bot-design.md#15-實現狀態首批落地)）。

## 大檔案分塊傳輸

小包同步之外，新增確定性使用者傳輸入口及分塊引擎：每傳輸最多 256 MiB、2048 檔案，接收端總暫存預算 512 MiB。清單固定檔案雜湊、大小與分塊佈局，分塊在寫入前校驗序號、偏移、位元組數和雜湊；重複塊僅允許完全相同內容，損壞塊可重傳。原始檔版本不符必須拒絕，不能將舊清單與新內容混合。

群內可選擇源/目標 Bot 和路徑直接啟動傳輸，不依賴模型理解自然語言。Hub 後臺任務有界、持久化並顯示進度、差異和錯誤；斷線後顯式恢復同一清單，接收器與 Hub 登記重建後繼續已確認塊。暫存目錄繫結 Hub、裝置、群、Bot、revision 和真實工作區，關閉服務保留未完成暫存，改根或換 Bot 不能複用舊包。

匯入仍須預覽並按 revision 確認，衝突路徑逐項明確覆蓋，不刪除目標檔案。取消先停止傳送及目標在途操作，等待實際 I/O 收尾和雙端 fence 確認後才釋放額度；停止未確認期間阻止繼續、匯入及衝突任務。連結/聯接、敏感路徑和忽略項沿用共享路徑規則。`sync_files` 複用分塊鏈路，工具回執僅保留有界摘要。

## AI 檔案同步

`device_collab` 的檔案流程：

1. `sync_files`：指定群、本機來源 Bot、目標 Bot、相對專案路徑；`recursive: true` 可遞迴選擇目錄。傳送端校驗檔案並製作 SHA-256 清單，中心轉發，目標暫存，返回 transferId 與差異預覽。遞迴發現的忽略或敏感路徑會跳過並通過 `exclusions` / `totalExcluded` 報告，顯式選擇這些路徑則拒絕。
2. `transfer_preview`：重新獲取目標現狀與 revision。
3. `transfer_apply`：攜帶確認的 revision；已有不同檔案預設拒絕，必須通過 overwritePaths 顯式指定覆蓋。

傳輸與任務使用目標 Bot 的固定專案根，不再維護群級裝置目錄繫結。Bot 配置按 Hub 地址與裝置身份隔離並原子持久化；完整提示詞、模型與能力配置、絕對路徑保留在本機，Hub 只同步公開身份與配置版本。任務或檔案操作持有 Bot 使用權期間拒絕修改或刪除；暫存檔案繫結 Bot 和工作區版本，切換後不能把舊檔案包匯入新目錄。其他 cwd 的對話不能借用該 Bot 的專案許可權。拒絕路徑穿越、軟連結/目錄聯接、`.git`、`.env*`、常見憑據路徑與 `node_modules`；目錄遞迴須顯式啟用，掃描最多 4096 個條目；不會刪除目標檔案。單包最多 8 MiB、128 個檔案，目標暫存總預算 32 MiB。資料目錄必須位於專案根之外。

覆蓋前重新核對目標基線，預覽之後發生修改時拒絕寫入。多檔案匯入不是跨檔案事務，會返回實際 applied、unchanged、rejected；失敗不自動重試已進入應用階段的傳輸。暫存檔案生命週期繫結本機服務，重新連線或重啟後可能失效，請重新發送。同步不自動執行指令碼、安裝依賴或重啟服務。

該傳輸提供類似 SFTP 的按需檔案/目錄傳遞，但使用現有裝置連線，無需配置 SSH/SFTP；不是持續目錄映象或刪除同步。詳見 [檔案傳遞邊界](device-file-sync.md)。本輪適合原始碼和小型測試素材，大型構建產物建議使用 Git LFS 或專用製品儲存。Git 倉庫傳遞和檔案包同步不會把其他機器的絕對路徑直接用於本機。

## 無域名裝置網頁入口

預設只開放 Hub 主埠即可。每臺裝置卡都有固定入口 `/device/<裝置ID>/`；可選別名（例如 `mac`、`office`、`linux`）仍先校驗登入與裝置歸屬，再進入相同單埠訪問鏈路，連結可帶 `#s=對話ID`。路徑模式不消耗裝置埠池，即使舊部署仍設定 `PI_DEVICE_HUB_PORTAL_PORTS`，也不會監聽這些額外埠；已有別名和埠記錄保留。

需要恢復舊版獨立來源時，設定 `PI_DEVICE_HUB_PATH_ACCESS=0`，再配置 `PI_DEVICE_HUB_PORTAL_PORTS=50002,50003,50004,50005` 或裝置域名。舊埠模式要求開放併成功監聽埠池中所有埠。無埠的路徑分配記錄切回舊模式時會按需分配埠，不重用其他裝置的歷史埠。

## 區域網優先訪問

從本機 pi-web-ui 的裝置卡選擇「開啟裝置」或「遠端桌面」時，兩者共用區域網優先協商。Hub 先校驗賬號與裝置歸屬，再通過已認證聯結器的 `device_lan` RPC 簽發短期裝置通道授權。被訪問裝置按需監聽一個隨機 TCP 埠，釋出最多 16 個 RFC1918 IPv4 候選地址；本機服務並行執行有總時限的真實 TLS 握手及健康請求，選擇首個通過身份驗證的地址。是否直連以實際可達和金鑰驗證為準，不按 IP 文本字首或同網段猜測。

直連成功後，頁面資源、對話 WebSocket、上傳和桌面 JPEG/輸入均經區域網傳輸，不再繞 Hub，也不經中繼 JSON/base64 分片。Hub 仍負責授權。通道使用 TLS 1.2 PSK 與每次授權的 32 位元組隨機金鑰，金鑰只存在於 Hub 和兩端服務程序，不傳給瀏覽器。隨機監聽埠僅接受有效 PSK，並複用聯結器的路徑白名單、本機 Host/Origin 重寫和憑據注入；本機配置與系統許可權申請介面仍不能從遠端訪問。無需把主 Web 服務改為區域網監聽。

瀏覽器開啟的是本機 `/device-lan/<裝置ID>/__open` 一次性票據包裝頁，遠端內容仍處於不含 `allow-same-origin` 的沙箱，通過隨機能力路徑載入；複用 Hub 路徑入口的 HTML 重寫、CORS、CSP 和頭部淨化，支援本機反代路徑字首。授權到期按需續簽，聯結器斷開或解除繫結時撤銷相關通道和連線；取消單次授權只撤銷該次金鑰，不影響其他連線。瀏覽器獨立標籤頁與 Electron 獨立視窗也使用相同選擇邏輯。

沒有可達私網地址或埠受阻時，嘗試下述 P2P；對端不支援或打洞失敗時使用原 Hub 票據。已開啟頁面斷線後先重新協商區域網，仍不可達則嘗試 P2P，失敗才申請新 Hub 票據並回退。以上 TLS 探測由已配對的本機服務發起；未安裝本機服務的瀏覽器使用下述獨立 WebRTC 通道。事實源為 `server/device-center/device-lan.ts`（裝置加密通道與並行探測）、`device-lan-access.ts`（本機隔離入口）和 `web/src/device-access.ts`（統一開啟入口）。

## P2P 裝置訪問

本機服務在區域網探測失敗後，自動嘗試裝置間 WebRTC P2P，失敗再使用 Hub 中繼。群成員的「開啟裝置」和「遠端桌面」共用該流程。這條原生路徑要求兩端執行 pi-web-ui；純瀏覽器路徑見下節。群組持久記錄、排序、審批、任務租約與裝置授權繼續由 Hub 管理。

Hub 通過已認證的 `device_lan` RPC 協商能力（相容舊響應），通過 `device_p2p` RPC 定向轉發有界 SDP。原生協商仍只接受現有人工裝置憑據，驗證賬號與裝置歸屬，不接受普通瀏覽器 Cookie。每次會話擁有獨立 ICE/DTLS 身份與短期 TLS-PSK 授權；原生路徑的 SDP、地址與 PSK 不返回瀏覽器。目標助手只連線本次授權的固定迴環閘道器，不接收任意 TCP 目標。

Go/Pion 助手通過 stdio 受 Node 管理，使用 UDP IPv4/IPv6 ICE、STUN 和可靠 DataChannel；一條 HTTP/TLS 或 WebSocket 連線對應一條資料通道。傳送分塊 16 KiB、單流高水位 256 KiB、SCTP 接收上限 1 MiB；沒有假資料預熱。每個助手最多 32 條活躍流和 32 條待建立流，Node 全域性最多 16 個助手、每個目標聯結器最多 8 個會話。總協商時限 25 秒，Hub 信令 10 秒，目標候選收集 8 秒，加密隧道驗證 8 秒；各階段仍受總時限及呼叫方取消約束。ICE connected 只表示底層連線，必須隨後通過實際 DataChannel 上的 TLS-PSK 握手及 HTTP 健康請求才宣佈 P2P 可用。佇列達到高水位後等待排空，傳送量仍在下降時繼續等待，連續 30 秒沒有進展才關閉該流；輪詢同時覆蓋低水位通知丟失的情況。UDP 使用系統分配的臨時埠，避免狹窄固定埠段衝突。繫結代次改變、聯結器斷開、授權撤銷、助手退出和關閉頁面均清理相關連線。

直連頁繼續使用 `/device-lan/` 隔離能力 URL，保留現有 CSP、路徑白名單、Origin 和憑據淨化。顯示通路由實際完成連線的結果決定：`lan` / `p2p` / `hub`。包裝頁解除安裝時傳送有能力校驗、按頁面代次區分的釋放請求，保留 2 秒重新整理寬限，重新載入不會誤撤銷新頁面；恢復連線時申請新票據並報告新通路。未確認的上傳、鍵鼠和任務命令不會由傳輸層自動重放。

完整 npm P2P 包附帶 Windows x64、macOS arm64/x64、Linux arm64/x64 助手及 SHA-256 清單，使用時校驗；macOS/Linux 使用私有臨時目錄中的可執行副本，避免 Windows 製作的 npm 包丟失執行許可權。使用者無需安裝 Go；不支援的平臺、舊 Hub/裝置、缺失助手或打洞失敗均回退 Hub。原始碼構建的完整分發入口是 `npm run pack:p2p`，需要 Go ≥1.24；普通 Web 構建不強制安裝 Go，也不保證包含助手。桌面安裝包由 `.github/workflows/desktop-release.yml` 的三個平臺 job 各自 `npm run build:device-p2p -- --host` 後再打包（`bin/` 在 electron-builder 白名單內），測試 `tests/unit/p2p-helper-release.test.ts` 守衛這條鏈路。原始碼目錄直接 `npm start` 時必須先跑一次 `npm run build:device-p2p -- --host`，否則本機沒有助手、P2P 永遠退回 Hub，日誌為 `helper-missing`。

裝置側設定：`PI_DEVICE_P2P=0` 停用；`PI_DEVICE_P2P_STUN` 為最多 4 個逗號分隔的 `stun:host:port`，預設 `stun:stun.l.google.com:19302,stun:stun.miwifi.com:3478,stun:stun.cloudflare.com:3478`，助手並行探測。預設值給多個伺服器的原因：只寫一個 STUN 時，該伺服器被牆或黑洞（曾在國內網路實測 `stun.cloudflare.com:3478` 超時）就收集不到 srflx 候選，打洞必然失敗且介面上只顯示中繼。打洞失敗按階段記錄一行日誌（`helper-missing` / `ice-config` / `gather-failed` / `signal-rejected` / `ice-failed` / `tunnel-failed` / `cancelled`），字首 `[DeviceCenter] Device <id> P2P failed: <reason>; using Hub relay`；目標端不報能力時記錄 `target reports no helper`。Hub 瀏覽器入口使用下述瀏覽器協商流程。可使用自建 coturn 的 STUN 服務；無法直連時走原 Hub。

### 純瀏覽器訪問 Hub 的直連通道

控制端無需安裝 pi-web-ui、RustDesk 或瀏覽器擴充套件，只需瀏覽器登入 Hub；被控端執行帶 P2P 助手的新版本。Hub 包裝頁用瀏覽器 `RTCPeerConnection` 與目標助手協商，ICE 在同區域網可選 host 通路、跨網可選打洞通路。**首屏不等協商**：包裝頁一開啟就把 Hub 中轉地址掛到子框架（約 2 秒出頁面），直連在後臺繼續協商，連上後新請求自動走直連、頁面長連線由應用自身重連切過去（會重開一次 WebSocket），協商失敗或直連中斷則保持/回到中轉。頂部狀態先顯示「伺服器中轉（後臺嘗試直連…）」，切換後按實際選中的候選顯示「區域網直連」「P2P 直連」「TURN 中轉」或「伺服器中轉」，不會用 ICE connected 代替業務健康檢查。瀏覽器的預設 STUN 為小米與 Cloudflare；裝置助手繼續使用裝置端配置。選中 TURN 時仍是中轉，不能稱為直連。

事實源：`browser-peer-client.ts`（包裝頁/沙箱內的 fetch、WebSocket 橋）、`browser-peer-gateway.ts`（裝置端協議與額度）、`device-p2p.ts`（助手與授權生命週期）、`relay.ts`（能力路徑信令）。Hub 先核驗現有賬號歸屬和隨機能力路徑，才允許 `__browser_p2p` 提交有界 SDP；信令只接受 Hub Origin 或具有有效能力路徑的 opaque 子框架。瀏覽器只得到這次裝置會話的短期閘道器金鑰，不得到本機憑據或 TLS-PSK。目標固定轉發至已有 PSK 授權閘道器，並複用管理路徑禁令、頭部淨化和桌面輸入限制。每次會話最長 30 分鐘，裝置斷開/重綁、助手退出和頁面關閉均回收；舊頁面遲到的關閉請求不能撤銷新連線。

頁面 HTML、指令碼等靜態資源仍由 Hub 載入；直連承擔對話/桌面 WebSocket 與動態 fetch（包括檔案分塊上傳下載）。群組授權、任務記錄等 Hub 管理操作仍歸 Hub。瀏覽器原生連結下載和未經過 fetch 的請求仍可走 Hub，不能聲稱所有流量都繞開伺服器。遠端會話內切換另一裝置使用獨立能力包裝頁，仍由當前控制瀏覽器連線目標裝置，不借第一臺裝置充當控制端。

連線失效後關閉在途通道並切回 Hub；失敗的提交、檔案分塊或鍵鼠輸入不自動重放，避免重複執行。應用原有重連負責重新建立 WebSocket。直連協商有 20 秒上限（超時隻影響是否升級，不影響頁面已經可用）；一次開啟只協商一次，關閉直連後需重新開啟裝置入口才再次嘗試直連。瀏覽器不支援 WebRTC、舊裝置不認識信令、缺少助手、UDP/NAT 不允許直連時均保留中轉。普通 HTTP Hub 可協商 DataChannel；剪貼簿許可權、WebCodecs 硬解碼和本機目錄授權依舊受瀏覽器安全上下文限制，使用 HTTPS 才能獲得相應能力。

更新 Hub 和被控端並重啟實際服務，從 Hub 重新開啟裝置即可測試；控制端僅重新整理瀏覽器。`node --import tsx tests/device-browser-p2p-test.mjs` 用真實 Chrome/Pion 驗證直連 HTTP/WS、上傳下載、取消、巢狀裝置、許可權和中轉回退；加 `--insecure-origin` 使用實際私網 HTTP 地址，檢查非安全上下文也能建立通道。這些測試不代表所有公網 NAT 組合或 120/240 Hz 桌面效能。

### TURN 中繼

某些對稱 NAT、CGNAT 或 UDP 受限的網路會導致直連失敗。兩端可配置 `PI_DEVICE_TURN`（最多三個地址）、`PI_DEVICE_TURN_USERNAME`、`PI_DEVICE_TURN_CREDENTIAL`，助手把 TURN 作為額外 ICE 伺服器並分配 relay 候選；選定中繼路徑時流量經自建 coturn 轉發。TURN 也不可用時仍回退 Hub。

TURN 地址支援 `turn:host:3478?transport=udp`、`turn:host:3478?transport=tcp` 和 `turns:host:5349?transport=tcp`，Node 與原生助手採用一致的協議、IPv6、埠及憑據驗證。`native/device-p2p/ice_tcp_test.go` 使用只監聽 TCP 的真實本地 TURN 服務驗證候選獲取。

執行 `pi-web-ui desktop diagnose --p2p` 可獲得不含 SDP、IP、憑據的診斷：助手可用性、TURN 配置狀態、host/srflx/relay 候選數量。它只驗證本機候選收集，不代表對端可達；此命令不檢測瀏覽器自身的 ICE 候選和連線。協商超時按 `gather-timeout`、`signal-timeout`、`ice-timeout`、`tunnel-timeout` 區分，只有呼叫方取消才報告 `cancelled`。

新版目標可返回白名單故障碼，如 `target-busy`、`target-helper-missing`、`target-unavailable`、`target-gather-timeout`；Hub RPC 失敗區分 `signal-timeout` 與 `signal-failed`。不回傳異常堆疊、憑據或任意錯誤文本。舊目標空響應仍記為 `signal-rejected`。`node --import tsx tests/device-p2p-latency-test.mjs` 在真實 DataChannel 與 TLS 握手間注入雙向延遲，覆蓋超過原 2 秒驗證視窗的正常連線和錯誤金鑰拒絕；執行前需構建本平臺 P2P 助手。

- 只有配置了 TURN 才允許 relay 候選：沒配時助手看到 relay 對直接判定失敗，避免流量莫名繞第三方。
- 中繼生效時日誌寫一行 `[DeviceCenter] Device <id> P2P is relayed through TURN`；介面通路仍顯示 `p2p`（它確實不是 Hub 中繼，只是經你自己的伺服器轉發）。
- 只配地址不配憑據會直接報 `ice-config`，不會靜默降級成"沒有中繼"。
- 頻寬：H.264 通道 1440p60 約 12 Mbps、1440p120 約 18 Mbps，coturn 只需按這個量級準備頻寬與 UDP 埠段（`min-port`/`max-port`）；TURN over TLS（`turns:`）需要額外證書，且延遲更高，優先 `turn:` + UDP。
- 部署示例見 [裝置中心部署](device-center-deployment.md#turncoturn)。伺服器只升級 Hub 就能承擔信令，無需安裝桌面環境。`PI_DEVICE_P2P_HELPER` 是受信任管理員/開發測試用的絕對路徑覆蓋，繞過隨包校驗；瀏覽器與 Hub 信令不能設定它。

`node --import tsx tests/device-p2p-test.mjs` 使用臨時資料目錄、兩份獨立助手程序和實際 Hub RPC/本機訪問 API，驗證 LAN 不可達時選擇 P2P、HTTP/桌面/聊天併發、金鑰不進入瀏覽器、併發會話、回退和撤銷。本機迴環驗證不代表跨網打洞或實際桌面幀率。完整實機驗收仍需 Mac/Windows 不同網路、UDP 禁止、裝置重連和平臺許可權檢查。P2P 不解除桌面採集和編碼的幀率限制。

## 瀏覽器遠端桌面

裝置卡提供獨立「遠端桌面」入口，複用賬號歸屬校驗、一次性票據和裝置訪問鏈路。實現參考 [krd](https://github.com/zzjcool/krd) 的原生捕獲與鍵鼠注入方式，畫面和輸入優先複用上述區域網通道，不可達時使用既有 WebSocket 中繼，不進入聊天快照或模型上下文。無需安裝 noVNC 或 VNC 服務，也無需固定桌面埠。

遠端桌面預設關閉；本機啟用偏好持久化到 `<dataDir>/desktop-settings.json`，寫入成功後才更新執行態。設定 `PI_DEVICE_DESKTOP=1` 會強制啟用，本機關閉偏好不能覆蓋該環境變數。只讀許可權由後端強制執行，只讀連線的鍵鼠輸入不會注入被控電腦。開啟遠端桌面頁面會自動以可控制模式連線已啟用且可用的裝置；使用者可在頂部切換隻讀。頂部使用緊湊單行工具欄，設定、macOS 許可權指引和文字輸入預設摺疊，畫面佔用剩餘高度；全屏保留工具欄。裝置未啟用或不可用時展開設定，啟用成功後自動連線，連線失敗顯示具體原因。遠端桌面票據兌換的 Hub 包裝頁允許跨來源嵌入，內部能力頁繼續使用不含 `allow-same-origin` 的沙箱和隨機能力路徑；普通裝置網頁包裝頁仍僅允許同源嵌入。舊獨立域/埠桌面票據換為 Hub 路徑票據後加載，避免浮窗依賴第三方 Cookie。

對話 Web UI 的裝置目錄和群成員遠端桌面入口統一在 App 共享懸浮窗內開啟，支援拖動、右下角縮放、最小化與全屏；點選聊天區域或切換檢視不會關閉視窗，最小化保留連線。視窗內 iframe 僅授予 scripts/forms/pointer-lock，禁止 `allow-same-origin`，沿用服務端簽發的隔離能力 URL 與既有授權流程。點選「獨立標籤頁」會重新申請一次性票據，成功開啟後關閉懸浮窗；彈窗被攔截或授權失敗則保留視窗並顯示錯誤。Electron 使用已有 `openHub` 橋開啟獨立視窗，同樣僅在橋返回成功後關閉懸浮窗。Hub 獨立頁面的入口行為保持不變。

| 平臺          | 捕獲與輸入                                                                      | 執行條件                                                       |
| ------------- | ------------------------------------------------------------------------------- | -------------------------------------------------------------- |
| Windows       | GDI 捕獲 + SendInput 鍵鼠注入                                                   | 可訪問的本機圖形桌面會話                                       |
| macOS         | Swift 原生助手：ScreenCaptureKit `SCScreenshotManager` 捕獲 + CoreGraphics 輸入 | macOS 14+、Swift CLI；螢幕錄製許可權，控制時還需輔助功能許可權 |
| Linux X11     | ffmpeg 捕獲 + xdotool 鍵鼠注入                                                  | 可訪問的 X11 會話與 ffmpeg；僅檢視時可不安裝 xdotool           |
| Linux Wayland | 暫不支援                                                                        | 後續需接入 Desktop Portal 的螢幕共享與遠端控制能力             |

舊 `PI_DEVICE_VNC_*` 環境變數已退役，不再用於地址、埠、密碼、路徑或瀏覽器元件配置。

## 驗證與邊界

群聊的交付面板以「需要我處理」彙總待驗收、審查要求修改、執行失敗和中斷，預設只顯示這些事項，可切換全部對話。分類由 `web/src/group-attention.ts` 根據執行狀態和精確交付 ID/提交 SHA 對應的最新審查派生；無顯式人工問題時，執行中、已關閉和無交付的普通問答不生成待辦，不解析報告文字猜測阻塞。Bot 可通過 `conversation_attention` 登記 `answer` / `decision` 和問題，必須繫結自身當前執行任務與原會話；問題儲存在會話中，重新整理後仍可展示。群成員通過「回覆並繼續」提交帶 `attentionId` 的人類答覆，Bot 停止執行後才能答覆；答覆、繼續任務和清除待辦在同一事務提交。重試複用冪等鍵，舊問題 ID 拒絕，其他 Bot 不能代答或設定他人問題。現有驗收操作繼續繫結原交付版本。

`tests/device-bot-live-integration-test.mjs` 經真實 Hub、裝置執行時、SDK 與本地確定性 HTTP 模型驗證主 Bot 免 @ 接收、工具委派關聯請求、執行結果回到原會話，以及補充訊息繼續同一執行者會話；同時驗證 SDK 工具提問落盤、人類答覆清除待辦並恢復原會話、重複請求只建立一次繼續任務及舊問題拒絕；它驗證傳輸與執行鏈路，不證明真實模型的任務理解與選擇質量。產物通過 `tests/lib/ensure-build.mjs` 統一準備。

相關測試位於 `tests/unit/device-center-*.test.ts`，覆蓋賬號隔離、配對、真實迴環 HTTP/WS 中繼、任務協議、@ 選擇、檔案完整性及衝突等。測試不呼叫真實模型，不能替代真實三平臺端到端驗收。公共運營還需部署監控、備份、賬號恢復與服務容量驗證；本次程式碼未自動建立域名、購買伺服器或開放公共註冊。
