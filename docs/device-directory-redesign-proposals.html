左上角「所有设备」浮层：结构重构

问题不在配色，而在结构：三个文字按钮把名称列挤成 40px，中文名被压成逐字换行；560px 宽的卡片里，一半宽度给了按钮。 重构后：高频动作留在行上（打开 / 远程桌面），只有低频进 ⋯，名称占满可读宽度，宽度 560 → 328px，单行 96 → 45px； 窄屏换成底部抽屉 + 44px 触控块，常用动作一律 ≤ 2 次点击。

落地记录
  • 已按 方案 B（极简单行）+ 手机底部抽屉 实现：web/src/components/DevicePanel.tsx（新）、DeviceDirectory.tsx（取数 + variant="panel"）、BrandDeviceMenu.tsx（浮层 / 抽屉容器）、use-coarse-pointer.ts（断点单源）与 styles.css 的 .dp-*。
  • 与稿件的一处差异：行尾第二个动作落地为远程桌面（稿里画的是 ↗「新标签打开」）。整行本身就是打开设备的入口，↗ 与它重复；远程桌面才是需要独立入口的第二高频动作。因此 ⋯ 菜单只剩「设置备注 / 复制设备 ID」。

01诊断：4 个结构性问题

截图里能直接看到的现象，逐条对应到代码（web/src/components/DeviceDirectory.tsx）。

01
名称列被按钮吃掉，中文名逐字换行

行内是 flex：图标 38 + 状态胶囊 ~62 + 三个文字按钮 ≈ 336 + 间距，合计 ~470px，留给名称的只有几十像素，而 .dd-identity strong 带 overflow-wrap: anywhere → 每个字单独一行（截图里的 cdeMa / c / mini.lo / cal）。

02
「所有设备」头占了 1/3 高度

38px 图标 + 两行文案（标题 + 「同一账号下的设备，使用本机绑定授权直接访问。」）+ 24px 下间距 ≈ 84px。这句话是一次性解释，不该常驻在一个每次点开的浮层里。

03
主次不分：一件设备有 3 个同权重的按钮

「修改备注 / 打开设备 / 远程桌面」视觉权重完全相同，而且「修改备注」这种低频操作和最常用的「打开设备」并排。真实使用频率极度倾斜：打开 ≫ 远程桌面 ≫ 备注。

04
备注编辑把行撑成两段，编辑时整块跳高

表单用 width:100% + flexWrap:wrap 追加在行末，输入框 minWidth:180px，加上两个文字按钮，编辑态高度直接翻倍 —— 列表上下跳动。

交互与可达性

主次动作

  • 主：点行 → 打开设备（最高频，一步到位）
  • 次：↗ 图标 → 新标签打开（可中键/Ctrl 点）
  • 低：⋯ → 远程桌面、备注、复制 ID
  • 离线设备：行仍可点，但先给 title="设备离线" 提示，失败时用行内 notice 而非全局报错

语义 / 键盘

  • 行用 <li> + 覆盖整行的 <a class="row-hit">（避免 button 套 button 的非法嵌套）
  • 图标按钮在 a 之上（z-index + position:relative）
  • Tab 顺序：行 → ↗ → ⋯；aria-haspopup="menu"、aria-expanded
  • focus ring：2px --accent，:focus-visible 才显示

长文本 / 极端值

  • 三件套：min-width:0 + overflow:hidden + ellipsis（不再 anywhere 逐字断行）
  • 200 字符设备名 → 单行省略，tooltip 全文
  • 备注为空 → 次行回落成 ID；备注全删 → 保存空串即清除
  • 设备 20 台 → 面板内滚动（max-height: min(60vh,420px)）

密度权衡

  • A：≥3 台仍舒适，信息完整（名称 + ID + 状态 + 本机）
  • B：设备 ≥5 台时切到单行；同一份数据，只换 variant
  • 两者共用行组件与事件，切换零成本

04手机适配：抽屉 + 触控优先，常用动作不进菜单

手机上照搬桌面浮层会有两个硬伤：hover 不存在（藏起来的图标等于不可发现），左上角不是拇指区（浮层展开后两个手指都难够到）。 所以窄屏换形态：点左上角 chip → 从底部升起抽屉，行高 56px，每个常用动作一个 44px 触控块，最多两次点击。

    注：现状的差距不只在次数 —— 它还伴随按钮折行、名称竖排、需要滚动；表里只对比「能不能一步做完」。次数相同但路径更短（不用读三行文字按钮）同样是收益。

    能被「去掉」的点击

    • 远程桌面不再进 ⋯：它是第二高频动作，藏在菜单里就变成 3 次点击
    • 备注去掉「保存」按钮：键盘上的完成/回车即保存，长按直接进入编辑
    • 刷新改下拉：抽屉本来就该能下拉，顺手省一次点击
    • 关闭不用找按钮：下滑或点遮罩，任何位置的拇指都能关

    不能为了省点击牺牲的

    • 不隐藏高频动作：靠 hover / 长按才能用的入口，只能给低频功能
    • 不做双击：双击与「打开」冲突，且系统级手势容易被浏览器吃掉
    • 不做二次确认：打开设备是可逆操作，不需要确认弹窗
    • 不做菜单套菜单：⋯ 里最多一层，不再出现「⋯ → 更多 → ⋯」

    还能再省一步（可选，需产品确认）

    • 若「打开本机」占绝大多数：手机端 chip 单击 = 直接回本机，长按 chip = 展开抽屉（1 次点击）
    • 抽屉打开时自动聚焦第一行（外接键盘 Enter 直开）
    • 记住上次选择：最近使用的设备排第二行，常用路径稳定在拇指第一屏

    桌面与手机共用同一套行组件与事件，只换容器（浮层 / 抽屉）与尺寸令牌；pointer: coarse 命中时自动切触控布局，不额外维护一套组件。
