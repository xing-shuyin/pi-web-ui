# docs/ Documentation Index

> The **single entry point** for this repository's docs. `AGENTS.md` only holds the “key feature → source-of-truth file → doc” mapping; this file holds “what each doc covers, how heavy it is, and when to read it”.
> Adding / removing / renaming a doc requires updating this index (guard: `tests/unit/docs-index.test.ts`).
> Every doc also has English and Traditional Chinese versions: `filename.en.md` and `filename.zh-TW.md` in the same directory, and the three files can switch language at the top; this index registers only the Chinese originals. Coverage check: `npm run docs:i18n` (`--check` for the gate form); `docs/*.html` design proposals also ship `.en.html` / `.zh-TW.html` variants (gate: `npm run docs:i18n:html`), and `CHANGELOG.md` is generated by the release script.

## What the Weights Mean

| Marker | Meaning                                                                                               | How to read                                        |
| ------ | ----------------------------------------------------------------------------------------------------- | -------------------------------------------------- |
| ★★★    | Must read before touching core code: global architecture decisions, cross-module hard rules, code map | Read in full                                       |
| ★★     | Must read before working on the module: its implementation boundaries, state machine, common traps    | Read that doc in full                              |
| ★      | Ops / deployment / integration: consult when changing environments, shipping, or wiring providers     | Look up on demand                                  |
| ○      | Reference material: design drafts, historical reviews, review evidence, sample presets                | No need to read in full; read when tracing history |

Hard-rule details (color tokens, the `details` cap, three-way prompt separation, compaction soft cap, takeover transactionality, etc.) **live in [`agent-rules.md`](agent-rules.en.md)**; other docs do not restate the prohibitions.

## 6. Maintenance Conventions

1. **One thing per place**: details go into the matching topic doc; `AGENTS.md` registers entry points only, and this index registers topics and weights.
2. **New doc** = create the file + add a row in the matching group of this index (topic, weight, when to read) + add a row to the `AGENTS.md` mapping table when necessary.
3. **Hard rules do not scatter**: new prohibitions go into `agent-rules.md`, plus a row and the guard test name in `AGENTS.md` §3.
4. Guards: `tests/unit/docs-index.test.ts` (this index covers every `docs/*.md`, links and anchors resolve, every row has a weight marker), `tests/unit/agents-md.test.ts` (`AGENTS.md` size and dead links).
