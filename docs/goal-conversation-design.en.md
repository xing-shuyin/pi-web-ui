# Goal Mode 2.0 design: turning "goal review" into a conversation

> **Status**: **implemented, and only one path remains**. Goal Mode 2.0 = server-driven + an executor conversation doing the work + **the current conversation acting as reviewer** (Plan A in this document, called 「执行对话模式」(executor-conversation mode) below). The v1 hidden isolated review session and the autonomy-marker path (`runGoalReview` / `isAutonomous` / `GOAL_COMPLETION_RE`) were **deleted** by product decision; Plan B (reviewer = role subagent) and the `reviewMode` switch are **not being implemented**. Implementation details and deviations are in §11.
> Related: #385 (AI goal extraction timeout, PR #386 pending merge), #389 (Goal & Plan, this design can merge with its Phase 1).
> **Revision history**
>
> - **v2.2 (this revision)**: **keep only the new mode** — the self path and the mode switch are removed (the protocol drops `reviewMode`; the `GoalStatus.reviewModel` field name stays for DSH, with the pi-side meaning changed to "research model"); a missing role bridge or an executor conversation that cannot be created = reject or abort, **with no fallback path**. See the last three rows of the §11.2 table.
> - **v2.1**: Plan A implementation complete — deviations from the v2 design, the file/function map, verification results and known leftovers are in §11.
> - **v2**: collapsed v1's A/B options into three configurations of **one server loop** (§4); option A becomes "the server runs the execution rounds, the main conversation only reviews"; read-only now reuses the existing `permissionPreset` + template extension whitelist and **drops the new template `tools` field**; role conversations default to `persist=false`; added 5 fact corrections (§2) + the failure matrix (§4.6) + decision conclusions (§6).
> - v1: Plan A (main conversation = reviewer) / Plan B (main conversation = executor) side by side.

## 0. Today's state and pain points

Today's 「目标模式」(Goal Mode) is a **one-way, server-orchestrated automation pipeline**:

```
GoalBar sets a goal
  → setGoal injects a user message 「【目标已设定】…请开始实现」(goal set… start implementing)   (goal-service.ts setGoal)
  → main conversation executes
  → agent_end hook                                            (agent-service.ts:5086)
  → runGoalReview spins up a 【hidden, inMemory isolated session】        (goal-service.ts:1148)
       · feeds: goal text + the main conversation's last output + git diff (capped at 60k, GIT_DIFF_CAP)
       · asks only for {"verdict":"pass|fail","feedback":"…"}
  → pass: clear the goal; fail: send the feedback back into the main conversation as a plain user message
```

Pain points (all pointing at "review is not a conversation"):

| #   | Pain point                                              | Root cause location                                                                                                                                                                                                                                                |
| --- | ------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 1   | **The review process is completely invisible**          | The isolated session is inMemory, never persisted, has no entry in the left panel; the user only sees 「审查中（第 N 轮）」(reviewing, round N)                                                                                                                    |
| 2   | **The review forgets every round**                      | Each round builds a new session via `createAgentSessionServices` (`:1274`); the reviewer cannot remember what it said last round and repeats the same remark                                                                                                       |
| 3   | **The execution side forgets too**                      | feedback is a one-shot user message; the executor can only catch it with its own context, with no structured handoff                                                                                                                                               |
| 4   | **Every round force-feeds a 60k diff**                  | `buildDiffFingerprint` (`:160`) + 60k truncation: high token cost, and a truncated diff makes "is it really progressing" come out wrong                                                                                                                            |
| 5   | **No real 「审核对话」(review conversation)**           | To intervene in the review ("这条你再核实一下" — double-check this one) the user can only cancel the goal and start over                                                                                                                                           |
| 6   | **A hung review wedges the loop forever** (new in v2)   | `await reviewer.prompt(...)` (`:1321`) has **no timeout**; if the isolated session never returns, it sits in 「审查中」 forever                                                                                                                                    |
| 7   | **The default path has no reviewer at all** (new in v2) | `reviewModel === null` (the default) → `isAutonomous` (`:1231`) takes "the main model writes 【目标已达成】(goal achieved) itself + a server-side circuit breaker", which is **a different code path** from what pain points 1–5 describe; both must be brought in |

**User ask**: make goal review itself a conversation. Two sketches (the core of v1):

- **A**: the current conversation = the review conversation, plus a separate **always-on subagent** that executes the task; when it finishes, control returns to the current conversation to review; if it fails, send the subagent a message to fix it.
- **B**: the other way round — the current conversation executes, and **the review gets its own subagent/conversation**.

## 1. Conclusion (TL;DR)

1. **The foundation already exists; no new mechanism is needed.** A first-party subagent **is just a normal conversation** (`subagents.ts:14-24`): visible in the left panel, openable, typeable (= steer), abortable. The only change is one sentence: **swap "the hidden isolated session" for "a role conversation"**.
2. **A and B differ only in "who executes, who reviews"** → extract one 「角色对话（role conversation）」(role conversation) layer and write **one** state machine; A/B are two configurations of it (§4, §5), not two implementations.
3. **Orchestration authority belongs entirely to the server.** The server holds: goal text, round budget, stagnation/same-error circuit breaker, verdict parsing, generation invalidation, and the birth and teardown of role conversations. **A round = one dispatch + one verdict; the model must not self-loop** (v1's option A handed the spawn→wait→steer→wait loop to the model, which invalidates both the round budget and stagnation detection — v2 changed this, see §5.2).
4. **Recommended configuration: ⚡ B (current conversation executes, review is an always-on role subagent), default.** The user's composer always points at the session that is actually doing the work; the review is naturally isolated, can be read-only, and can use a cheap model.
5. **Read-only needs no new template field.** `permissionPreset` takes effect **per conversation** and is read hot (`makeConversation` assigns it at `:4107`; `wrapWrite/Edit/Bash` call `getPermission()` every round at `:3917/:3925/:3961/:7187`) → set a role subagent to `read-only` after creation and the gate is done; then make the reviewer template's `enabledExtensions` non-empty so plugin/MCP tools never enter that session at all (`agent-service.ts:3976`). v1's `SubagentTemplate.tools` field is therefore **unnecessary**.
6. **Role conversations default to `persist=false`**: `persist` only decides "whether to archive into history" and affects neither left-panel visibility nor typeability; a `persist=true` subagent has `isSubagent=false` and **counts toward the project's resident normal-conversation count (unlimited by default, capped only when `PI_WEB_MAX_OPEN_CONVERSATIONS` is explicitly configured)** (`:2392-2418`).
7. **Zero change to default behavior.** `reviewMode` defaults to `"self"` (= today's autonomy path); clients that already set `reviewModel` auto-upgrade to `"reviewer"` (they were already on external review — switching to a role conversation just turns the isolated session into a visible one, at the same token order of magnitude). Rollback still relies on the existing master switch `goalModeEnabled`.
8. **Landing order: B first (PR-1/2), then decide on A after observing real usage (PR-3).** Do not pre-build abstractions for an unvalidated interaction.

## 3. Layering principle (settle it first, or A/B each get written once)

| Layer               | Owner                          | Content                                                                                                                                                                                                     |
| ------------------- | ------------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| State machine       | **Server** (`goal-service.ts`) | Goal text, lock and round budget (`maxRounds`, 0 = unlimited), stagnation circuit breaker, `parseReviewerVerdict` parsing, generation invalidation, timeouts and degradation, quiesce and the master switch |
| Work within a round | **Model** (role conversation)  | How to do / verify this round, what to produce, the reviewer's `{"verdict","feedback"}`                                                                                                                     |
| Visibility          | **Role conversation**          | The execution/review process must land in a conversation that can be opened from the left panel, not a hidden session                                                                                       |

**New rule 4 (the key to v2): round ownership belongs to the server.**

> A round = 「the server dispatches once + the server judges once」. The model may freely use tools (read, run tests, grep) **within a round**, but **must not** drive the next round itself: no `subagent_spawn` of sibling roles yourself, no `subagent_wait_all` on the executor, no deciding "one more round".
> Rationale: round numbering, stagnation fingerprints, same-error counts and generation invalidation are all computed server-side (`:1208-1229`); once the model self-loops, all of those measurements are wrong — the server only sees one result at `agent_end`.

Corollary: **there is exactly one structured contract** (the reviewer's verdict JSON); the execution side only gets free text, and progress is always measured by the server (`git diff` fingerprint + session error signature).

## 4. The recommended unified loop (v2 core)

### 4.1 Abstraction

```
Goal Mode = one server loop + two role slots

  executor slot: the main conversation (the user's own session) or a role subagent
  reviewer slot: the main conversation or a role subagent or none (self autonomy)

  Three configurations (§5):
    ⚡ reviewer : executor=main conversation  reviewer=role subagent    ← recommended default
    🧭 delegated: executor=role subagent      reviewer=main conversation ← v1's option A
    🕯 self     : executor=main conversation  reviewer=none              ← today's default behavior
```

```ts
/** A 「角色对话」(role conversation) under Goal Mode. */
interface RoleAgent {
	kind: "executor" | "reviewer";
	/** Conversation id carrying this role; = goal.conversationId means the main conversation itself. */
	convId: string;
	/** true = a subagent the server spawned (dismissable / restartable); false = the main conversation (message injection only). */
	spawned: boolean;
	/** Must always equal the main conversation's cwd: review must see the actual changes in the same workspace. */
	cwd: string;
	/** Generation: rebuilt after a role conversation is closed externally; old callbacks are invalidated by it. */
	generation: number;
}
```

### 4.2 Timing of one round (server-driven, A/B fully isomorphic)

```
ROUND r (server):
 ① dispatch  executor ← task message (goal + round r + previous round's feedback)
         main conversation: sendUserMessage(…, {deliverAs: isStreaming ? "steer" : "followUp"})
         subagent: r==1 ? spawnRoleAgent(…) : sendRoleAgent(convId, …)
 ② wait      waitRoleAgent(executor, deadline)          # event-driven, not polling
 ③ sample    measured by the server: git diff fingerprint (buildDiffFingerprint) + session error signature (extractErrorSnippet)
         — sampled on **the executor's conversation**, not "the main conversation" (v1 would sample the wrong one here)
 ④ review    reviewer ← review message (goal + "round r" + the executor's own account + optional plan progress)
 ⑤ wait      waitRoleAgent(reviewer, REVIEW_DEADLINE) → take text → parseReviewerVerdict
 ⑥ judge     the server (sole arbiter):
          pass      → clear the goal, tear down role conversations, notify
          revise    → r++, feedback goes into ①
          blocked   → stagnation/same-error circuit breaker (server-computed, never asks the model)
          exhausted → round budget spent / single-shot mode
          invalid   → no JSON: treat as fail with raw as feedback (unchanged), or retry once per config
```

- The essential difference from v1: **the waits in ②⑤ belong to the server**; inside a role round the model only does 「这一轮的工作」(this round's work). v1's option A handed this loop to the main conversation model (spawn→wait→steer→wait→JSON), which invalidates the round budget and stagnation detection.
- Side benefit: review rounds no longer depend on `subagent_wait_all` (60s cap, the model has to wait repeatedly); the review deadline is managed centrally by the server (fixes pain point 6).

### 4.3 Contract (the two messages sent into role conversations)

**Execution round (sent to the executor slot)**

```
【Goal · round N/M】
<full goal text>

Previous review feedback (round N-1, if any):
<feedback verbatim>

Requirements: start changing the workspace directly; when done, explain in one paragraph what changed and how you verified it.
Forbidden: asking the user anything (this conversation is an automated flow; dialogs return as cancel);
      spawning/waiting on other subagents yourself (rounds are controlled by the server);
      describing changes in the reply without actually modifying files.
```

**Review round (sent to the reviewer slot)**

```
You are a strict, independent acceptance reviewer. Judge only whether the goal is fully satisfied — not what it says, but the actual state of the workspace.

【Goal】<full goal text>
【This is round N/M】
【Executor's account this round】<the executor's last assistant text; if empty, note "（无自述）" (no account)>
【Plan progress (optional, only when a plan exists)】<planManager.describePlan(convId)>

You may (and only should) verify with read-only means: read / grep / scm (read-only git) / read-only bash (running tests).
Forbidden: modifying any file (this conversation is set to read-only; write tools error out immediately);
      asking the user anything (dialogs return as cancel);
      spawning or waiting on subagents (rounds are controlled by the server);
      putting any text other than JSON in the reply.

Output exactly one JSON:
{"verdict":"pass","feedback":"<one sentence: what is satisfied>"}
{"verdict":"fail","feedback":"<concrete, directly actionable items to fix>"}
```

Contract copy follows repo conventions: the server uses `pick(lang, zh, en, key, vars)` with globally unique keys (`goal.role.exec`, `goal.role.review`…), and notices pushed to the UI use the `text` + `textEn` pair.

### 4.4 Callbacks GoalHost needs (the only real engineering work)

```ts
interface GoalHost {
	// …existing (gitDiff / reviewSettings / emit / flushSnapshot / isDisposed / quiesceBlocked / getConv …)

	/** Spawn a role conversation: same channel as spawnSubagentConversation (template/model/thinking level/quota all reused).
	 *  permissionPreset is written when the conv is created (so the first round's tool calls cannot race ahead of the permission taking effect). */
	spawnRoleAgent(opts: {
		role: "executor" | "reviewer";
		prompt: string;
		cwd: string; // always equal to the main conversation's cwd
		template?: string; // default "goal-executor" / "goal-reviewer" (built-in, overridable in the settings panel)
		model?: string | null; // null = template model → panel default → follow the main conversation
		thinkingLevel?: string;
		permissionPreset?: string; // reviewer passes "read-only"
		persist?: boolean; // defaults to false
	}): Promise<string>; // → convId

	/** Event-driven "wait for this round to finish": subscribe to the conversation's agent_end (the hook site already exists at agent-service.ts:5085),
	 *  returning done / error / canceled / timeout / gone. Never implement it as polling. */
	waitRoleAgent(convId: string, timeoutMs: number): Promise<"done" | "error" | "canceled" | "timeout" | "gone">;

	/** Continue/follow up: subagent = a new turn; main conversation = a user message (queued per the 4.3-① input policy). */
	sendRoleAgent(convId: string, message: string, opts?: { deliverAs?: "steer" | "followUp" }): Promise<boolean>;

	/** The role conversation's last assistant text (= snapshot.output, agent-service.ts:2614). */
	readRoleAgent(convId: string): string | undefined;

	/** Teardown: dismiss the role subagent when the goal is cleared/completed/blocked (a no-op for the main-conversation slot). */
	dismissRoleAgent(convId: string): Promise<void>;

	/** Set permission by convId (`setPermissionPreset` only affects the active conv, so this variant is needed). */
	setConvPermission(convId: string, preset: string | null): void;

	/** Whether the conversation still exists (steer silently no-ops after a subagent is dismissed/removed, so this must be checked explicitly). */
	hasConv(convId: string): boolean;
}
```

Implementation notes (all small changes to existing code):

- `waitRoleAgent`'s event source: hang a `Map<convId, resolver>` off the `agent_end` branch of `onEvent` (`agent-service.ts:5040-5086`, which already reports the outcome of `conv.isSubagent`); take `error/canceled` from the existing `subagentRunOutcome(conv)`.
- `spawnRoleAgent` reuses `spawnSubagentConversation` with two new optional parameters (`permissionPreset`, `role`), writing the role name into `conv.subagentType` (the left-panel badge shows `goal-executor` / `goal-reviewer`).
- A role conversation with `persist=false` **does not enter history** but **does enter the left-panel list** (existing behavior, no change needed).

### 4.5 Measurement definitions for verdicts and circuit breaking (the v2 corrections)

| Signal                                | Current measurement                             | 2.0 measurement (common to A/B)                                                                                                                                                                                                                                 |
| ------------------------------------- | ----------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Workspace progress (diff fingerprint) | `mainConv.cwd` (`:1224`)                        | **Unchanged**: always the main conversation's cwd (both slots share the cwd; this is a hard constraint)                                                                                                                                                         |
| Error signature (`sameErrorRounds`)   | `mainSession` (`:1208`)                         | **Changed to the executor's conversation** — under delegated the main conversation is the reviewer, and its own tool errors (e.g. a wait timeout) do not mean execution is struggling                                                                           |
| Round numbering / budget              | `g.round` + `locked`/`maxRounds`                | **Unchanged** (server-computed, the contract states "round N/M", same as v1)                                                                                                                                                                                    |
| `blocked` decision                    | `sameErrorRounds >= 2 \|\| stagnantRounds >= 2` | **Unchanged**; under `self` it is only triggered by "review absent", while under reviewer/delegated it **asks the reviewer first and computes the circuit breaker independently of the verdict**, terminating and injecting a blocked explanation when it fires |

### 4.6 Failure matrix (new in v2, one testable case per row)

| Scenario                                                    | Detection point                                                                                  | Handling                                                                                                                                                                                                                             |
| ----------------------------------------------------------- | ------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Role conversation dismissed by the user / bulk removed      | `hasConv(roleConvId)` before every step                                                          | reviewer slot: **rebuild once** (cheap, stateless) and continue; executor slot: set the state to 「受阻（执行对话已失联）」(blocked: executor conversation lost) and wait for the user (rebuilding would lose the executor's memory) |
| Role round finished but errored (provider 400/timeout)      | `waitRoleAgent → "error"`                                                                        | Reviewer error → treat as fail (feedback = the error text) or retry once; executor error → counts toward `sameErrorRounds`                                                                                                           |
| Role round timed out                                        | `REVIEW_DEADLINE` (suggested 10 min) / executor deadline (suggested = the tool watchdog measure) | Reviewer: treat as fail + "review timed out"; executor: `stopRoleAgent` then treat as fail, avoiding a permanent wedge (fixes pain point 6)                                                                                          |
| Subagent quota full (16 in-memory / 8 normal conversations) | `spawnRoleAgent` throws                                                                          | **Degrade**: the role slot falls back to `self` (no reviewer) or "the main conversation doubles up", plus one warning notice; the loop never dies from quota                                                                         |
| quiesce (server draining) / dispose                         | existing `quiesceBlocked()` / `isDisposed()`                                                     | Same as today: no further dispatches mid-flight, state set to 「已中止」(aborted), role conversations torn down as well                                                                                                              |
| Service restart                                             | All in-memory state is lost (the goal itself is not persisted either)                            | Semantics match today; GoalBar shows 「角色对话已失联」(role conversation lost) and allows reopening                                                                                                                                 |
| Takeover across pages                                       | The target conv moves, `goal` state does not                                                     | A `persist=false` role conversation **moves with the parent** (`agent-service.ts:12415`); the new holder rebuilds the loop; the docs state "one more round runs after takeover, history rounds count from 0"                         |
| User clears the goal / changes it mid-flight                | existing `goalGeneration` / `goalReviewGeneration`                                               | Reused: every in-flight `waitRoleAgent` callback is invalidated by generation; role conversations are torn down                                                                                                                      |
| User aborts the main conversation manually (Stop)           | existing `onAgentEnd(conv, true)`                                                                | Reused: clear the goal, tear down role conversations, notify 「已手动停止」(stopped manually)                                                                                                                                        |

## 5. The three configurations

### 5.1 ⚡ `reviewer`: main conversation executes, review is a role subagent (**recommended default**, = v1's Plan B)

| Dimension           | Conclusion                                                                                                                                                                                                                    |
| ------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| User's view         | The composer points at whoever is actually working; interrupt or abort at any time; the review is a left-panel badge you can open and read item by item, and even steer yourself ("这条你再核实一下" — double-check this one) |
| Review independence | Isolated session + read-only preset + extension whitelist (no plugin write tools)                                                                                                                                             |
| token               | Low: the reviewer verifies in the same cwd itself, so the server need not force-feed a 60k diff; each round only consumes "goal + own account + plan progress"                                                                |
| Reviewer memory     | Reuses the same convId (it remembers what it said last round), avoiding repeating the same remark                                                                                                                             |
| Retrofit size       | Small: one block of `runGoalReview` ("build its own isolated session", `:1274-1337`) becomes three host callbacks                                                                                                             |
| Risk                | The subagent is headless → cannot ask the user (the contract forbids it); quota usage (degradation in §4.6)                                                                                                                   |

### 5.2 🧭 `delegated`: main conversation = reviewer, the executor is an always-on role subagent (= v1's Plan A, **v2 changes how it is driven**)

Differences from v1's formulation (must be aligned):

| Item                        | v1 formulation                                                                                                                                                 | v2 formulation (recommended)                                                                                                                                                                                                                                             |
| --------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Round driving               | kick leaves the main conversation to `subagent_spawn` → `wait_all` → `get_result` → maybe `steer` and back to wait (the inner loop is unconstrained by budget) | Only after ①②③ does the server inject "this round's finished executor account + round N/M" into the main conversation, which **only reviews**                                                                                                                            |
| Main conversation occupancy | The whole execution period (possibly tens of minutes) sits in one long turn, and the user cannot use it normally                                               | Only review turns are occupied; the main conversation is idle during execution and the user chats as usual                                                                                                                                                               |
| Round budget                | The inner loop escapes it; `stagnantRounds` only sees one diff at the outermost level                                                                          | Every round has its own diff fingerprint and error-signature sampling (§4.5)                                                                                                                                                                                             |
| Review read-only            | The main conversation must be **temporarily** set to `read-only` and then restored (guarding against overwriting a manual user switch)                         | **Not needed**: execution and review phases are separated, and write tools in the review turn are still rejected (same as above, but the restore window is tiny and the server restores right after ⑤); if that is too much trouble, PR-3 can rely on the contract alone |
| Input conflict              | User messages get `steer`ed into the review turn (semantic conflict)                                                                                           | The review turn lasts one model round trip (usually tens of seconds), and user messages queue as `followUp` meanwhile                                                                                                                                                    |
| Cost                        | —                                                                                                                                                              | Added constraint: `onAgentEnd(main)` is read as a verdict only while the server holds the `awaiting_verdict` flag; otherwise it is treated as a normal conversation (a user interjection) and ignored                                                                    |

The main line is still the six steps of §4.2, only ① swaps its slot for the subagent and ④ swaps its slot for the main conversation. Suits users who say "I set a goal and walk away, but I want to see what it is reviewing".

### 5.3 🕯 `self`: no reviewer (**today's default behavior, kept**)

- The existing path when `reviewModel === null`: the main model self-reports the `GOAL_COMPLETION_RE` marker → pass; `sameErrorRounds/stagnantRounds ≥ 2` → blocked; otherwise continue (`:1231-1281`).
- Why keep it: zero extra sessions, zero extra tokens, still needed by DSH and lightweight users; and "self-reported markers are unreliable" is exactly what §5.1 solves — you do not fix it by deleting the fallback.
- Relation to 2.0: `self` is **the degradation target** (quota full / role lost / user turns role mode off), so it must stay healthy.

### 5.4 👥 Dual agents (not doing it)

Both roles as subagents, leaving the main conversation with nothing but orchestration — nothing is visible there, and the user has to jump back and forth between two badges. **Not justified, not implemented**; if it is needed later, §4's abstraction supports it naturally (both slots `spawned=true`) with no rework.

## 9. Risks and rollback

| Risk                                                                                                            | Mitigation                                                                                                                                                                                                                                                                                 |

### 11.3 Key implementation details (landmines already hit)

- **spawn delivery is fire-and-forget**: inside `spawnSubagentConversation`, `sendUserMessage` is not awaited, so the server's immediate "wait for this turn to end" misreads "not started yet" as "already finished" (empty sample → the next round's dispatch collides). Fix: `conv.kickoff` records the delivery Promise + a 3s startup grace in `waitConversationTurnEnd`.
- **`steerSubagent` silently no-ops on a vanished session**: every step of the loop checks existence with `hasConv` first, and a lost role closes as `blocked` (no silently substituting a "new person" to continue).
- **Measurement definitions**: the stagnation fingerprint consumes the workspace `git diff` (same cwd as the main conversation), the error signature consumes **the executor conversation** (the `errorSnippet` returned by `readRoleAgent`) — the main conversation is the reviewer, and its tool errors do not mean execution is struggling.
- **User interjections**: `waitMainIdle` runs before delivering the review instruction (wait for the main conversation to go idle, at most one deadline), otherwise it gets injected as a `steer` into the user's own turn.
- **Generation guard**: `stopDelegated` wakes verdict waiters with `gone`; a late verdict is dropped because `awaitingVerdict` is already cleared / the generation does not match (covered by unit tests).
- **"Abort / close means stop"**: when `waitRoleAgent` returns `canceled` (the subagent was ⏹/aborted) or `gone` (the conversation was removed / the service restarted), the loop **closes immediately** and does not steer another round; only `error` / `timeout` (recoverable failures) proceed to the next round within budget. After stopping, the goal bar's 「■ 停止目标」 is clickable at any time.
- **The collapsed state is a pill, not a panel**: when collapsed, `GoalBar` renders only `.goalbar-collapsed` (**deliberately without the `.goalbar` class**) — `.goalbar`'s border/background/radius/padding are all superfluous when collapsed, and a theme drawing `.goalbar { border-top: … !important }` produces a band spanning the whole column across the last message, cutting it off (reported as "when collapsed a full-width row covers the bottom message"). The pill row carries `min-width:0` + `max-width:100%` + `overflow:hidden`, so plugins contributing items to the pill row cannot widen it either. Guard: `tests/unit/goalbar-collapsed-pill.test.ts`.

### 11.5 Known leftovers / follow-ups

1. **Reviewer read-only gate not enabled** (half of D2): the main conversation is the user's own session, so review turns rely on the contract's 「只读核实」 constraint and do not temporarily change its `permissionPreset`. A hard gate requires implementing "set permission by convId" (already listed as a callback in §4.4).
2. **Takeover**: the executor conversation moves with the parent (`collectSubagentDescendantIds`) but `goal` state does not → the new holder must re-set the goal; no automatic resumption.
3. **Service restart**: goal state is in-memory (lost on restart); the executor conversation **is persisted**, so its transcript can be reviewed in history, but the loop does not resume automatically.
4. **Plan linkage (#389 Phase 1)**: done (see B8 — the review contract carries `describePlan`, wizard output carries the step board).
5. **DSH engine**: still its own goal implementation (model self-judgement + round-driver), not wired to executor-conversation mode; the `reviewPrompt` setting still applies to it.
