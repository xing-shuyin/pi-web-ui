The top-left 「所有设备」(All devices) popover: structural rebuild

The problem is not the palette, it is the structure: three text buttons squeeze the name column down to 40px and Chinese names end up wrapped one glyph per line; in a 560px-wide card, half the width goes to buttons. After the rebuild: high-frequency actions stay on the row (open / remote desktop) and only low-frequency ones move into ⋯, names get the full readable width, the panel goes 560 → 328px, a row 96 → 45px; on narrow screens it becomes a bottom sheet with 44px touch blocks, and every frequent action stays at ≤ 2 taps.

What shipped
  • Shipped as option B (minimal single line) + a mobile bottom sheet: web/src/components/DevicePanel.tsx (new), DeviceDirectory.tsx (data + variant="panel"), BrandDeviceMenu.tsx (popover / sheet container), use-coarse-pointer.ts (single source for the breakpoint) and the .dp-* rules in styles.css.
  • One deviation from the mock: the second action at the row end shipped as remote desktop (the mock drew ↗ "open in new tab"). The row itself is already the entry point for opening a device, so ↗ duplicated it; remote desktop is the second-most frequent action and does deserve its own entry point. The ⋯ menu therefore only holds "set note / copy device ID".
  • Measured: desktop popover 264 × 221px (6 devices), row 30px, icon 24px; mobile row 56px, touch block 44×44, the sheet scrolls inside 62dvh, pull-to-refresh gesture wired up.
  • Tests: tests/unit/device-panel.test.ts (5 cases: compact row / whole-row open / row-end remote desktop / ⋯ menu / touch edit bar) and brand-device-menu.test.ts (new sheet cases: closing via the scrim and Escape).

01Diagnosis: 4 structural problems

Every symptom visible in the screenshot, mapped line by line to the code (web/src/components/DeviceDirectory.tsx).

01
Buttons eat the name column and Chinese names wrap glyph by glyph

The row is flex: icon 38 + status pill ~62 + three text buttons ≈ 336 + gaps, ~470px in total, which leaves a few dozen pixels for the name — and .dd-identity strong carries overflow-wrap: anywhere → one glyph per line (that is the cdeMa / c / mini.lo / cal in the screenshot).

02
The 「所有设备」(All devices) header eats 1/3 of the height

38px icon + two lines of copy (title + "Devices on the same account, reached directly with this machine's binding grant.") + 24px bottom gap ≈ 84px. That sentence is a one-time explanation; it has no business living in a popover you reopen every day.

03
No hierarchy: one device carries 3 buttons of equal weight

「修改备注」(Edit note) / 「打开设备」(Open device) / 「远程桌面」(Remote desktop) carry identical visual weight, and a low-frequency action like editing a note sits right next to the most used one. Real usage is heavily skewed: open ≫ remote desktop ≫ note.

04
Note editing splits the row in two and the whole block jumps

The form is appended at the end of the row with width:100% + flexWrap:wrap; the input is minWidth:180px and two text buttons ride along, so the editing state doubles the height — the list jumps up and down.

Interaction and accessibility

Primary vs secondary actions

  • Primary: click row → open device (most frequent, one step)
  • Secondary: ↗ icon → open in a new tab (middle click / Ctrl+click works)
  • Low: ⋯ → remote desktop, note, copy ID
  • Offline device: the row stays clickable but carries a title="device offline" hint, and failures show an inline notice rather than a global error

Semantics / keyboard

  • The row is an <li> plus a full-row <a class="row-hit"> (avoids illegal button-inside-button nesting)
  • Icon buttons stack above the a (z-index + position:relative)
  • Tab order: row → ↗ → ⋯; aria-haspopup="menu", aria-expanded
  • focus ring: 2px --accent, shown only on :focus-visible

Long text / extreme values

  • The trio: min-width:0 + overflow:hidden + ellipsis (no more glyph-by-glyph anywhere wrapping)
  • 200-char device name → ellipsis on one line, full text in the tooltip
  • Empty note → the sub-line falls back to the ID; note deleted → saving an empty string clears it
  • 20 devices → the panel scrolls internally (max-height: min(60vh,420px))

Density trade-off

  • A: still comfortable at ≥3 devices, complete information (name + ID + status + this device)
  • B: switch to the single line from 5 devices up; same data, only variant changes
  • Both share the row component and its events, so switching costs nothing

04Mobile: a sheet, touch first, frequent actions out of the menu

Copying the desktop popover onto mobile breaks in two hard ways: there is no hover (a hidden icon is an undiscoverable icon), and the top-left corner is not thumb territory (once the popover opens, neither finger reaches comfortably). So narrow screens change shape: tap the top-left chip → a sheet rises from the bottom, rows are 56px, every frequent action gets a 44px touch block, two taps at most.

    Note: today's gap is not only the tap count — it comes with wrapping buttons, vertically stacked names and scrolling. The table only compares "can it be done in one go". The same tap count over a shorter path (no need to read three text buttons) is a win too.

    Taps that can be deleted

    • Remote desktop leaves ⋯: it is the second-most frequent action, and hiding it in a menu turns it into 3 taps
    • The note drops its Save button: Done/Enter on the keyboard saves, long-press goes straight into editing
    • Refresh becomes a pull: a sheet should pull anyway, so the tap goes away for free
    • Closing needs no button hunt: swipe down or tap the scrim, any thumb position works

    What we will not trade away for fewer taps

    • Never hide a frequent action: an entry point that needs hover or a long-press is only allowed for low-frequency features
    • No double-click: it collides with "open", and system-level gestures get eaten by the browser
    • No confirmation dialog: opening a device is reversible, it does not need a modal
    • No menu inside a menu: ⋯ holds one level, never "⋯ → more → ⋯"

    One more step to save (optional, needs product sign-off)

    • If "open this device" dominates: on mobile one tap on the chip = jump straight back to this machine, long-press the chip = open the sheet (1 tap)
    • Focus the first row when the sheet opens (external keyboard: Enter opens it directly)
    • Remember the last choice: the most recently used device sits on row two, so the usual path stays on the thumb's first screen

    Desktop and mobile share one row component and one set of events; only the container (popover / sheet) and the size tokens change. pointer: coarse switches to the touch layout automatically, with no second component to maintain.
