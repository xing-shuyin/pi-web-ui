把「Source Control」从 命令菜单 改成 可读的状态机

现在的 Git 面板能把活干完，但读不出来"现在该做什么"：分支、上游差、暂存状态、提交上下文全挤成一排小图标， 真正要用的动作（Pull / Push / Fetch / Checkout / Stash / Tags）藏在一个 16 项平铺的右键菜单里。 下面三套方案都把 GitHub 已经验证过的心智模型搬过来——状态条说清"差多少"、文件列表按暂存分组、动作按意图分组—— 每套都给出可点的静态原型、改动面和风险。

现状诊断

基于截图（VS Code 式 Source Control）与 web/src/components/SCMPanel.tsx 现有结构

四个具体问题
  • 菜单即功能表：右键菜单 16 项平铺，Pull/Push 同时出现在两处，Clone 与本地仓库动作混排，无搜索、无分组、无快捷键提示。
  • 暂存状态不可见：文件列表不区分 staged / unstaged（只有 x/y 两个字母），用户无法"逐文件勾选再提交"。
  • 同步差是装饰：↑2 ↓0 是灰色小字，没有对应的动作按钮；不知道该 Push 还是 Pull。
  • 提交区没有上下文：输入框 → Commit 按钮，缺少"这次提交包含几个文件、多少行、提交到哪个分支、是否 amend"。
现有能力（不用重写后端）
  • 查询：scm_status / history / filediff / commit（server/files-service.ts → scmQuery）。
  • 动作：全部经终端桥 runGitCommand() 执行 git add -- <path> / git reset HEAD -- <path> / commit --amend / stash push|pop|apply|drop。
  • 已有 fileKind(f)（line 83）能把 x/y 归到 staged / unstaged / untracked / both —— 只是没被 UI 用起来。
  • 缺的只有 fetch / clone / tags / remote / checkout-to-commit，加命令即可，协议与权限模型不变。

从 GitHub 借的 6 条

不是抄配色，是抄信息层级与命名

1 · Sync bar 代替箭头
GitHub Desktop 顶部一条 Fetch origin / Push origin ↑2 / Pull origin ↓1 智能切换按钮：差多少直接写在按钮上。
2 · 文件行 = 勾选框 + 统计条
每个文件前面一个勾选框（= 暂存），行尾 GitHub 的 5 格 stat 条 + +12 −3；悬停才出现破坏性动作。
3 · 提交图是时间线，不是列表
History 用"日期分组 + 圆点 + refs 徽章"，与 GraphQL 式 main / origin/main 徽章并置，一眼看出是否已推送。
4 · Diff 是可检阅的
Unified / Split 切换、Viewed 勾选、行号为锚点的评论按钮、Files changed 12 的绿红比例条。
5 · 动作可搜索
⌘⇧P 命令面板：分组 + 描述 + 快捷键，替代平铺菜单；右键只留最常用 5 项。
6 · 状态即结论
✓ 3 checks passed / Conflicts 1 用徽章一次性给结论，不用读日志。

落地顺序（可分 3 次提交）
  1. 抬单源：把 SCMPanel.tsx:83 的 fileKind() 串到 web/src/scm-file-kind.ts，补单测（后续分组、TransitionCount 全用它）。
  2. 分组 + 勾选：仅前端 + 现成 git add -- <path> / git reset HEAD -- <path>，无协议改动。
  3. 同步条：pull / push 复用，新增 fetch 一条；按 ahead/behind 切换主按钮文案与颜色。
  4. 提交区常驻：文件数 / 行数由已暂存集合推导（不要在组件里再存一份计数）。
  5. ⌘⇧P 面板：替换 gd-more；动作表与快捷键表同源，避免两处漂移。
  6. 全屏 review（方案 B）：单开一个需求，补 scm_commit_files 后再做，不影响前五步。
落地时要守的红线（否则 CI 会拦）
  • 强调色实底上的文字必须用 --accent-contrast（Commit 主按钮、勾选框选中态）——accent-contrast 守卫。
  • 路径长文本三件套：单行 ellipsis + min-width:0 + 悬停 title 全路径——text-wrap 守卫。
  • 命令面板属于叠栈浮层，z-index 一律走 useOverlayZIndex()，禁写死数值——overlay-stack 守卫。
  • 新增文案走 scm* 前缀 i18n key，中英包同步（npm run i18n 校验）。
  • 不涉及插件，无需 bump manifest.json；不新增可开关工具，无需改 catalog。
荐

A + C 组合（2.5 天）

A 把“每天都做的三件事”（暂存、提交、同步）做成零点击的可见状态；C 把“偶尔才用的十几项”做成可搜索的命令面板。两者互不依赖，可以分两次提交：先 A（可见收益最大），再 C（顺带删掉那个 16 项菜单）。B 单独排期，等前两步上线、确认侧栏已能覆盖 90% 场景后再做。

本页为静态原型：无真实 git 调用，勾选 / 切换 / 搜索均为本地模拟；所有尺寸与色值取自 web/src/styles.css 的 :root。
