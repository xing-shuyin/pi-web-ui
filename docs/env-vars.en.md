# Environment variables

`PI_WEB_LOAD_TIMING=1` enables server-side phase timing for opening a historical conversation (off by default; `true` / `on` / `yes` also accepted). The server console prints `[load-timing]` JSON covering the repair, SDK open, branch calibration, preview, runtime init, bind and snapshot send phases, without session paths, IDs or message bodies. It does not measure browser rendering or network delivery. See [loading performance](loading-performance.en.md).

## Device Center remote desktop

| Variable                  | Default                                            | Purpose                                                                                                                                                                                                             |
| ------------------------- | -------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `PI_DEVICE_DESKTOP`       | empty (off)                                        | `1` force-enables the local native remote desktop; when unset it reads the enable preference from `<dataDir>/desktop-settings.json`, off by default. A local off preference cannot override an env-forced enable.   |
| `PI_DESKTOP_SERVICE_AUTO` | empty (auto)                                       | On Windows x64, installs/updates the bundled desktop component during a global install and interactive start; `0` disables auto-install. Requires admin authorization and does not change the remote-access toggle. |
| `PI_DESKTOP_FFMPEG`       | `bin/ffmpeg/<platform>-<arch>/ffmpeg(.exe)` → PATH | Absolute path to the ffmpeg used by the H.264 desktop channel; absolute paths only, for debugging or your own build with NVENC. Falls back to JPEG when missing.                                                    |

Remote desktop follows [krd](https://github.com/zzjcool/krd)'s native capture and input injection approach; frames and input reuse the existing WebSocket relay, so no noVNC, VNC server or extra desktop port is needed. Windows uses GDI + SendInput; macOS uses a native Swift helper that captures via ScreenCaptureKit `SCScreenshotManager` and injects input through CoreGraphics, requiring macOS 14+, the Swift CLI and screen recording permission (plus accessibility permission to control); Linux X11 uses ffmpeg + xdotool, and xdotool is optional for view-only. Wayland is not supported yet and will need Desktop Portal integration. Read-only is enforced by the backend.

The old `PI_DEVICE_VNC_*` environment variables are retired and no longer read; there is no need to configure a VNC address, port, password, path or noVNC install directory. See 「浏览器远程桌面」(browser remote desktop) in `docs/device-center.md`.

## SSH host authentication

Remote workspaces and the official SFTP plugin verify `~/.ssh/known_hosts` by default; `PI_WEB_SSH_KNOWN_HOSTS` can point at another OpenSSH known_hosts file. Unknown, changed or `@revoked` host keys are rejected before authentication, and the program never adds trust automatically. Plain and hashed host records, non-default ports and aliases are supported; host certificate trust based solely on `@cert-authority` is not supported yet — pre-provision the concrete host public key.

First-time setup: verify the host fingerprint independently via the server console or an administrator, then run `ssh -o StrictHostKeyChecking=ask -p <port> <user>@<host>` under the same account that runs the service and confirm only when the fingerprint matches; alternatively pre-provision the independently verified public key record into the file above. Downloading a public key or running ssh-keyscan is not authentication. The connection address and port must match the record.

## Local config page (no command line)

After startup visit `http://127.0.0.1:<port>/setup` (**loopback only**; non-local requests get a 403 outright, and it is not behind token auth — it is exactly what you use to reset a forgotten secret).
Configurable: access token, listen host, port, Host allowlist, extra Origin allowlist.
Persisted to `<dataDir>/server-config.json`, precedence: command-line flags > environment variables > this file > defaults.
Token changes apply immediately (WS included); host/port/allowlists need a `pi-web-ui server restart`.

## Device-to-device P2P

| Variable                    | Default                                                                                | Purpose                                                                                                                                      |
| --------------------------- | -------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------- |
| `PI_DEVICE_P2P`             | enabled when a helper is available                                                     | `0` disables P2P, keeping the LAN and Hub fallbacks                                                                                          |
| `PI_DEVICE_P2P_STUN`        | `stun:stun.l.google.com:19302,stun:stun.miwifi.com:3478,stun:stun.cloudflare.com:3478` | Up to four comma-separated STUN addresses, probed in parallel; a self-hosted coturn works too                                                |
| `PI_DEVICE_TURN`            | empty (off)                                                                            | Up to three comma-separated `turn:` / `turns:` addresses; both ends must configure it. The only way to connect directly behind symmetric NAT |
| `PI_DEVICE_TURN_USERNAME`   | empty                                                                                  | TURN long-term credential username; must be paired with `PI_DEVICE_TURN_CREDENTIAL`                                                          |
| `PI_DEVICE_TURN_CREDENTIAL` | empty                                                                                  | TURN credential password; an address without credentials is a hard config error, never a silent fall back to no relay                        |
