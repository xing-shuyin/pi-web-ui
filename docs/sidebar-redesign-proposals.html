左侧栏「运行中 + 历史会话」重构方案全景
解决双滚动条挤压 · 解决当前项重复 · 提升 Agent 监控感知
pi-web-ui
用户截图暴露的四大视觉与体验痛点
1. 双滚动条垂直“硬割裂” 上面 5 个运行中占用一截高度并出滚动条，下面 200 条历史又出滚动条，互相挤压抢高度，两边都看不完整。
2. “当前会话”在两个列表里同时重复 「我想测试下群组...」在上面运行列表中出现一次（标当前），在历史列表中又出现一次，凭空浪费两倍高度。
3. “运行中”无实时感知 既然是并发后台运行的 Agent，无法直观知道谁在流式输出、谁在等待用户决策(Question)、谁在报错，视觉全是一样的灰色卡片。
4. 历史 200 条无法快速检索 一马平川的长列表没有「今天/昨天/本周」时间维度分割，也没有即时搜索框，找历史对话如大海捞针。
👑 极致零占地方案：原位替换架构 (In-place Replacement) 不占1像素空间 · 无呼吸灯 · 状态一目了然
跳出“做加法（加标签、加边条、加区域）”的思维误区，改做“原位替换（In-place Reuse）”！
利用现有卡片本就存在的「左侧 16px 图标位」和「第二行辅助信息位」，在不同状态下无感切换，标题享受 100% 原始横向空间，绝无半点压迫感。
1️⃣ 左侧已有图标位「原位替换」
原本的灰色气泡纯属占位。现在：
• 执行中：原位变为纯单色静态闪电 ⚡（无任何闪烁/呼吸）；
• 待用户确认：原位变为单色琥珀问号 ?；
• 空闲/历史：保持微弱灰色气泡。
横向 0 额外像素！
2️⃣ 现有第二行文本「原位替换」
卡片第二行本来就写着 443 条消息 或时间。
• 执行时直接原位显示高亮绿字：执行中 · 38s；
• 待答复时直接原位显示暖金字：等待你的确认；
• 历史保持显示消息数与时间。
纵向 0 额外行高，不撑大卡片！

📐 两种设计方式对横向标题空间的巨大影响：

❌ 传统加标签（压缩标题）
标题后挂上 [执行中] 或 [待确认] 徽标，导致标题横向空间被硬削掉 60px，原本能完整显示的标题被提前截断为：
「我想测试下群组... [执行中]」
✅ 零占地原位替换（完整标题）
标题享用 100% 完整可用宽度，状态由左侧图标和第二行自然表达，标题完整舒展：
⚡ 「我想测试下群组的功能,但是不知道出个什么合适」
⭐ 终极融合方案：分段选项卡 (Tabs) + 智能状态胶囊 (Filter Chips) 用户选定方案 · 体验天花板
集方案 1 的「100% 全高独占视窗 + 彻底消灭双滚动条」与方案 3 的「微状态胶囊过滤 + 智能去重 + 运行态高密度感知」于一体。
在【⚡ 运行中】专注多 Agent 状态调度与即时干预；在【🕒 全部历史】专注精准检索、时间线归纳与零重复展示。
⚡ 【运行中】专属：状态胶囊过滤 + 实时任务监控
顶部提供横向状态过滤胶囊：[ 全部 5 ] [ 执行中 2 ] [ 待答复 1 ] [ 空闲 2 ]。
每个卡片呈现高密度实时反馈：当前调用的工具名、耗时、快捷一键直达与中断。
🕒 【全部历史】专属：即时检索 + 智能去重 + 时间线归纳
顶部集成实时搜索输入框，支持拼音与关键词快速过滤。
智能去重机制：当前活跃会话在历史列表中以轻量提示呈现，不再生成双份大卡片；按「今天」「昨天」「更早」分组折叠，200 条会话井然有序。

🛡️ 彻底告别呼吸灯 · 3 种高质感静止表达形式（左栏可即时切换预览）

形式 A：静止微标签 (默认)
采用类似 Linear/GitHub PR 的微型文本徽标：执行中 待确认 ?，信息明确，零动态闪烁打扰。
形式 B：侧边细色条
采用类似 VS Code 的卡片左侧 2.5px 静态强调线（执行中为翠绿、待确认为琥珀金），最适合极简主义者。
形式 C：极简语义字符
采用类似 JetBrains / 键盘键帽的静态微字符：▶ ? ✓，极客感强。
⚠️ 当前现状：双重滚动条与空间撕裂 痛点显微镜
当前实现将侧边栏纵向硬生生切成了两半（sash 拖拽分割）。当并发任务多于 3 个且历史积累达到 200 条时，两个独立的内嵌滚动条同时出现，空间支离破碎。
↕️ 两个滚动条互相打架
在日常鼠标滚轮操作中，指针稍有偏移就会滚错区域。上半部分被硬截断，最底部仅能露出文字的半截（如用户截图中的 xz）。
🔄 同一会话上下重复占位
当前正在聊天的会话，既在顶部的「运行的对话」里占一个卡片，又在底部的「历史对话」顶部占一个卡片，逻辑混乱且浪费宝贵的垂直视线。
方案 1：分段选项卡架构 (Segmented Tabs + 单一全高主画布) 体验最优解 · 彻底根除滚动条打架
借鉴 Linear、Arc 浏览器与现代 IDE 视窗设计。将「纵向拆分双滚动条」升级为「水平分段透视」。 侧边栏在任意时刻都拥有 100% 完整的垂直高度，再也不会被截断或露出半截文字。
⚡ 运行中专属「任务中控 (Mission Control)」
切到【⚡ 运行中 (5)】时，列表不再是冷冰冰的标题，而是高信息密度的任务卡：显示绿灯呼吸动画、正在调用的工具名（如 patch-bash-process）、耗时和快速中断按钮。
🕒 历史记录具备时间分段与秒级过滤
切到【历史】时拥有顶部即时搜索框。长达 200 条的历史自动按照「今天 (4)」、「昨天 (7)」、「上周 (18)」进行视觉分段，条理极其清晰。
方案 2：顶置微型监控坞 (Live Activity Dock) + 历史主轴 极客监控感 · 类似 iOS 灵动岛 / VS Code Debugger
运行中的 Agent 本质上是“正在进行的短期活动”，不需要占据和历史列表等高的并列大窗。 通过将其收拢为顶部的紧凑胶囊（Live Pill），让历史会话保持自上而下的自然大单流。
🔔 待审批/问答优先浮起
如果有会话正在等待用户答复（例如 ask_user_question 或执行授权），胶囊卡片呈现琥珀色呼吸灯，并置顶于监控坞第一位，一键直达处理。
📐 极低空间占用
常态下只占用顶部 60px~100px 高度；空闲或没有运行任务时自动隐去，历史会话自动顶格展示。
方案 3：智能融合时间流 + 活跃置顶 (Smart Stream & Auto-Pin) 自然直觉 · Slack / Telegram / Raycast 风格
打破「运行」与「历史」的物理二元隔阂！所有会话在一个单一列表中，按照活跃时间智能排布。 当前正在运行的会话通过流光边框、发光徽标自动置顶在最上方，结束后平滑沉降至历史区，绝不重复出现两遍。
🏷️ 快捷胶囊过滤器 (Filter Chips)
顶部提供横向滑动胶囊：全部 205、⚡ 活跃 5、❓ 待决策 1、⭐ 星标 3。点击瞬间筛选，无需切页。
🔄 状态平滑过渡，零认知负担
用户无需思考“我现在是在找运行中的还是找历史的”，所有东西都在一个时间轴上，符合人类大脑最自然的记忆规律。
方案 4：项目/工作区聚合树 (Workspace Tree & Multi-Agent Matrix) 大型多仓库开发 · 多端协同首选
在多项目或使用设备中心（跨端同步/群组协同）时，会话很容易出现同名混淆（如截图中的两条“架构重构”）。 以「项目/工作区」为第一层级聚合，内部再分设运行中与归档。
🌿 会话归属感清晰，杜绝同名混淆
清晰看出每个项目各自正在跑几个任务。即使在不同分支或子模块跑同名任务，也井井有条。
👁️ 悬停预览穿透 (Hover Peek)
鼠标悬停在卡片上，右侧弹出轻量气泡预览最后一轮对话结论，无需点击切换打断当前工作流。

🚀 推荐落地路线（建议采纳方案 1 或方案 1+3 的融合版）

  1. 第一阶段（立竿见影）：改垂直分割为 Segmented Tabs。在 LeftPanel.tsx 顶部加入 [ ⚡ 运行中 (5) ] 和 [ 🕒 历史记录 (200) ] 的药丸切换，彻底去掉 sash 拖拽条和双独立滚动条。
  2. 第二阶段（解决重复）：消除当前会话的冗余展示。历史列表中如果该会话已经在「运行中」展开，历史中自动标记或默认不重复堆叠。
  3. 第三阶段（体验升级）：引入时间段分组与轻量搜索框。200 条历史根据 lastModified 自动划分「今天 / 昨天 / 7天内 / 更早」，并在列表顶部放置轻量 filter input。
