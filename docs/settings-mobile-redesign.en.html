Mobile settings redesign · three interactive options

Today: settings is a 960px-wide desktop dialog, and mobile crams 21+ tabs into one horizontal pill rail (inside @media (max-width:640px), .settings-rail{flex-direction:row;overflow-x:auto}), while group titles and search are display:none. All three options share the same real tab inventory (no new product surface); they differ only in how the home screen lowers the cost of a jump.

9:41

Option A · Grouped home + push into second-level pages

A straight port of iOS Settings: large title → identity card → 6 group cards (3–6 rows each), with a current value replacing the bare chevron on each row. Second-level pages slide in from the right and the save state lives at the right end of the nav bar.

Why we recommend it

Scanning
7 rows plus 5 group titles per screen, eyes stay on the left-hand labels — built for "find a feature", not "read content"
Touch
56px rows, one 44px+ hit area per row, so nobody has to hit a 30px dot to flip a switch
Mental model
Isomorphic with iOS Settings, zero learning cost, and the back gesture comes for free
Cost
Lowest: the existing tab state maps straight onto a "stack"; one new mobile block in the stylesheet is enough

Cost / trade-offs

Jumps
Changing one value costs 2 jumps on average; the value preview only rescues read-only confirmation
Long tail
The 21 tabs still need groups to carry them, and a newcomer may never find "Approval rules"
Mitigation
Search always pinned at the top + counts on group titles + recently changed items floating up (recorded locally, no collection)

Try it

Tap a row to enter its second-level page (the back arrow returns); switches flip directly; in option A, "Reset & destructive actions" is reached from the bottom of the About page or from the last row of the home screen. Switch the demo to "Save failed" to see the red receipt at the top and the retry.

The options differ only in the home shell:

  • A: 6 group cards + identity card, all expanded by default (everything exposed, fastest scanning).

4.1 State-by-state notes

  • Default: row 56 tall, icon pedestal 28, right value 13px in --text-dim, chevron 16px; at most one accent colour per screen (switch on / selected), everything else rests on hierarchy and whitespace.
  • Pressed: :active → background --fill-press (7% white on dark / 6% black on light) + tile scale(.975), 120–160ms; no ripple, no change in shadow.
  • Disabled: aria-disabled="true" + icon at 45% opacity + label in --text-faint + the chevron stays; the secondary copy must spell out why it is disabled and where to fix it.
  • Loading: first entry shows a skeleton (not a spinner), aria-busy="true" + aria-label="Loading settings"; once content exists, changing a value updates only that part — never a full-page flash.
  • Empty: no search results → icon + "No setting matches “XXX”" + suggested keywords + a "Clear search" button. Never write information-free copy like "No data yet".
  • Switch: on = --accent track + the dot slides 20px right; off = --track-off. The copy layer also exposes aria-checked, so colour never speaks alone.
  • Entering a second-level page: a 220ms translateX(16px)+fade push; going back runs the reverse. Android uses the system back key; on iOS also enable the edge-swipe back (cheap to implement, see the rollout checklist).
  • Destructive actions: the row is only an entry point → second-level page → tapping the action brings up the bottom sheet (the title restates the object + the consequences + whether it is irreversible); the confirm button is solid red, cancel sits below and is taller; do not use a system Alert with side-by-side "OK / Cancel" — thumbs misfire on it.
  • Save policy: everything applies immediately, there is no Save button. The 28px pill at the top reads Saved / Saving… / Unsaved · retry; on failure a red banner (role="alert") and a red row appear together, and tapping either retries. This matches the receipt semantics of the existing useSettingsSync.
  • Search: always resident on the home screen (never collapsed into an icon). Scope = row label + secondary copy + group name + second-level title + keyword aliases (reusing the Chinese/English aliases in TAB_KEYWORDS). Input is debounced 200ms, result rows carry a group breadcrumb ("· Everyday"), and toggles can be flipped right in the results.

5Visual brief for Figma / AI design tools

The whole block can be pasted straight into Figma Make / v0 / Cursor.

Artboard: iPhone 15 (390×844, radius 46), status bar 54, Home area 34, with SafeArea auto layout; also produce 320×568 and 360×780 versions for adaptation checks.

Style: modern, restrained, trustworthy; take the information density from iOS Settings and the card whitespace from Material 3. Dark is the default (page base #0D0E12); light is a Light variant (#F1F2F6 base + pure-white cards + 1px #E6E8EF stroke + a very soft shadow). No large gradients — only the identity card's brand square may take a 150° purple→indigo gradient (#8B5CF6 → #6366F1).

Home screen, top to bottom: ① large title "Settings" at 30px/700, with a 28px-tall state pill on the right (6px green dot + "Saved" at 11.5px); ② search field 44px tall, radius 11, one elevation brighter than the page, 16px line magnifier on the left; ③ identity card, radius 12, 46×46 brand square + 16px title + 12.5px status line (7px state dot) + a 36px-tall outlined "Switch engine" button on the right; ④ 6 groups, each = a 13px/700 group title (#9AA1B4, 4px side inset) + card (radius 12, 1px stroke, 1px dividers indented 56px); ⑤ finally a separate "Destructive actions" card holding a single red-text entry.

Row: 56 tall, 16 side padding; at the left a 28×28 radius-8 icon pedestal (fill = the row's hue at 16% opacity, glyph 16px line, hue at 100%); in the middle the label at 16px/500, with an optional 12.5px secondary copy (two lines max, colour #9AA1B4); at the right the current value at 13px in the same colour, 42% width max and ellipsised beyond; far right a 16px chevron in #8B93A7. Toggle rows carry no chevron.

Hue assignment (icon pedestals, one consistent set): models = blue #60A5FA, prompt = blue, tools = purple #A78BFA, skills = amber #FBBF24, MCP = sky #38BDF8, approval = green #34D399, notifications = pink #F472B6, danger = red #F87171, everything else = grey #94A3B8.

Second-level page: a 48px nav bar (44×44 back on the left, 17px/650 title in the middle, the same state pill on the right), with identically styled group cards below; segmented control 36px tall, inset track, the selected item floating on a white fill at radius 8.

Confirm sheet: a bottom sheet with a top radius of 18, title 16px/650, explanation 13px, primary button 50px tall in solid red (dark text #1A1A1A in the dark theme to hold contrast), secondary "Cancel" outlined below. Scrim 58% black + 2px blur.

Forbidden: no stacked card shadows, no glassmorphism, no rainbow icons, no type below 8pt, no action that only appears on hover, no fixed bottom bar covering the last row (leave safe-area + 24 at the end of the list).

export const T = {
  rowH: 56, rowHSm: 48, touch: 44, padX: 16, gap: 16, radius: 12, iconTile: 28,

// SettingsHome.tsx
export function SettingsHome({ onOpen }: { onOpen: (page: PageId) => void }) {
  return (
    <SafeAreaView edges={['top', 'bottom']} style={{ flex: 1, backgroundColor: c.bg }}>
      <LargeTitle title="Settings" accessory={<SavePill />} />
      <SearchField placeholder="Search settings" onChange={setQuery} />
      <FlatList
        data={groups}                      // data-driven: group → rows, order is priority
        keyExtractor={(g) => g.id}
        renderItem={({ item }) => (
          <Section title={item.title}>
            {item.rows.map((r) => r.kind === 'toggle'
              ? <ToggleRow key={r.id} row={r} />
              : <NavRow key={r.id} row={r} onPress={() => onOpen(r.page)} />)}
          </Section>
        )}
        ListFooterComponent={<DangerSection />}
        contentContainerStyle={{ paddingHorizontal: T.padX, paddingBottom: insets.bottom + 24 }}
      />
    </SafeAreaView>
  );
}

// Row: one tap target per row; the switch is visual only
function ToggleRow({ row }: { row: Row }) {
  const on = useSetting(row.key);
  return (
    <Pressable
      role="switch"                       // TalkBack / VoiceOver announce "switch"
      aria-checked={on}
      accessibilityLabel={row.label + (row.desc ? ', ' + row.desc : '')}
      onPress={() => setSetting(row.key, !on)}
      style={({ pressed }) => [styles.row, pressed && { backgroundColor: c.fillPress }]}
    >
      <RowIcon icon={row.icon} tone={row.tone} />
      <View style={{ flex: 1, minWidth: 0 }}>
        <Text numberOfLines={1} style={styles.label}>{row.label}</Text>
        {row.desc ? <Text numberOfLines={2} style={styles.desc}>{row.desc}</Text> : null}
      </View>
      <Switch value={on} pointerEvents="none" accessible={false} />
    </Pressable>
  );
}

// Destructive action: entry → sheet → confirm
const askClearHistory = () => sheet.confirm({
  title: 'Clear input history?',
  body: 'All 238 input records will be permanently deleted; conversation content is not affected.',
  confirmLabel: 'Confirm delete',
  destructive: true,
  onConfirm: () => api.clearPromptHistory(),
});

// Accessibility and dynamic type
<Text maxFontSizeMultiplier={1.6} allowFontScaling style={{ fontSize: T.fs.label }} />

Rollout checklist (which files change)

  • Already shipped (option A, first cut): new web/src/components/settings-mobile/ — SettingsMobileHome.tsx (home: title + search + group cards), mobile-ia.ts (a pure tab→group function; an unknown group falls back to the last group so nothing is dropped), use-narrow-layout.ts (640px breakpoint), settings-mobile.css (full screen + safe areas + 56px rows).
  • Already changed web/src/components/SettingsModal.tsx: on narrow screens it adds the is-mobile / is-mobile-home classes, renders SettingsMobileHome as the home screen, and reuses the existing head (plus a back key and the current page title) and body for second-level pages; the desktop DOM and render path are unchanged. Groups reuse the existing TAB_GROUPS / GROUP_LABELS, with zero new copy and zero new i18n keys.
  • To change web/src/styles.css: drop the two "make mobile cope" rules .settings-rail{overflow-x:auto} and .settings-search-wrap{display:none}, and replace them with the new component styles + new tokens (--row-h / --touch / --group-gap). Mind the overlay-stack / accent-contrast / semantic-contrast guards: new colours must land in tokens, never hard-coded.
  • To change web/index.html: add viewport-fit=cover to viewport; change color-scheme from the fixed dark to light dark (or set it dynamically from the theme).
  • Add a guard tests/unit/settings-mobile-ia.test.ts: assert that every id in the SettingsTab union appears in the mobile group table — otherwise a new tab "disappears" on phones, and that class of regression is the hardest to notice.
  • Do not add: any new settings field, new product API, or new dependency (keep using react-icons/fi line icons, consistent with desktop).
