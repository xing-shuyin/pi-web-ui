# 根因整改：操作身份与提交边界

本文件记录跨模块必须保持的行为约束。具体审查证据见 `audits/root-cause-review-2026-10-29.md`。

## 工作树清理

工作树状态读取失败属于未知状态，不能用于授权删除。`getUncommittedCount()` 失败时返回保守的 dirty 状态与错误；非强制删除和子代理终态清理要求查询明确成功。

子代理终态清理只有在 status 成功且干净、HEAD 与创建时 baseCommit 相同时才自动移除工作树。在仓库操作锁内再次检查 HEAD，并执行非强制 Git 删除；Git 因并发修改拒绝删除时保留工作树并报告错误。分支删除使用 `update-ref -d <ref> <baseCommit>` 条件删除，避免清理时删除被并发推进的分支。

回归：`tests/unit/root-cause-worktree.test.ts` 通过破坏索引模拟 status 失败且 HEAD 可读，验证未知状态不删除未提交文件或分支；原有 `subagent-worktree.test.ts` 覆盖正常清理和保留路径。

## 调度、持久化与画布

插件 cron 的分片计时保留同一个 `dueAt`，仅在该时刻到期并执行后计算下一次。普通插件设置与加密后的 `setting:` secret 同存 **状态目录** `<dataDir>/plugin-data/<id>/storage.json`（代码目录 `plugins/<id>/` 是纯缓存，可被重新物化），以一次原子替换提交；内部 `__settingsSecrets` 为保留键，插件 storage API 不可读取或修改，旧 `secrets.bin` 仍作为未迁移项的兼容读取源。保存失败不通知设置回调或返回成功。

MCP 同文件改名一次原子提交；跨作用域迁移先写恢复日志、提交目标，再清理源。迁移失败保留至少一份记录，重复相同保存请求可以恢复；目标冲突或两端内容变化则拒绝恢复。原子写复用 `atomic-file.ts`，MCP 新文件默认 `0600`，支持刷新暂存文件；这不构成断电持久性承诺。

画布 WS 与工具删除统一经过 orchestrator：先使图生命周期代次失效并取消执行，再删除文件。异步完成和下游派发校验图、节点代次及执行对象身份；运行态保存只更新存在的工程。重复启动不得替换正在运行的图对象。

## 会话、目标与多引擎

目标设置在入口捕获操作代次，等待旧执行者清理后重新校验原代次及对象身份；清除、替换和关闭均能使等待中的旧设置失效。向导提交返回明确凭证，先提交计划，再持该凭证抢占和启动。

子代理创建需要贯穿父工具取消及稳定父运行身份，候选 runtime 提交前再次检查；同一会话的 interrupt/reset 共享在途操作，提交绑定原 runtime。审批取消使用稳定请求对象，展示 ID 及持有方迁移不改变一次性结算身份。

Universal 回合捕获会话对象与 cwd，结束后按该归属保存，禁止找不到旧会话时回退到 active；工作区切换先取消旧回合，并阻止切换期间新回合进入。DSH 重启必须显式传入目标 cwd，启动失败不能发布新工作区。

Claude 与 Durable 历史目录按引擎隔离并验证记录的 engine。缺少引擎标识的旧转录只导入展示消息，清除底层 `driverSessionId`，保留原记录；迁移标记防止用户删除后再次导入。

## HTTP 传输

`net-guard.ts` 的生产请求通过独立 undici dispatcher 将连接解析约束到校验过的 IP，保留原域名 Host、TLS servername 与证书校验。每次重定向重新验证并固定地址，取消前一跳正文；跨源跳转剥离凭据。截止时间覆盖 DNS、连接、重定向及正文消费。预设抓取与市场请求复用该路径，替换全局 fetch 不能跳过校验。

## 共同约束

- 异步工作在入口捕获稳定的运行对象与归属信息；跨等待恢复后不能读取当前 active/cwd 作为旧任务的归属兜底。
- 代次属于发起操作，不能在恢复时重新读取最新代次让旧操作继续提交。只有仍有效的操作才能发布状态、写运行态或派发后续任务。
- 取消、关闭、删除需要撤销执行资格；删除磁盘文件或隐藏 UI 不代表后台生命周期终止。
- 完整校验之后才产生持久副作用；持久提交成功之后才发布运行态与成功回执。损坏、不可读和不存在是不同结果。
- 存储身份包含必要的项目和引擎维度；不同引擎的底层会话 ID 不能直接互相恢复。
- 计时器保留本次 dueAt，分片等待不改变本次执行身份；执行之后才计算下一次。
- 网络预检查必须约束实际连接使用的地址；独立的 DNS 预检查不能作为 DNS rebinding 防护。

实现和测试应围绕以上边界验证故障、取消及交错执行，避免只在正常路径添加重复守卫。
