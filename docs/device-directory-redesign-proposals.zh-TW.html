左上角「所有裝置」浮層：結構重構

問題不在配色，而在結構：三個文字按鈕把名稱列擠成 40px，中文名被壓成逐字換行；560px 寬的卡片裡，一半寬度給了按鈕。 重構後：高頻動作留在行上（開啟 / 遠端桌面），只有低頻進 ⋯，名稱佔滿可讀寬度，寬度 560 → 328px，單行 96 → 45px； 窄屏換成底部抽屜 + 44px 觸控塊，常用動作一律 ≤ 2 次點選。

落地記錄
  • 已按 方案 B（極簡單行）+ 手機底部抽屜 實現：web/src/components/DevicePanel.tsx（新）、DeviceDirectory.tsx（取數 + variant="panel"）、BrandDeviceMenu.tsx（浮層 / 抽屜容器）、use-coarse-pointer.ts（斷點單源）與 styles.css 的 .dp-*。

01診斷：4 個結構性問題

截圖裡能直接看到的現象，逐條對應到程式碼（web/src/components/DeviceDirectory.tsx）。

01
名稱列被按鈕吃掉，中文名逐字換行

行內是 flex：圖示 38 + 狀態膠囊 ~62 + 三個文字按鈕 ≈ 336 + 間距，合計 ~470px，留給名稱的只有幾十畫素，而 .dd-identity strong 帶 overflow-wrap: anywhere → 每個字單獨一行（截圖裡的 cdeMa / c / mini.lo / cal）。

02
「所有裝置」頭佔了 1/3 高度

38px 圖示 + 兩行文案（標題 + 「同一賬號下的裝置，使用本機繫結授權直接訪問。」）+ 24px 下間距 ≈ 84px。這句話是一次性解釋，不該常駐在一個每次點開的浮層裡。

03
主次不分：一件裝置有 3 個同權重的按鈕

「修改備註 / 開啟裝置 / 遠端桌面」視覺權重完全相同，而且「修改備註」這種低頻操作和最常用的「開啟裝置」並排。真實使用頻率極度傾斜：開啟 ≫ 遠端桌面 ≫ 備註。

04
備註編輯把行撐成兩段，編輯時整塊跳高

表單用 width:100% + flexWrap:wrap 追加在行末，輸入框 minWidth:180px，加上兩個文字按鈕，編輯態高度直接翻倍 —— 列表上下跳動。

互動與可達性

主次動作

  • 主：點行 → 開啟裝置（最高頻，一步到位）
  • 次：↗ 圖示 → 新標籤開啟（可中鍵/Ctrl 點）
  • 低：⋯ → 遠端桌面、備註、複製 ID
  • 離線裝置：行仍可點，但先給 title="裝置離線" 提示，失敗時用行內 notice 而非全域性報錯

語義 / 鍵盤

  • 行用 <li> + 覆蓋整行的 <a class="row-hit">（避免 button 套 button 的非法巢狀）
  • 圖示按鈕在 a 之上（z-index + position:relative）
  • Tab 順序：行 → ↗ → ⋯；aria-haspopup="menu"、aria-expanded
  • focus ring：2px --accent，:focus-visible 才顯示

長文本 / 極端值

  • 三件套：min-width:0 + overflow:hidden + ellipsis（不再 anywhere 逐字斷行）
  • 200 字元裝置名 → 單行省略，tooltip 全文
  • 備註為空 → 次行回落成 ID；備註全刪 → 儲存空串即清除
  • 裝置 20 臺 → 面板內滾動（max-height: min(60vh,420px)）

密度權衡

  • A：≥3 臺仍舒適，資訊完整（名稱 + ID + 狀態 + 本機）
  • B：裝置 ≥5 臺時切到單行；同一份資料，只換 variant
  • 兩者共用行元件與事件，切換零成本

04手機適配：抽屜 + 觸控優先，常用動作不進選單

手機上照搬桌面浮層會有兩個硬傷：hover 不存在（藏起來的圖示等於不可發現），左上角不是拇指區（浮層展開後兩個手指都難夠到）。 所以窄屏換形態：點左上角 chip → 從底部升起抽屜，行高 56px，每個常用動作一個 44px 觸控塊，最多兩次點選。

    注：現狀的差距不只在次數 —— 它還伴隨按鈕折行、名稱豎排、需要滾動；表裡只對比「能不能一步做完」。次數相同但路徑更短（不用讀三行文字按鈕）同樣是收益。

    能被「去掉」的點選

    • 遠端桌面不再進 ⋯：它是第二高頻動作，藏在選單裡就變成 3 次點選
    • 備註去掉「儲存」按鈕：鍵盤上的完成/回車即儲存，長按直接進入編輯
    • 重新整理改下拉：抽屜本來就該能下拉，順手省一次點選
    • 關閉不用找按鈕：下滑或點遮罩，任何位置的拇指都能關

    不能為了省點選犧牲的

    • 不隱藏高頻動作：靠 hover / 長按才能用的入口，只能給低頻功能
    • 不做雙擊：雙擊與「開啟」衝突，且系統級手勢容易被瀏覽器吃掉
    • 不做二次確認：開啟裝置是可逆操作，不需要確認彈窗
    • 不做選單套選單：⋯ 裡最多一層，不再出現「⋯ → 更多 → ⋯」

    還能再省一步（可選，需產品確認）

    • 若「開啟本機」佔絕大多數：手機端 chip 單擊 = 直接回本機，長按 chip = 展開抽屜（1 次點選）
    • 抽屜開啟時自動聚焦第一行（外接鍵盤 Enter 直開）
    • 記住上次選擇：最近使用的裝置排第二行，常用路徑穩定在拇指第一屏

    桌面與手機共用同一套行元件與事件，只換容器（浮層 / 抽屜）與尺寸令牌；pointer: coarse 命中時自動切觸控佈局，不額外維護一套元件。
