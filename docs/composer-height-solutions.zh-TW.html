輸入框高度自適應失控 & 正文遮擋治理

針對使用者反饋的「輸入框高度一直增加直到遮擋正文、無法下拉縮小、無文字時也被巨大保底撐滿」缺陷，從根因剖析、互動演進到工程落地的 4 套完善方案合集與可互動沙箱原型。

現行程式碼的 4 大致盲性邏輯缺陷（為什麼無法減小？為什麼空內容也撐滿？）

1. Math.max 產生“只能增不能減”死鎖

程式碼中寫了 Math.min(Math.max(scrollHeight, composerH), cap)。當用戶輸入長文本導致 scrollHeight 達 500px 時，向下拖拽把 composerH 降到 150px 根本無效，scrollHeight 始終死死頂住高度！

2. 720px 絕對畫素脫離視口安全保障

硬編碼了 COMPOSER_MAX_H = 720。1080P 或筆記本視口常只有 750~850px，輸入框加上工具條直接佔滿 100% 視口，將正文區（.messages）擠壓至 0px 徹底不可見。

3. localStorage 持久化“幽靈高度”

一旦拉高或誤觸，保底高度存入 localStorage。之後清空文字、新建對話，輸入框依然以 720px 撐開整個螢幕（如截圖所示無文字卻佔全屏），而“雙擊恢復”隱藏在隱形細線上無法被發現。

4. 抓手重疊與操作盲區

頂部拖拽條平時 opacity: 0，當輸入框被撐大到頂邊時，抓手與快捷短語藥丸嚴重重疊擠佔，滑鼠極易觸發短語點選，根本摸不到 14px 的細窄抓手。

方案 1 機制：視口百分比上限 + 雙向自由裁剪

徹底解決“只能變大不能縮小”以及“空文本霸屏”的黃金法則：

動態相對上限：摒棄 720px，採用 maxHeight = min(40vh, 320px)，正文隨時擁有 ≥60% 安全視口。
雙向真實控制：使用者拖動時，設定的是目標限高 userH。當 userH < scrollHeight 時，強制啟用內部縱向滾動 overflow-y: auto，讓使用者能隨時向下拉扁輸入框看上面的正文！
空狀態智慧回縮：無內容時始終緊湊（40px），使用者拖拽的高度僅作為“長文本時的容納上限”，決不再出現截圖中的巨型空框！
// ChatInput.tsx 核心計算公式重構 const MAX_SAFE_CAP = Math.min(window.innerHeight * 0.42, 320); let targetH = COMPOSER_AUTO_H; if (!text.trim()) { targetH = COMPOSER_MIN_H; // 空文本絕對不撐滿 } else if (userH != null) { // 允許向下自由壓縮！超出部分交給內部滾動 targetH = Math.min(userH, MAX_SAFE_CAP); } else { targetH = Math.min(ta.scrollHeight, MAX_SAFE_CAP); } ta.style.height = `${targetH}px`; ta.style.overflowY = ta.scrollHeight > targetH ? "auto" : "hidden";

方案 2 機制：Splitter 剛性安全門禁

將訊息流與輸入框作為真正的 Flex 分割視窗：

正文剛性下限：宣告 .messages { min-height: 240px; flex: 1 1 auto; }，輸入框絕對無法侵佔該區域。
物理阻尼碰撞：拖動分割線時，如果正文高度即將低於 240px，拖動手勢立即進入硬阻尼鎖定，防止穿透。
大屏多工友好：適合桌面寬屏 IDE 風格，兩塊區域各自擁有獨立捲軸，權責分明。
/* CSS 剛性佈局防侵入 */ .main-chat-container { display: flex; flex-direction: column; height: 100vh; } .messages { flex: 1 1 auto; min-height: max(240px, 40vh); /* 絕對不可侵犯的正文空間 */ overflow-y: auto; } .composer-pane { flex: 0 0 auto; max-height: calc(100vh - 240px); /* 動態鎖死上限 */ }

方案 3 機制：長文編輯與日常聊天分離 (強烈推薦)

現代頂級 AI 應用（Claude 3.7 Projects、Cursor Composer、GitHub Copilot）普遍採納的行業終極範式：

主介面極致緊湊：輸入框高度牢牢鎖死在 40px~140px（不超過 5 行）。絕不對正文產生壓迫感。
按需展開沉浸空間：貼上多行內容或內容變長時，右下角高亮提示「⛶ 展開編輯」，彈窗中支援舒適排版與 Token 估算。
心智徹底解脫：使用者再也不用在侷促又容易變形的主聊天框裡提心吊膽地上下拉扯，從根源上消除高度自適應的邊際災難。
// 模態與主輸入框雙向同步 function openZenEditor() { zenTextarea.value = chatTextarea.value; zenModal.style.display = "flex"; } function saveZenEditor() { chatTextarea.value = zenTextarea.value; zenModal.style.display = "none"; triggerComposerAutoResize(); }

方案 4 機制：離散檔位吸附 (Discrete Magnetic Tiers)

消除畫素級拖拽的不確定性，提供明確預期：

三種固定心智模型：44px（快速指令）、160px（多行提問）、280px（大段程式碼審閱），嚴格封頂 280px。
狀態一目瞭然：右上角始終標明當前檔位，隨時可點切，不會出現“不知道當前處於什麼保底高度”的隱形困擾。
結合拖拽吸附：如果使用者手動拖拽，鬆手時自動平滑磁吸至最近的一檔（Magnetic Snap），手感順滑。
