側欄 Dock：從「貼邊膠囊」改成「貫通列」 你要的是整列從頂欄下沿一直貫通到狀態列，而不是懸在中間 70vh 的浮標。下面 4 個方案都按這個 前提畫，差別在「這一列到底是透明的、和麵板合併的、帶文字的，還是包進視窗外框的」。

共同修正整列 height:100%、無 scrollbar、tooltip 移出滾動容器、圖示規格統一。
推薦方案 A 改動最小、最像 Linear/Arc；方案 B 最治「割裂」，但要多寫一層容器。
關鍵約束保持 start / center / end 三槽與外掛槽位相容，不重排資料。
手機版同一列收窄到 46px（命中區 38），關掉懸停標籤，其餘規則不變。
00 / 診斷

割裂和橫向捲軸，是三個獨立問題疊出來的

左邊是現在的樣子：一個 border + 陰影 + 半透明模糊的膠囊貼在面板邊上，而面板自己是另一張卡片， 於是「兩層框」互相切割。同時膠囊內部 overflow-y: auto 讓 overflow-x 被計算成 auto，而 tooltip 偽元素是往右伸出的，於是橫向捲軸被撐了出來。

現狀復刻（左側收窄）
1
兩層卡片語言打架

dock 有 border + 陰影 + backdrop-filter，面板又是另一張帶 border 的卡片，中間還留了透明縫 —— 眼睛會讀成「兩個不相干的浮層」。

2
豎向列表裡冒出橫向捲軸

只聲明瞭 overflow-y: auto，另一軸會從 visible 計算成 auto；而 [data-tip]::after 用 left: calc(100% + 8px) 往右伸出，撐大了可滾動區域。

/* 現狀 */ .side-dock-seg { overflow-y: auto; } ← 橫向也被 auto .side-dock [data-tip]::after { left: calc(100% + 8px); } ← 撐寬 /* 修法 */ .side-dock-seg { overflow-y: auto; overflow-x: clip; } // tooltip 改成單例 fixed 浮層，不進滾動容器
3
尺寸語言沒統一

同一列裡混著 30px 圓形 border-radius: 50% 的 bar item、22px 的摺疊鍵、18px 的引擎徽標；和頂欄 28px 圓角 8px 的按鈕、狀態列 11px 的字號不構成一套。

4
整列只有 70vh 高

.side-dock-float { height: 70vh; top: 50% } 決定它天然不可能「貫通」， 上下都是空氣，視覺重量和左右面板不在同一根線上。

方案 A

無形之欄：貫通整列，完全透明

推薦

不畫卡片、不畫外框、不畫陰影 —— 圖示直接坐在和頂欄、面板同一塊表面上，從頂欄下沿貫通到狀態列。 位置感只靠「1px 髮絲線」+「啟用態左側 3px 豎條」建立。hover 時只長出一塊藥丸底， 並向右滑出文字標籤，解決純圖示不可讀的問題。

怎麼做到「貫通」

  • 列寬固定 --rail-w: 56px，高度吃 flex，不再有 70vh / translateY。
  • 底色與頂欄、面板同為 --bg-elev：三者連成一片 L 形表面，不再是貼上去的卡片。
  • 與面板之間只留 1px --border-soft 髮絲線；不畫外框、不畫陰影。
  • 底部圖示用 margin-top: auto 頂到底，跟狀態列留 9px 呼吸。

取捨

＋ 改動最小：只動 .side-dock* 的 30 行 CSS + SideDock 根節點。

＋ 最接近 Linear / Arc 的「無容器」觀感，和任意主題都好配。

− 純圖示可讀性依賴 hover 標籤，觸屏上要退回長按提示。

適配細節

  • 圖示 19px / 命中區 36px / 圓角 11px / 間距 3px，與頂欄 28px 按鈕同族。
  • 掃描外掛槽位：align=start/center/end 三槽保留，視覺上只表現為「空隙 + 1px 細線」。
  • 標籤用絕對定位，但 rail 不能設 overflow，否則又被裁。
方案 A · 手機版

同一列，收窄到 46px

手機上沒有第二個面板——左右面板都變成抽屜，所以這條豎列是唯一常駐的導航。它不能消失，也不能吃掉太多寬度： 列寬從 56 收到 46，命中區從 36 拉到 38（拇指能穩穩點中），懸停標籤改成關掉（觸屏沒有 hover）， 其餘（貫通、髮絲線、啟用豎條）與桌面完全一致。右側列只在真有條目時出現，空的時候不佔位。

手機上的規則

  • 列寬 46px、按鈕 38px、間距 4px（觸控命中區下限）。
  • 不彈懸停標籤（觸屏無 hover）；保留 title 供長按提示。
  • 左右面板都是抽屜，列不跟著抽屜走，始終貫通全高。
  • 右列沒有條目時整列 display:none，不白佔 46px。

為什麼不用底部 tab bar

底部已經有輸入框 + 狀態列，再加一條 tab 會變成三層。豎列與桌面同一套 DOM， 只用媒體查詢換尺寸，改動面最小；且手機橫屏時列自動變回“側欄”的直覺位置。

方案 B

一體雙欄：dock 和麵板住進同一張卡片

割裂的根源是「兩個浮層」。這個方案反過來：dock + 面板合成一個容器，只有一條外邊框、一個圓角； dock 用比面板深一檔的底色區分層級，中間一條 1px 內線。中間會話區不再是「被兩塊卡片夾住」， 而是反過來浮在畫布上 —— 也就是 Figma / Linear 桌面版的骨架。

否則換成哪個方案都會再冒出「割裂」和「捲軸」：

改動清單（按檔案）

  • web/src/styles.css · .side-dock：width 改固定 var(--rail-w)；刪 border / box-shadow / backdrop-filter； height: 100%，刪掉 .side-dock-float 的 70vh + translateY。
  • .side-dock-seg：overflow-y: auto 旁邊補 overflow-x: clip，並且別再把 tooltip 放這裡面。
  • web/src/components/BarItem.tsx（1132 行）：把 data-tip 的自繪偽元素換成統一 tooltip 層（單例 position: fixed，250ms 延遲，左右側自動翻轉）。
  • web/src/components/SideDock.tsx：根節點加 --rail-w 與 data-side；三槽保留，視覺分隔改為「空隙 + 可選 1px 線」；超出高度時收進 「更多」而不是滾動。
  • web/src/App.tsx:334 的 PanelRail（面板摺疊後的把手）：與 rail 同寬同色，別再單獨一個浮動圓角塊。
  • 守衛：tests/unit/bar-item-unified.test.ts 里加一條靜態斷言「rail 內部不得出現 overflow-x: auto」。
