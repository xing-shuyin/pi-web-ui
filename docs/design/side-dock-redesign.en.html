4 options · all running top to bottom

Side dock: from a "floating capsule" to a "continuous column" What you asked for is one column running from the bottom edge of the top bar all the way to the status bar, not a buoy hovering at 70vh in the middle. All 4 options below work from that assumption; they differ in whether that column is transparent, merged with the pane, carrying labels, or folded into the window frame.

Common fixescolumn height:100%, no scrollbar, tooltip out of the scroll container, one icon spec.
Recommendedoption A changes least and looks most like Linear/Arc; option B kills the fragmentation best but needs one more container layer.
Hard constraintkeep start / center / end slots and the plugin slots compatible, no data reshuffle.
Mobilethe same column narrows to 46px (38px hit area), hover labels off, every other rule unchanged.
00 / diagnosis

The fragmentation and the horizontal scrollbar are three separate problems stacked up

On the left is what it looks like now: a capsule with a border + shadow + translucent blur stuck to the edge of the pane, while the pane is a card of its own, so the two frames cut into each other. And overflow-y: auto inside the capsule makes overflow-x compute to auto, while the tooltip pseudo-element reaches out to the right, which forces a horizontal scrollbar open.

Today, reproduced (left side cropped)
1
Two card languages fighting each other

the dock has border + shadow + backdrop-filter, and the pane is another card with its own border with a transparent seam in between — the eye reads it as two unrelated overlays.

2
A vertical list grows a horizontal scrollbar

Only overflow-y: auto is declared, so the other axis computes from visible to auto; and [data-tip]::after uses left: calc(100% + 8px) to reach right, widening the scrollable area.

/* today */ .side-dock-seg { overflow-y: auto; } ← the other axis goes auto too .side-dock [data-tip]::after { left: calc(100% + 8px); } ← widens the box /* the fix */ .side-dock-seg { overflow-y: auto; overflow-x: clip; } // tooltip becomes a singleton fixed layer, outside the scroll container
3
No single size language

One column mixes 30px round border-radius: 50% bar items, a 22px collapse key, an 18px engine badge; none of it belongs to the same family as the 28px / 8px-radius top-bar buttons or the 11px status bar.

4
The whole column is only 70vh tall

.side-dock-float { height: 70vh; top: 50% } makes running the full height impossible by construction, with air above and below; its visual weight does not sit on the same line as the panes beside it.

Option A

The invisible rail: one continuous, fully transparent column

Recommended

No card, no frame, no shadow — the icons sit on the same surface as the top bar and the panes, running from the bottom edge of the top bar down to the status bar. Position is established by a 1px hairline plus a 3px bar to the left of the active item. On hover only a pill background appears, with a text label sliding out to the right, which fixes the unreadability of icon-only navigation.

How to get it continuous

  • Fixed column width --rail-w: 56px, height from flex, no more 70vh / translateY.
  • Background matches the top bar and the panes (--bg-elev): the three join into one L-shaped surface instead of a card stuck on top.
  • Against the pane, only a 1px --border-soft hairline; no outer frame, no shadow.
  • Bottom icons use margin-top: auto to sit at the bottom, 9px of breathing room above the status bar.

Trade-offs

＋ Smallest change: only .side-dock* — about 30 lines of CSS plus the SideDock root node.

＋ Closest to the containerless look of Linear / Arc, and it plays well with any theme.

− Icon-only readability leans on hover labels; on touch it falls back to long-press hints.

Implementation details

  • Icons 19px / hit area 36px / radius 11px / gap 3px, same family as the 28px top-bar buttons.
  • Plugin slots: align=start/center/end — the three slots stay, and visually they only show up as a gap plus a 1px line.
  • Labels are absolutely positioned, but the rail must not set overflow or they get clipped again.
Option A · mobile

The same column, narrowed to 46px

There is no second pane on mobile — the left and right panes both become drawers, so this column is the only permanent navigation. It cannot disappear, and it cannot eat much width: width drops from 56 to 46, the hit area grows from 36 to 38 (a thumb lands on it reliably), hover labels are switched off (no hover on touch), everything else (continuity, hairline, active bar) matches the desktop exactly. The right column only appears when it has real items; when empty it takes no space.

Rules on mobile

  • Column 46px, buttons 38px, gap 4px (the floor for a touch target).
  • No hover labels (no hover on touch); keep title for the long-press hint.
  • Both panes are drawers; the column does not travel with them and always runs the full height.
  • With no items, the right column goes display:none instead of wasting 46px.

Why not a bottom tab bar

The composer and the status bar already sit at the bottom; a tab bar would make three layers. The column shares the desktop DOM, so a media query only changes sizes — the smallest possible surface; and in landscape the column falls back to the intuitive "sidebar" position.

Option B

One-piece columns: the dock and the pane move into one card

The root of the fragmentation is two overlays. This option inverts it: dock + pane become one container with a single outer border and a single radius; the dock separates levels with a background one step darker than the pane plus a 1px inner line. The conversation area is no longer pinched between two cards; it floats on the canvas instead — which is the skeleton of the Figma / Linear desktop apps.

Structure

  • .card-b { display:flex; border:1px; radius:13px; overflow:hidden }
  • dock background = color-mix(bg-sunken 55%, bg-elev), one step away from the pane.
  • Mirrored: the right side is "pane + dock" with the same frame, visually symmetric.
  • The conversation area is an independent card with 8px of canvas colour around it, no longer pinched from both sides.

Trade-offs

＋ Kills the double frame most thoroughly; hierarchy comes from lightness, not shadow.

＋ A 13px-radius outer frame makes the window read as one app instead of stitched-together pages.

− On .layout, add one more container layer + 8px padding — a bigger surface than A.

− Pane and dock borders have to be recomputed (the pane used to carry its own border).

Watch out

  • A card with overflow:hidden means popovers inside the pane must go through a portal or they get clipped.
  • The drag resizer moves between cards, not onto the pane.
  • Narrow screens (<900px) degrade to a single card, the dock stays continuous.
Option C

Wide rail with icons + labels: the column is the navigation

The shape of the new Slack / Notion / ChatGPT sidebars: icons with labels, one column running top to bottom, a brand block on top, account and status at the bottom. The win: you know what every icon does without hovering, and the grouping (navigation / plugins / system) is expressed by section headings, so no number of plugins gets out of hand. It collapses to a 60px icon-only state.

Structure

  • The rail is the navigation: width: 204px, 60px collapsed, one DOM.
  • Sections: navigation / plugins / system, each with a heading; the plugin area grows as things are installed from the market.
  • A fixed account block at the bottom, 4px from the status bar, reading as one line.
  • No tooltip on hover — the labels are always there.

Trade-offs

＋ Best readability; no number of installed plugins turns into "a row of icons you cannot read".

＋ Collapse/expand changes one width, and mobile reuses it for free.

− 204 + 218 + 240 = 662px gone; only comfortable on a wide screen.

− The hierarchy of the current "narrow rail + pane" has to be redefined (which of rail and pane leads).

Suggested combination

  • ≥1600px: wide rail expanded (this figure).
  • 1200–1600px: auto-collapse to 60px icon-only, labels on hover.
  • <1200px: fall back to the continuous narrow rail of option A.
Option D

Window frame: the column runs from the very top of the window to the very bottom

More radical than "continuous below the top bar": the column takes the top-left corner, the brand logo heads it, the top bar starts to its right — producing one unbroken vertical line from the top of the window to the status bar. That is the skeleton of the Linear / Notion desktop apps and the limit of what "running top to bottom" can do.

Whichever you pick, these 6 changes go together

Otherwise the fragmentation and the scrollbar come right back, whichever option you pick:

Change list, by file

  • web/src/styles.css · .side-dock: width becomes a fixed var(--rail-w); delete border / box-shadow / backdrop-filter; height: 100%, drop .side-dock-float from 70vh + translateY.
  • .side-dock-seg: next to overflow-y: auto add overflow-x: clip, and do not put the tooltip back in there.
  • web/src/components/BarItem.tsx (1132 lines): replace the hand-drawn data-tip pseudo-element with one shared tooltip layer (singleton position: fixed, 250ms delay, auto-flips left/right).
  • web/src/components/SideDock.tsx: add --rail-w and data-side to the root; keep the three slots but make the visual separation a gap plus an optional 1px line; on overflow, fold into "More" instead of scrolling.
  • web/src/App.tsx:334 — the PanelRail (the handle left after collapsing a pane): same width and colour as the rail, not another floating rounded block of its own.
  • Guard: tests/unit/bar-item-unified.test.ts — add a static assertion: "the rail must not contain overflow-x: auto".

My recommendation: ship A first.It only changes .side-dock* and still buys all three wins at once — continuous top to bottom, no scrollbar, no double frame — and it stays compatible with the three slots and plugins. Once A has run for a week, if the icons still feel too light and not separated enough from the pane, add a container layer to .layout and upgrade to B — B is a structural superset of A, so none of that work is wasted.

What shipped (implemented as A)

  • web/src/styles.css: .side-dock becomes a 56px continuous column (same background + 1px hairline, no frame/shadow/frosted glass); .side-dock-seg gains overflow-x: clip; three blocks of [data-tip]::after are gone; .rail-tip is new; .side-dock:not(:has(.bar-item)) — an empty column takes no space; @media (max-width: 768px) gets 46px / 38px; the pane collapse handle's double offset is gone.
  • web/src/components/SideDock.tsx: the tooltip becomes a singleton fixed layer (useOverlayZIndex, 220ms delay, auto-flips left/right); desktop drops the native title to avoid double hints; touch turns hover hints off.
  • server/client-state.ts: sideDockFloat now defaults to false (the old "floating" mode is a full-height capsule now, no longer a 70vh buoy).
  • tests/unit/side-dock-rail.test.ts: locks in "fixed column width + both axes declared + no pseudo-element tooltip + no 70vh + mobile spec".
