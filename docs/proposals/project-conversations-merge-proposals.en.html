✨ Smart half-collapse (Partial Collapse) interactive demo

Your idea — "collapsing should hide only what is not running" — is a genuinely sharp design: it gives users the tidy sidebar they want while folding away piles of history, and it eliminates the risk of a background Agent being buried for good!

Try it:
State A: expanded (Full Expand) With the project expanded, the 2 running tasks are pinned on top and history conversations are listed below.
State B: collapsed (Partial Fold · the core new behaviour) The user collapses a project: all static history conversations fold away, yet running tasks still hang right below the project title — progress and spinners stay live, so no execution state is ever hidden. A "+ expand 3 history items" entry also appears below.
State C: tasks settle back naturally once they finish When a background task finishes while the project is collapsed, it simply merges into the folded history and the project closes up into a single row. No jarring jumps.

💻 Core front-end rendering algorithm (pseudocode)

// When rendering conversations inside a Project group:
const runningConvs = convs.filter(c => c.running);
const historyConvs = convs.filter(c => !c.running);

// Key point: collapsing filters out history only; running is always rendered!
const visibleConvs = isCollapsed ? runningConvs : [...runningConvs, ...historyConvs];

// When collapsed and hidden history exists, render the lightweight expand affordance:
if (isCollapsed && historyConvs.length > 0) {
  render(+ expand ${historyConvs.length} history items...);
}
