🛠️ 架構與系統級根本解決路線（跳出打地鼠視角）
為什麼單純在前端寫兩個 if (block.name === 'edit') 是“頭痛醫頭”？以下是根本性系統設計剖析：
+----------------------------------------------------------------------------------------+ | 1. 服務端事實源與上下文預算保障 | | | | [Agent Core / SDK] | | | | | |-- edit 成功執行 --> result.details: { diff, patch, firstChangedLine } (已原生具備) | | | | | |-- write 成功執行 -> 守衛 details 預算 <= 64KB (AGENTS.md 硬規則) | | 服務端僅注入 { isNewFile: boolean, totalLines: number, oldLines?: number } | | 絕不注入超大原始檔案內容，防止 WS 背壓與整包丟棄！ | +----------------------------------------------------------------------------------------+ | v (WebSocket protocol: message_delta / snapshot) +----------------------------------------------------------------------------------------+ | 2. 前端穩健資料模型 (FileMutationModel) | | | | [tool-args.ts] 統一抽象 parser: parseFileMutationArgs(name, argumentsText, details) | | | | | +-- 🛡️ 流式容錯: 即使 JSON 剛收到一半 (如 {"path": "src/a.ts", "edits": [...) | | | 正則提前提取 path 與第一段 hunk，顯示 "正在替換第 N 行..."，杜絕白屏與拋錯 | | | | | +-- 🧩 統一規格: 無論 edit / edit_soft / write / patch，輸出標準 UnifiedDiffBlock[] | +----------------------------------------------------------------------------------------+ | v +----------------------------------------------------------------------------------------+ | 3. 表現層複用與多視口一致性保障 | | | | [FileChangeCard.tsx] 核心高內聚元件 | | | | | |-- 1. 普通聊天流卡片 (ToolCallBlock.tsx 展開態) | | |-- 2. 極簡/Flow 模式彈窗 (ToolInspectorModal.tsx 居中彈窗) | | |-- 3. 懸浮檔案預覽抽屜 (file-preview-bridge.ts 側邊抽屜) | | | | ✅ 統一複用 styles.css 中的 .scm-diff 語義色與 CSS 變數 (--green, --red, --bg-elev) | | ✅ 統一滿足文字對比度與無障礙規範 (AGENTS.md: semantic-contrast / accent-contrast) | +----------------------------------------------------------------------------------------+

根本性解決步驟清單：

  1. 模型層抽象 (web/src/file-diff.ts)： 解耦具體工具名稱，將 edit 的 oldText/newText、SDK 的 details.diff、write 的 content 統一規整化，支援流式容錯解析。
  2. 渲染層元件 (web/src/components/FileChangeCard.tsx)： 實現統一差異、分屏差異、詞級高亮、行號對齊與摺疊保護（預設展示最多 20 行，超額摺疊）。
  3. 兩處視口無縫聯動： 同時接入 ToolCallBlock.tsx（普通對話流）與 ToolInspectorModal.tsx（Flow 檢查器模式），保證全站一致體驗。
  4. 細節打磨與安全測試： 嚴格遵守 AGENTS.md 規範（details ≤64KB、CSS 變數先定義後引用、文字對比度合規），並補充單元測試 tests/unit/file-change-card.test.ts。
