Sink the terminal into a bottom drawer; promote Git to a right-hand review drawer

Today: terminal and Git are both full-page .view-pane tab switches — one line of a compile error pushes the conversation off screen. This proposal re-seats both tools around how they are actually used: terminal = runtime state (run while you chat, in a draggable bottom drawer); Git = review state (read the diff while you have the agent edit, in a wide non-modal right drawer). On mobile both degrade to a full-screen sheet.

02

Mobile

No vertical split; both tools degrade to a full-screen sheet, dismissed by pulling the top handle down

Why mobile gets no split screen

  • Screen height is ~740px; after a vertical split the conversation area holds two or three bubbles — worse than the full-page switch.
  • The soft keyboard eats another 40% of the height, xterm and the input fight for space, and fit() thrashes nonstop.
  • The high-frequency terminal use on mobile is “check whether the command finished”, and full-screen sheet + pull-to-dismiss has the lowest mental cost.

Three additions for mobile

  • Sheet handle: a 34×4 grabber at the top plus pull-down-to-dismiss, replacing the full-page back button in the top-left.
  • Git becomes a full-screen sheet: a segmented control at the top switches Changes / History, file list → diff as a second-level drill-down.
  • Tabs become horizontal chips: multiple terminals on a narrow screen become scrollable chips instead of a row of cramped little squares.

Motion and feel

  • Expand/collapse: height 220ms cubic-bezier(.22,1,.36,1); add .dragging while dragging to kill the transition, re-enable it on release.
  • The Git drawer pushes the workspace with width + opacity rather than sliding in via translate — a slide-in would cover the bottom terminal and the two would fight when open together.
  • 9px handle hit area for a 36×3 visual; on hover it widens to 52 and takes the accent — small, but not hard to hit.
  • Running uses a 2.2s pulsing dot, not an endlessly spinning loader (the terminal already emits output; two animations would fight).
  • Throughout, animate only transform/opacity/height, never top/left/width (except the Git drawer's width, which is the main task while dragging).

Visual rules

  • Hierarchy comes from background steps, not outlines: --bg → --bg-elev → --bg-elev2 in three steps + 1px --border-soft.
  • Accent is reserved for exactly three things: the active tab underline, primary buttons, the focus ring. Everything else stays neutral.
  • Semantic color marks status only: M amber / A green / D red / U blue — always a 15×15 rounded square + a mono letter, never the full word.
  • Paths and numbers are always mono with tabular-nums; diff line numbers stay right-aligned and don't jitter.
  • Three radius steps: outer frame 14 · card/drawer 10 · chip/kbd 5–7. Nothing below 4px, to avoid the “legacy admin panel” look.

Information-architecture rework (this is what actually makes it look better)

  • Terminal: the old left aside crammed in both “command list + tab list”, two navigation layers side by side. The new version demotes the command list to an on-demand overlay (Commands button / Ctrl+K), leaving only tabs and actions in the drawer head.
  • Git: the old header stacked 4 rows of buttons (branch, stash, branch, amend, blame…). The new version keeps a single row (branch + fetch/pull/push + close) and tucks the rest into a ⋯ menu.
  • The commit action is pinned to the bottom: commit is the frequent end point and must not drift with content inside the scroll area.
  • Changes / History / Stash become a segmented control, replacing three buttons of equal weight.
  • AI Bash stays a collapsible group but is expressed as “group header + count”, no longer visually peer to user tabs.

Implementation notes

Follow the repo's existing constraints to avoid rework and guard failures

Non-negotiables

  • Keep the xterm instance mounted: collapsing is display:none only, never unmount; otherwise replaying the full 2MB buffer flickers the screen.
  • Throttle fit while dragging: check resizing in the ResizeObserver callback, then measure once more after release.
  • DeferredMount semantics: switch from view==="terminal" to “the drawer has been opened at least once”, mounting only on first open.
  • Layering goes through useOverlayZIndex(); never hard-code z-index (the overlay-stack guard).
  • Bottom safe area: include env(safe-area-inset-bottom) in the drawer height so the last line isn't hidden under the home indicator.
  • Keep every entry point: the TopBar tb-tab, the left dock, and the uiSlots slots all stay; only their behavior changes from “switch page” to “open drawer”.

Easy traps

  • Mobile gesture conflict: useSwipeDrawer already handles left/right swipes for the sidebar; the upward drag from the bottom must be limited to the grabber area so it doesn't hijack full-screen gestures.
  • Composer pushed out: if an expanded drawer squeezes the input box out of the viewport, the messages-behind-composer guard fails; cap the terminal height at 70vh, not 90vh.
  • Git drawer vs. right panel: RightPanel owns the right side. The rule: “the right panel auto-collapses while Git is open and restores on close” — cheaper in width than showing both.
  • Fullscreen diff button: SCMPanel already has a fullscreen diff; keep it in the drawer as the “maximize” escape hatch so reading diffs on a small screen isn't painful.
  • Persistence: height/width follow the same localStorage pattern as panelWidthKey, with keys like pi-web-ui:term-drawer-h.
  • Reduced motion: respect prefers-reduced-motion — the drawer cuts instead of sliding.
