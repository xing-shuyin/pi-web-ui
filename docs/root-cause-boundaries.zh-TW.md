# 根因整改：操作身份與提交邊界

本檔案記錄跨模組必須保持的行為約束。具體審查證據見 `audits/root-cause-review-2026-10-29.md`。

## 工作樹清理

工作樹狀態讀取失敗屬於未知狀態，不能用於授權刪除。`getUncommittedCount()` 失敗時返回保守的 dirty 狀態與錯誤；非強制刪除和子代理終態清理要求查詢明確成功。

子代理終態清理只有在 status 成功且乾淨、HEAD 與建立時 baseCommit 相同時才自動移除工作樹。在倉庫操作鎖內再次檢查 HEAD，並執行非強制 Git 刪除；Git 因併發修改拒絕刪除時保留工作樹並報告錯誤。分支刪除使用 `update-ref -d <ref> <baseCommit>` 條件刪除，避免清理時刪除被併發推進的分支。

迴歸：`tests/unit/root-cause-worktree.test.ts` 通過破壞索引模擬 status 失敗且 HEAD 可讀，驗證未知狀態不刪除未提交檔案或分支；原有 `subagent-worktree.test.ts` 覆蓋正常清理和保留路徑。

## 排程、持久化與畫布

外掛 cron 的分片計時保留同一個 `dueAt`，僅在該時刻到期並執行後計算下一次。普通外掛設定與加密後的 `setting:` secret 同存 **狀態目錄** `<dataDir>/plugin-data/<id>/storage.json`（程式碼目錄 `plugins/<id>/` 是純快取，可被重新物化），以一次原子替換提交；內部 `__settingsSecrets` 為保留鍵，外掛 storage API 不可讀取或修改，舊 `secrets.bin` 仍作為未遷移項的相容讀取源。儲存失敗不通知設定回撥或返回成功。

MCP 同文件改名一次原子提交；跨作用域遷移先寫恢復日誌、提交目標，再清理源。遷移失敗保留至少一份記錄，重複相同儲存請求可以恢復；目標衝突或兩端內容變化則拒絕恢復。原子寫複用 `atomic-file.ts`，MCP 新檔案預設 `0600`，支援重新整理暫存檔案；這不構成斷電永續性承諾。

畫布 WS 與工具刪除統一經過 orchestrator：先使圖生命週期代次失效並取消執行，再刪除檔案。非同步完成和下游派發校驗圖、節點代次及執行物件身份；執行態儲存只更新存在的工程。重複啟動不得替換正在執行的圖物件。

## 會話、目標與多引擎

目標設定在入口捕獲操作代次，等待舊執行者清理後重新校驗原代次及物件身份；清除、替換和關閉均能使等待中的舊設定失效。嚮導提交返回明確憑證，先提交計劃，再持該憑證搶佔和啟動。

子代理建立需要貫穿父工具取消及穩定父執行身份，候選 runtime 提交前再次檢查；同一會話的 interrupt/reset 共享在途操作，提交繫結原 runtime。審批取消使用穩定請求物件，展示 ID 及持有方遷移不改變一次性結算身份。

Universal 回合捕獲會話物件與 cwd，結束後按該歸屬儲存，禁止找不到舊會話時回退到 active；工作區切換先取消舊回合，並阻止切換期間新回合進入。DSH 重啟必須顯式傳入目標 cwd，啟動失敗不能釋出新工作區。

Claude 與 Durable 歷史目錄按引擎隔離並驗證記錄的 engine。缺少引擎標識的舊轉錄只匯入展示訊息，清除底層 `driverSessionId`，保留原記錄；遷移標記防止使用者刪除後再次匯入。

## HTTP 傳輸

`net-guard.ts` 的生產請求通過獨立 undici dispatcher 將連線解析約束到校驗過的 IP，保留原域名 Host、TLS servername 與證書校驗。每次重定向重新驗證並固定地址，取消前一跳正文；跨源跳轉剝離憑據。截止時間覆蓋 DNS、連線、重定向及正文消費。預設抓取與市場請求複用該路徑，替換全域性 fetch 不能跳過校驗。

## 共同約束

- 非同步工作在入口捕獲穩定的執行物件與歸屬資訊；跨等待恢復後不能讀取當前 active/cwd 作為舊任務的歸屬兜底。
- 代次屬於發起操作，不能在恢復時重新讀取最新代次讓舊操作繼續提交。只有仍有效的操作才能釋出狀態、寫執行態或派發後續任務。
- 取消、關閉、刪除需要撤銷執行資格；刪除磁碟檔案或隱藏 UI 不代表後臺生命週期終止。
- 完整校驗之後才產生持久副作用；持久提交成功之後才釋出執行態與成功回執。損壞、不可讀和不存在是不同結果。
- 儲存身份包含必要的專案和引擎維度；不同引擎的底層會話 ID 不能直接互相恢復。
- 計時器保留本次 dueAt，分片等待不改變本次執行身份；執行之後才計算下一次。
- 網路預檢查必須約束實際連線使用的地址；獨立的 DNS 預檢查不能作為 DNS rebinding 防護。

實現和測試應圍繞以上邊界驗證故障、取消及交錯執行，避免只在正常路徑新增重複守衛。
