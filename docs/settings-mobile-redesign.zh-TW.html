移動端「設定」重構 · 三套可互動方案

現狀：設定是一個 960px 寬的桌面彈窗，移動端把 21+ 個頁籤壓進一條橫向膠囊滾道（@media (max-width:640px) 裡 .settings-rail{flex-direction:row;overflow-x:auto}），分組標題與搜尋被 display:none。 三套方案都基於同一份真實頁籤清單（不新增業務），差異只在「首頁如何降低跳轉成本」。

9:41

方案 A · 分組首頁 + 推入二級頁

iOS 設定的直接移植：大標題 → 身份卡 → 6 個分組卡（每組 3–6 行），行右側用「當前值」替代純箭頭。二級頁從右滑入，導航欄右側承接儲存狀態。

為什麼推薦它

掃讀
一屏 7 行 + 5 個組標題，視線只在左側標籤上，符合「找功能」而非「讀內容」
觸控
行高 56px，整行一個 44px+ 命中區，開關不必點準 30px 圓點
心智
與 iOS 設定同構，零學習成本；返回手勢天然
成本
最低：現有 tab 狀態可直接對映為「棧」，樣式表新增一段移動端規則即可

代價 / 取捨

跳轉
改一個值平均 2 跳；值預覽只能救回「只讀確認」
長尾
21 個頁籤仍要分組承載，新手可能找不到「審批規則」
緩解
搜尋常駐吸頂 + 分組標題帶計數 + 最近改動項上浮（本地記錄，不採集）

試用提示

點行進入二級頁（返回箭頭可回）；開關可直接切；方案 A 的「重置與危險操作」在關於頁底部或首頁最後一行進入。切到「儲存失敗」看頂部紅色回執與重試。

方案差異只發生在首頁殼：

  • A：6 張分組卡 + 身份卡，全部預設展開（資訊全暴露，掃讀最快）。
  • B：2×2 高頻磁貼 + 分組預設摺疊（首屏密度最高，但可發現性依賴展開）。
  • C：搜尋 hero + 常改 6 項 + 5 個場景摺疊 + 底部「全部設定」（按意圖找，最深路徑最長）。

4.1 逐狀態說明

  • 預設：行高 56，圖示托 28，右值 13px --text-dim，箭頭 16px；同一屏最多 1 個強調色（開關開啟 / 選中），其餘靠層級與留白。
  • 按下：:active → 背景 --fill-press（深色 7% 白 / 淺色 6% 黑）+ 磁貼 scale(.975)，120–160ms；不做漣漪、不做投影變化。
  • 停用：aria-disabled="true" + 圖示 45% 透明 + 主文案轉 --text-faint + 保留箭頭；必須在副文案寫清「為什麼停用、去哪修」。
  • 載入：首次進入用骨架屏（不是轉圈），aria-busy="true" + aria-label="正在載入設定"；已有內容時改值只更新區域性，絕不整頁閃。
  • 空：搜尋無結果 → 圖示 + 「沒有匹配"XXX"的設定」+ 建議關鍵詞 + 「清除搜尋」按鈕。不寫「暫無資料」這種無資訊文案。
  • 開關：開＝--accent 軌道 + 圓點右移 20px；關＝--track-off。文案層同時給出 aria-checked，不靠顏色單獨表達。
  • 進二級頁：220ms translateX(16px)+fade 推入；返回反向。Android 用系統返回鍵，iOS 建議同時開啟邊緣滑動返回（實現成本低，見落地清單）。
  • 危險操作：行本身只是入口 → 二級頁 → 點動作彈底部面板（標題複述物件 + 後果 + 是否不可撤銷），確認按鈕實底紅、取消在下且更高；不用「確定/取消」並排的系統 Alert，拇指更容易誤觸。
  • 儲存策略：全部即時生效，沒有「儲存」按鈕。頂部 28px 膠囊顯示 已儲存 / 儲存中… / 未儲存·重試，失敗時同時出現紅色橫幅（role="alert"）+ 行級標紅，點任意一處都可重試。這與現有 useSettingsSync 的回執語義一致。
  • 搜尋：常駐首頁（不折疊成圖示）。匹配範圍＝行標題 + 副文案 + 分組名 + 二級頁標題 + 關鍵詞別名（沿用 TAB_KEYWORDS 的中英別名）。輸入 200ms 防抖，結果行帶分組麵包屑（「· 常用」），可在結果裡直接切開關。
