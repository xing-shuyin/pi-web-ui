# 本地化：模組字典與語言包

## 事實源與模組邊界

介面文案按業務模組儲存在 `web/src/i18n/messages/<module>/<locale>.json`。`core` 承接原 `web/src/i18n.tsx` 的中英文字典和已有 key；Canvas 的介面文案放在 `canvas`，服務端執行狀態及系統日誌放在 `canvas-runtime`。新增功能優先在對應模組維護，含義一致的通用操作繼續使用已有公共 key。

`web/src/i18n/catalog.ts` 彙總內建 `zh`、`en` 字典，保留精確的翻譯 key 型別。`web/src/i18n.tsx` 只維護 Provider、語言選擇、語言包載入、引數替換和回退；元件仍通過同一個 `useT()` / `useI18n()` 讀取當前語言，不建立模組獨立的語言狀態。

Canvas 兩個模組提供全部 14 種語言：`zh`、`en`、`de`、`es`、`fr`、`it`、`ja`、`ko`、`pt`、`ru`、`tr`、`zh-TW`、`zh-Hant`、`zh-HK`。額外語言模組檔案是這些模組的翻譯源；`locales/*.json` 仍是對外發布的扁平下載包，保留現有伺服器安裝與下載介面。語言模組原始碼不要求把所有語言一起打進首屏。

## 新增和修改文案

1. 在模組的 `zh.json`、`en.json` 中新增有語義且帶模組歸屬的 key，例如 `canvas.deleteConfirm`；歷史 key 無需為了拆檔案而改名。
2. 動態值使用 `{name}`、`{count}` 等命名佔位符，通過 `t(key, vars)` 傳入，避免拼接完整句子。所有語言必須保留同一組佔位符。
3. 在該模組的額外語言原始檔中補齊翻譯。維護完整語言模組時，翻譯 key 必須與該模組中文一致，不得以複製英文或簡體中文冒充已經完成的翻譯。
4. 執行 `npm run i18n:sync` 更新下載包，再執行相關字典、語言包、死 key 和 Canvas 單測。中英文字典及下載包保持同一合併順序。

只翻譯 UI：按鈕、欄位標籤、狀態、操作提示、角色與引數的操作說明使用顯式 key，後設資料裡的角色、狀態、埠等通過固定 key 對映取值，避免執行時拼接翻譯 key。模板選擇名稱、Pstack 名稱與分類可以作為介面資訊本地化。

具體內容統一使用英文源，包括 Pstack 的官方說明與規約正文、執行 Prompt、預設 instruction、模板實際任務和示例任務正文。這些內容不進入語言字典，不隨介面語言改寫。使用者儲存的名稱、指令、AI 回覆、工具輸出及匯入資料按原文保留。

## 服務端執行訊息

服務端系統狀態和日誌在協議中附帶 `CanvasMessage`：`{ key, vars? }`。節點通過 `currentActionMessage`、`errorMessage` 攜帶狀態和錯誤的訊息後設資料，日誌通過 `CanvasNodeLogEntry.message` 攜帶，`canvas_error` 通過 `messageI18n` 攜帶。

原有 `currentAction`、`error`、日誌 `text` 和錯誤 `message` 繼續作為相容文本。服務端儲存和前端匯入共用訊息形狀校驗，限制 key 為字串、引數為字串或有限數字。瀏覽器用自己的當前語言翻譯已知訊息 key，未知 key、損壞的歷史後設資料或舊資料回退原文；同一執行可以被使用不同語言的瀏覽器同時檢視。插值只處理原模板一次，使用者值裡的 `{count}`、`$&` 等內容保持字面原文。AI 回覆和使用者輸入不附加系統訊息後設資料。

狀態合併時，新的原文必須同時替換對應後設資料；原文更新而訊息後設資料預設代表清除舊後設資料，不能繼續顯示上一次執行的系統提示。訊息後設資料與其他執行欄位一樣參與持久化合並，不能被過期的拓撲儲存覆蓋。

## 工具與驗證

`scripts/lib/i18n-catalog.mjs` 是 Node 工具讀取字典的統一入口，負責模組發現、確定合併順序、重複 key 和各語言 key / 佔位符校驗。翻譯工具不再從 React 檔案的位置或正則提取推斷當前字典。

- `npm run i18n:sync`：讀取模組字典，補齊、清理並重排 `locales/*.json`；模組已有的額外語言翻譯覆蓋下載包的同 key。傳統語言包的其他文案繼續保留。
- `npm run i18n:diff -- --base <ref>`：與 Git 基準比較翻譯變化，支援基準仍為單個 `i18n.tsx` 的舊佈局。
- `npm run i18n:check`：檢查下載包與當前字典的同步情況。
- `node scripts/zh-tw-locale/build-all.mjs`：通過統一同步入口更新繁體語言包，模組明確提供的繁體譯文優先。

對應守衛包括模組字典一致性、下載包 key 與佔位符、同步器迴歸、死 key、Canvas 前端契約及後端訊息生命週期。新增模組還須在瀏覽器字典入口登記，確保工具讀取到的模組與實際執行時一致。
