# Experimental coding-workflow preset

[claude-code-inspired.json](./claude-code-inspired.json) is an importable pi-web-ui preset that borrows coding practices such as investigation, root-cause fixes, sustained execution and closing the verification loop. It is not an official Anthropic preset, and it neither copies nor was checked against any version of the Claude Code system prompt; it is not guaranteed to improve every model or task.

## Import and restore

1. In preset management under settings, first save and export the current configuration as a restore copy.
2. Import the JSON in this directory, review the import preview, then apply "Claude Code 风格编码（实验）" (Claude Code-style coding (experimental)).
3. Check the expanded result in the prompt settings; subsequent turns of the main session use the new template. Apply the preset saved earlier when you need to restore.

The file contains only three fields: `promptTemplate`, `promptOverrides` and `promptDisabled`. The template keeps all 11 dynamic sources and appends an English coding workflow at the end, so tool descriptions, project instructions, skills and the working directory continue to be generated by the runtime. `append` still keeps its automatic content, including any existing `APPEND_SYSTEM.md`.

Applying it replaces the current compose template, clears existing per-section overrides and re-enables every prompt section. If you rely on a custom `soul`, `guidelines` or other per-section overrides, you must merge them yourself after applying; check the preview before importing. Model, thinking level, tools, permissions and context parameters are not part of this preset. Preset application still goes through the host's unified settings and tool gating flow.

This main-session template does not override subagent role templates automatically. Mode constraints such as planning, review and approval are still enforced by the host; this workflow requires respecting them.

## Comparative evaluation

Evaluate the original configuration and the experimental preset under the same repository commit, model version, thinking level, tool permissions and task inputs. Start every run from an independent new conversation so earlier investigation does not influence the comparison. Pick a few real bug-fix and feature tasks and record:

- whether the right entry point, call chain and authoritative state were located, and whether the root cause was fixed.
- whether the change is complete, and whether it introduces unrelated refactors or misses callers.
- whether the relevant checks were run, and whether the reported results match what actually ran.
- regression status, manual rework, and time and token cost.

Prompt effects are stochastic, and a single result is not enough to prove an overall improvement. If a difference stems from lost tool output, context restoration or execution errors, fix the corresponding mechanism.
